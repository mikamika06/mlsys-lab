## Context

Python dictionaries use open addressing internally. When several keys map to
the same initial table slot, CPython follows a deterministic perturbation probe
sequence instead of scanning slots linearly.

For a table with size $2^n$, the table mask is

$$
\mathrm{mask} = 2^n - 1 .
$$

The first slot is computed from the key hash $h$:

$$
j = h \mathbin{\&} \mathrm{mask}.
$$

Each later slot is generated by CPython's perturbation recurrence:

$$
j = (5j + 1 + \mathrm{perturb}) \mathbin{\&} \mathrm{mask},
$$

followed by

$$
\mathrm{perturb} = \mathrm{perturb} \gg 5 .
$$

The shifting perturb value causes the sequence to depend on more bits of the
hash while the multiplication step spreads collisions across the table.

## Task

Implement `dict_probe_sequence(hash_value, size, steps)`:

```python
def dict_probe_sequence(hash_value: int, size: int, steps: int) -> list[int]:
    ...
```

The function must return the first `steps` table positions visited by the
perturbation probe algorithm for the supplied integer hash value and table size.

The first returned value must be `hash_value & (size - 1)`. Each following value
must use the recurrence above. The `size` argument is always a power of two.

Do not use a Python dictionary to calculate the answer. Implement the probing
logic directly.

## Example

```python
print(dict_probe_sequence(42, 8, 5))
# [2, 5, 3, 0, 1]
```

## What the gate checks

The gate computes expected sequences using the same perturbation algorithm and
compares the submitted implementation against those sequences exactly.

The cases include different integer hashes, table sizes, and sequence lengths.
An implementation using linear probing or updating `perturb` in the wrong order
will produce different slot sequences and fail.
