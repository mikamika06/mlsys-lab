## Context

A CPU branch predictor tries to guess the result of a conditional branch before
the real value is available. A common simplified model is a 2-bit saturating
counter with four states:

$$
0 = \text{strongly not taken}, \quad
1 = \text{weakly not taken}, \quad
2 = \text{weakly taken}, \quad
3 = \text{strongly taken}.
$$

The predictor guesses taken for states $2$ and $3$, and not taken for states
$0$ and $1$. After the real branch result is known, the state moves one step
toward that result while remaining between $0$ and $3$.

The branch being modeled is:

$$
\text{taken} =
\begin{cases}
1 & x > t \\
0 & x \le t
\end{cases}
$$

When values are sorted around the threshold, branch outcomes often form long
runs. An unsorted arrangement may alternate outcomes more frequently, causing
more predictor failures.

## Task

Implement `branch_mispredict_counts(arr_sorted, arr_unsorted, threshold)`:

```python
def branch_mispredict_counts(arr_sorted, arr_unsorted, threshold):
    ...
```

For each input array, scan values from left to right. Start a fresh predictor
with state $1$ (weakly not taken). Count a misprediction whenever the predictor
choice differs from the actual result of $x > threshold$.

Return:

```python
(mis_sorted, mis_unsorted)
```

where each element is the number of mispredicted branches for its corresponding
array.

## Example

```python
mis_sorted, mis_unsorted = branch_mispredict_counts(
    [1, 2, 8, 9],
    [8, 1, 9, 2],
    5,
)

# sorted outcomes:   [False, False, True, True]
# unsorted outcomes: [True, False, True, False]
```

The two sequences produce different predictor histories.

## What the gate checks

The gate computes the expected result using an independent deterministic
2-bit predictor simulation. During reference computation it also runs the
deterministic cache simulator on the generated byte-address access traces with
fixed cache parameters. No measurements from real CPU hardware are used.

The returned tuple must exactly match the deterministic reference result.
