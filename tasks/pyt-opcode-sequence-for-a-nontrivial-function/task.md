## Context

Python functions contain a code object that stores compiled bytecode in `co_code`.
The `dis` module exposes the interpreter instructions generated by CPython.

A bytecode instruction has an opcode number and a human-readable operation name.
For a function $f$, the opcode name sequence is

$$
[\mathrm{opname}(i_1), \mathrm{opname}(i_2), \dots, \mathrm{opname}(i_k)],
$$

where each $i_j$ is an instruction decoded from $f.\_\_code\_\_.co\_code$.

The exact sequence depends on the CPython version because the bytecode format is an
implementation detail. This task targets the pinned CPython runtime used by Arena.

## Task

Implement `opcode_sequence(func)`:

```python
def opcode_sequence(func):
    ...
```

The function receives a Python function object and returns a list containing the
full sequence of opcode names produced by CPython's bytecode decoder for that
function.

Use the standard library `dis` module. Do not return byte values, numeric opcode
IDs, instruction objects, or source-level tokens.

## Example

```python
def add_or_subtract(x):
    if x > 0:
        return x + 1
    return x - 1

names = opcode_sequence(add_or_subtract)
# [
#   "RESUME",
#   "LOAD_FAST",
#   ...
# ]
```

The exact list depends on the running CPython version.

## What the gate checks

The gate creates a real Python function containing a loop and conditional
branches. It computes the expected opcode sequence using CPython's `dis`
decoder at grading time and compares it with the returned list.

A correct implementation must match the complete decoded instruction name
sequence exactly. Partial sequences, source-code analysis, and returning bytecode
numbers do not pass.
