## Context

Dropout sets a random fraction of activations to zero. On a GPU, the binary
mask is generated by a kernel that decides, per element, whether to keep it
($m_i = 1$) or drop it ($m_i = 0$). Because the kernel can be launched with
different block/grid shapes, the THREAD that ends up handling a given
element can change from run to run — but if the random decision depends
only on the element index $i$ and never on which thread/block happens to
carry it, the mask itself is still identical every time. That's
**geometry-independent RNG**, and it's essential for reproducible training.

This CUDA-C subset has no bitwise operators (no `^`, `&`, `>>`) — only
`+ - * / %` and comparisons. That's enough to build a deterministic hash:
an explicit `% 4294967296` ($2^{32}$) stands in for 32-bit unsigned
wraparound, and integer `/ 16777216` ($2^{24}$) followed by `% 256` stands
in for extracting a byte the way `>> 24 & 0xff` would on real hardware.

## Task

Implement the kernel:

```cuda
__global__ void dropout_mask_kernel(float* mask, int seed, int n, int limit);
```

Compute the geometry-independent element index the standard CUDA way —
`i = blockIdx.x * blockDim.x + threadIdx.x` — and, guarded by `i < n`:

$$
h = (\text{seed} + i \times 2654435761) \bmod 2^{32}, \qquad
r = \left\lfloor h / 2^{24} \right\rfloor \bmod 256,
$$
$$
m_i = \begin{cases} 1.0 & r < \text{limit} \\ 0.0 & \text{otherwise} \end{cases}
$$

and store $m_i$ at `mask[i]`.

## Example

For `seed=12345`, `n=1024`, `limit=128`, a correct kernel's output matches a
CPU-computed reference using the exact same formula, element for element —
`ref_match = 1.0` — AND produces the byte-for-byte identical mask whether
launched as `grid=16, block=64` or `grid=32, block=32` — `geom_match = 1.0`.

An empty kernel body (the starter) never writes `mask`, so every element
stays `0.0`. Since roughly half the reference mask is `1.0` (dropout ≈ 50%
at `limit=128` out of 256), that only accidentally agrees with the
reference on the `0.0` half: `ref_match ≈ 0.5`. `geom_match` is still `1.0`
in that case — two empty runs trivially agree with EACH OTHER — which is
exactly why the gate requires both metrics, not just geometry-agreement
alone.

## What the gate checks

- `ref_match >= 1.0`: the mask, from the real CUDA-C kernel executed on
  `arena.cuda_sim.GPU`, must exactly equal a CPU-computed reference using
  the same formula.
- `geom_match >= 1.0`: launching the SAME kernel with two different
  grid/block configurations that both cover all `n` elements must produce
  the identical mask — proof the RNG depends only on `i`, never on thread
  or block shape.
