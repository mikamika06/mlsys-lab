## Context

In many language‑model serving systems a *key–value store* (KV store) holds pre‑computed embeddings or cached results for sequences of tokens.  
A request is represented as an ordered list of integer token IDs. To decide whether a sub‑sequence can be served from the cache, the system splits each request into consecutive **chunks** of fixed size `CHUNK_SIZE`.  

For a chunk \(c = (t_1,\dots,t_k)\) we compute a *prefix hash* by hashing the tuple of its token IDs:

\[
h(c)=\operatorname{hash}\bigl((t_1,\dots,t_k)\bigr).
\]

The chunk is considered a **hit** if this integer hash appears as a key in the KV store; otherwise it is a **miss**.

## Task

Implement the function `label_chunk_hits` that, given:

* `requests`: a list of lists of integers (each inner list is a request),
* `kv_store`: a dictionary whose keys are integer hashes,
* `chunk_size`: an integer > 0,

returns a NumPy array of shape `(n_requests, n_chunks)` containing boolean values where `True` indicates a cache hit for that chunk.

```python
def label_chunk_hits(requests: list[list[int]],
                     kv_store: dict[int, any],
                     chunk_size: int) -> np.ndarray:
    ...
```

The function must be deterministic and use only standard Python/NumPy features. No external libraries are allowed.

## Example

```python
import numpy as np

requests = [
    [10, 20, 30, 40, 50],          # 5 tokens → chunks: [10,20,30,40] & [50]
    [1, 2, 3, 4, 5, 6, 7, 8]       # 8 tokens → two full chunks
]

# Pre‑populate the KV store with a few hash keys.
kv_store = {
    hash((10,20,30,40)): None,
    hash((1,2,3,4)): None,
    hash((5,6,7,8)): None
}

chunk_size = 4

hits = label_chunk_hits(requests, kv_store, chunk_size)
print(hits.astype(int))
# [[1 0]
#  [1 1]]
```

The first request has a hit on its first chunk and a miss on the second.  
The second request has hits on both chunks.

## What the gate checks

A single gate named `exact_match` verifies that the output of your implementation matches an oracle computed by the grader. The oracle splits each request into chunks, hashes each chunk as described above, and checks membership in the provided KV store. Your solution must produce exactly the same boolean matrix for all test cases generated by the grader.
