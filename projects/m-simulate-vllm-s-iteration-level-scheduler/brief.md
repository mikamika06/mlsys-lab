Our serving cluster is experiencing unpredictable tail latency spikes and priority inversion incidents during peak traffic hours. When internal administrative probes or latency-sensitive critical requests are injected into the serving queue alongside heavy batch workloads, they suffer from severe head-of-line blocking. Operators report that despite tagging these urgent requests with high priority metadata, they queue behind hundreds of long-running generation sequences in the iteration-level scheduler. Furthermore, as concurrent request counts scale up, the measured throughput curve exhibits a sharp degradation beyond a certain concurrency threshold due to KV cache thrashing and scheduling overhead, yet our monitoring tools fail to accurately predict or simulate this tipping point. We need to implement a robust iteration-level scheduler simulation module that faithfully models vLLM's chunked prefill and token-by-token generation phases, build a throughput versus concurrency measurement harness to identify optimal operating points, and implement comparative evaluation tools for FCFS versus priority-aware scheduling policies to guarantee that high-priority jobs bypass the queue congestion without violating memory constraints.
