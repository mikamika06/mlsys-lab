When scaling Transformer training using Fully Sharded Data Parallel (FSDP), memory overhead and collective communication volumes can degrade overall throughput if sharding policies and per-layer transient memory peaks are misconfigured.

Your cluster is experiencing unexpected Out-Of-Memory (OOM) exceptions during memory-intensive training passes, alongside network bottlenecks across node interconnects. The current monitoring infrastructure lacks exact analytical metrics for per-rank parameter memory allocation, exact per-step communication payloads across different FSDP sharding strategies (`FULL_SHARD`, `SHARD_GRAD_OP`, `NO_SHARD`), and forward-pass layer-level transient memory usage peaks.

To resolve these bottlenecks, you must build an analytical estimation engine that determines per-rank parameter sharding layouts (accounting for non-divisible parameter sizes and remainder assignment rules), computes exact per-step communication payload sizes across the three major sharding strategies, and calculates transient peak memory allocations during a layer's forward execution pass. Finally, you will write a suite of regression tests that catches improper parameter allocation and communication undercounting bugs.
