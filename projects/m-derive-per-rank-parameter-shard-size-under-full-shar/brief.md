We are debugging our custom Fully Sharded Data Parallel (FSDP) training implementation on a multi-node GPU cluster, specifically focusing on parameter sharding, communication volume accounting, and memory profiling during the forward pass.

Recently, when scaling our model across non-uniform tensor parallelism and odd data parallel world sizes, we noticed that our GPU memory consumption during activation and parameter all-gathers does not match our theoretical expectations. Specifically, when the total parameter count is not evenly divisible by the data parallel world size, some ranks end up allocating mismatched tensor buffers, leading to silent memory padding overheads or out-of-memory errors during the transient peak memory window of the forward pass. Furthermore, our aggregated telemetry for communication volume across different sharding strategies (FULL_SHARD, SHARD_GRAD_OP, and NO_SHARD) reports inconsistent inter-node traffic bytes compared to raw NCCL profile traces, suggesting our formula for tracking per-step communication bytes overestimates or underestimates collective sizes during backward and forward all-gathers/reduce-scatters.

We need a rigorous, mathematically robust library to derive precise per-rank parameter shard sizes (handling remainder rules correctly), compute exact per-step communication volumes under different FSDP configurations, and calculate the exact transient peak memory footprint during a single layer's forward pass. This will allow us to run offline profiling and sanity checks before launching expensive multi-node training jobs.
