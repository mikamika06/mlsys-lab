When loading various GGUF models into our low-level inference runtime, we often encounter unexpected metadata inconsistencies or outright missing keys in the GGUF file key-value store. Our current architecture KV schema validator assumes all mandatory keys are always present and correctly typed, which leads to silent failures, incorrect layer configuration parsing, or uninformative crash reports deep in the tensor allocation pipeline.

Recently, support for newer architectures revealed that certain GGUF files omit critical parameters or use non-standard naming conventions for the attention head counts and dimension sizes. Consequently, deriving the Grouped-Query Attention (GQA) ratio and the individual head dimension from the metadata becomes unreliable, causing incorrect KV cache sizing and memory allocation errors on startup.

We need a robust, deterministic schema validation and metadata parsing utility that systematically inspects the GGUF metadata dictionary. Specifically, the utility needs to locate the exact first missing required KV key according to the model architecture's strict schema specification, correctly derive the GQA ratio and head dimension, and validate the overall metadata structure before any memory buffers are allocated. Your task is to implement this validation and derivation pipeline so that schema violations are caught early with precise diagnostic reporting, ensuring safe and predictable model initialization across all supported GGUF formats.
