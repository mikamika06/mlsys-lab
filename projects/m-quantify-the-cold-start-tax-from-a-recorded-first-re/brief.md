# Quantifying the Cold-Start Tax From a Recorded First-Requests Trace

Production clusters running low-latency machine learning inference models under scale-to-zero infrastructure policies regularly exhibit unpredictable tail-latency spikes and erratic performance degradation during low-traffic windows or intermittent burst periods. Engineers monitoring serving infrastructure observe that individual requests hitting an idle, scaled-down instance suffer from massive latency outliers—often taking an order of magnitude longer than requests processed by warm, active instances—yet aggregate dashboard metrics and average response times completely mask these transient initialization penalties.

Furthermore, capacity planning teams lack a reliable analytical approach to evaluate how tuning the scale-to-zero idle timeout parameter affects the overall proportion of user requests exposed to these initialization overheads versus the financial savings of idling inactive pods. Without an automated, systematic method to parse historical request traces, isolate idle gaps, and accurately quantify both the cumulative cold-start tax and the exact fraction of requests falling victim to scale-to-zero transitions, optimization efforts remain entirely guesswork, leading to poor user experience SLAs and inefficient resource allocation.
