We are encountering severe performance regressions and compilation discrepancies during model deployment pipelines using TorchInductor. Downstream systems report that generated C++ code paths for CPU execution frequently fail to emit expected vectorization instructions or OpenMP parallel directives under heavy workloads, resulting in thread starvation and severe single-threaded execution bottlenecks. Additionally, operators dispatched to GPU execution environments via Triton are experiencing silent metadata extraction failures, where crucial compilation parameters such as block size, warp counts, and thread grids are either omitted or incorrectly recorded in compiler dumps. This leads to invalid kernel launch configurations and suboptimal GPU hardware occupancy. Furthermore, when evaluating multi-layer perceptron (MLP) architectures under various operator fusion settings, the compiler outputs inconsistent and unpredictable counts of distinct generated kernels, complicating memory planning and caching heuristics. Engineers currently lack automated auditing tools to inspect, parse, and verify these low-level code generation artifacts, leading to extended debugging cycles and regression leaks in production environments. We urgently require a robust, automated analysis suite capable of reliably parsing CPU C++ outputs for OpenMP pragmas and vectorized loops, extracting precise GPU kernel metadata from Triton dumps, and computing accurate kernel counts across distinct fusion scenarios.
