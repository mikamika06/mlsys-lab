An incident occurred in the Triton execution pipeline during a routine scale-up of 2D kernel workloads. Operators noticed that processing multi-dimensional tensors with irregular shapes results in silent data corruption along the outer boundaries of the computation grid. Specifically, when executing a 2D tiled elementwise kernel that relies on a meta-lambda grid configuration, the final row and column of output elements consistently fail to be computed, leaving stale values uninitialized or zeroed out depending on the allocation pre-initialization.

Initial inspection indicates that the grid generation logic used to compute the total number of programs (`num_programs`) relies on standard integer floor division when mapping global tensor dimensions to block dimensions. This approach truncates any remainder tiles that do not fit evenly into the block size, causing the grid launcher to completely omit the trailing boundary partitions. Because many downstream verification tasks assume complete tensor coverage, this silent omission leads to validation failures further down the testing pipeline.

Your task is to fix the grid derivation and kernel configuration code so that `num_programs` correctly accounts for partial boundary tiles using ceiling division semantics, implement a 2D tiled elementwise kernel via a meta-lambda grid configuration that handles arbitrary tensor shapes without omission, and write a robust regression test to prevent future boundary truncation regressions.
