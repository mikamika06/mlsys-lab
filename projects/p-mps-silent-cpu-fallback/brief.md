When running our large language and vision models on Apple Silicon using the Metal Performance Shaders (MPS) backend, we observe that inference throughput is significantly lower than expected—often lagging behind CPU-only execution or showing only marginal speedups despite heavy GPU utilization metrics. Profiling hints that certain tensor operations and custom layers might be executing suboptimally, but standard high-level monitoring tools fail to pinpoint the bottleneck because the framework does not raise explicit errors or warnings during execution. Instead, individual operations appear to complete successfully yet take an abnormally long duration or exhibit severe pipeline stalls. We suspect that certain operations lack native MPS backend implementations and are silently falling back to the CPU device under the hood, causing frequent device synchronization overhead, unnecessary host-to-device memory transfers, and serialized execution bottlenecks. Your task is to investigate this behavior, build tools to detect and quantify these silent fallbacks, refactor or rewrite the problematic operations to run natively on the accelerator, verify performance gains, enforce strict zero-fallback policies on critical hot paths, and implement a robust regression testing suite to protect against future performance regressions.
