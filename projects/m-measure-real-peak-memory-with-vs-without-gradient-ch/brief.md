When training large language models or transformer architectures with frozen base layers and gradient checkpointing enabled, engineers notice unexpected behaviors. First, despite calling model.gradient_checkpointing_enable(), peak memory consumption during the forward pass remains unexpectedly high or fails to drop as predicted, or even increases due to checkpointing overhead when applied improperly. Second, when attempting to fine-tune a model where the base transformer backbone is frozen (i.e., param.requires_grad = False), enabling gradient checkpointing causes downstream gradients to silently become None for the base layers, completely breaking backpropagation and halting parameter updates on unfrozen adapter modules or heads attached to the model. Attempting standard workarounds results in persistent runtime errors, missing gradients, or silent training stagnation where loss values fail to decrease during optimization steps. This ticket asks you to build a robust diagnostic and measurement utility suite that accurately tracks peak memory differentials with versus without gradient checkpointing, reproduces the silent gradient-flow failure when checkpointing a frozen base model without input requires grad, and verifies the application of input requirement fixes to restore correct gradient propagation across all trainable components.
