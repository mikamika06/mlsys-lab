Our CPU inference latency benchmarks on Skylake-X and Cascade Lake server nodes show unexpected performance regressions. When we enabled INT8 quantized GEMM kernels utilizing 512-bit AVX-512 VNNI instructions (`vpdpbusd`) alongside our standard FP32 attention head code, total end-to-end token generation latency unexpectedly degraded by 18% instead of speeding up. This occurs despite static arithmetic throughput calculations projecting a 4x MAC/cycle advantage over AVX2 baselines.

Furthermore, microbenchmarking reveals that executing brief bursts of 512-bit heavy instructions causes subsequent scalar and 256-bit vector operations on the same core to experience throughput drops for thousands of cycles afterward. Our current execution estimator assumes static clock frequencies and zero state transitions, completely ignoring CPU thermal downclocking magnitude, instruction ISA tier classifications, and frequency recovery hysteresis windows.

We need an execution modeling module in `avx512_mechanics/` that correctly classifies assembly instruction streams into ISA frequency tiers, accounts for downclock recovery windows during mixed-workload execution, and computes the realistic net speedup of VNNI over non-VNNI fallback routines.
