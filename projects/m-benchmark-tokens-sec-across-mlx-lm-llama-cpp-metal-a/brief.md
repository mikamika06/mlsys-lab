Our performance profiling team has reported erratic and contradictory benchmarking results when evaluating local LLM inference engines across Apple Silicon backends (`mlx-lm`, `llama.cpp-metal`, and `torch-mps`).

Specifically, during continuous integration test runs, reports indicate that `torch-mps` is occasionally logged as having higher steady-state generation speed than `mlx-lm`, despite user-visible latency showing the exact opposite. Initial investigations suggest that prompt prefill latency (Time-To-First-Token, or TTFT) is being blended directly into the token generation phase, skewing the reported steady-state tokens-per-second metric whenever long prompt contexts are evaluated. Additionally, peak resident set size (RSS) memory telemetry varies drastically between backend runs because memory usage during prompt evaluation is not being sampled at consistent execution checkpoints.

We need a unified benchmarking module, `benchedge`, that standardizes timing collection, cleanly separates prompt prefill TTFT from steady-state decode throughput, tracks peak RSS memory usage accurately across backends, and generates comparative metrics against a configurable baseline.
