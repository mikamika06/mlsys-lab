We are running a multi-tenant inference cluster serving a series of hybrid large language models that combine full-attention layers with interleaved sliding-window attention layers. During high-concurrency peak traffic, our memory tracking tools report anomalous out-of-memory crashes on instances that should theoretically have ample headroom based on peak context length calculations.

Upon closer inspection, the operational tooling shows discrepancies between our theoretical static KV cache memory allocation and the actual bytes consumed per token during generation. Specifically, when sliding windows are interleaved irregularly across depths, standard uniform allocation formulas overestimate or underestimate the active footprint depending on whether a token is within the local window or past it. Furthermore, our auto-scaling admission controllers rely on a startup KV cache size prediction that diverges from the exact byte tally during prefill versus generation phases, leading to premature request throttling or cache oversubscription.

Your task is to implement a robust low-level module in `hybridkv/` that parses hybrid attention configurations, accurately computes the effective bytes per token considering interleaved sliding windows, and provides a verified predictive model for startup versus steady-state KV cache footprints. You must ensure that your implementation passes all accuracy checks and protects against incorrect sliding-window byte scaling regressions.
