Our high-throughput LLM serving runtime is experiencing noticeable CPU launch overheads during recurrent inference loops, particularly when dispatching small CUDA kernels sequentially across multiple streams. While profiling our execution traces under heavy load, the systems team recorded a set of before-and-after CUDA runtime trace logs detailing kernel submission delays, driver queue wait times, and host-side synchronization bottlenecks. At the same time, our deep kernel autotuning pipeline for mixed-precision matrix multiplications is failing to correctly bound the parameter search-space size when combining varied tile shapes, warp configurations, and pipeline stages.

We need to build a robust diagnostic and modeling component within our low-level runtime that parses these recorded trace files to compute exact CPU-launch-overhead reduction ratios, while simultaneously calculating the precise combinatorial search-space size for our max-autotune matmul tuner. If either computation drifts or misinterprets the underlying execution parameters, our scheduling layer either overestimates the benefits of graph capture or exhausts available memory limits during autotuning sweeps. Your task is to implement the core processing modules that ingest trace metrics, evaluate overhead reduction factors against our latency thresholds, and accurately compute the discrete search space for the matmul parameter matrix.
