Ticket: #49821 - Intermittent compilation stalls and unclassified out-of-memory failures during large model export

During the end-to-end compilation and conversion pipeline for our multi-modal attention networks under TensorRT and ONNX Runtime backends, several deployment pipelines are experiencing unhandled allocation faults. Specifically, when deploying models with aggressive tensor context sharing enabled under constrained device memory budgets, the compilation workflow either fails abruptly during network optimization or crashes downstream during the first execution iteration.

Engineers report that compilation logs show sudden termination without explicit error codes when workspace limits are exceeded. Furthermore, when optimization tactics fail due to memory limits, the underlying engine drops candidate fusion kernels silently without generating actionable trace evidence or provenance logs, making it nearly impossible to determine whether the failure originated during build-time workspace allocation or runtime tensor activation buffering. We require a robust programmatic mechanism to construct valid context sharing schedules within strict memory budgets, accurately classify OOM events into build-time and runtime categories, and extract definitive forensic evidence of silent tactic exclusions from engine diagnostic outputs.
