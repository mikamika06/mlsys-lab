Our primary LLM inference pipeline in production is failing to meet its strict Service Level Objective (SLO) target of 20 ms per token, currently averaging 48 ms per token under standard batching conditions. The engineering team is locked in heated debate regarding where optimization resources should be allocated. One group argues for re-writing the multi-head self-attention mechanisms in custom Triton and fused CUDA kernels, claiming that attention is the primary computational bottleneck. A second group insists that model weights must be quantized from FP16 to INT8/INT4 to eliminate memory bandwidth saturation during the autoregressive decoding phase. A third group recommends fusing elementwise activation functions and normalization layers (such as LayerNorm and GELU) to eliminate intermediate DRAM write-backs.

To resolve this conflict with mathematical rigor rather than guesswork, we recorded detailed execution profiling traces across representative inference runs. Each profile record includes exact FLOP counts, memory bytes transferred across the HBM/DRAM interface, and measured execution time in microseconds for every active kernel in the model.

Rather than providing a generic list of optimization heuristics, we need an automated Roofline model analysis system. This tool must calculate the arithmetic intensity of every kernel, position each kernel on the target GPU's Roofline curve, establish theoretical minimum execution times based on hardware performance bounds, predict realistic model speedups for proposed optimization strategies, and produce a prioritized optimization report sorted by maximum attainable time savings.
