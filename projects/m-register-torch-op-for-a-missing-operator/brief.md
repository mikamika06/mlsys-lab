When exporting a vision-transformer-based convolutional backbone model through the edge compilation pipeline to intermediate language (MIL), the translation routine abruptly terminates during lowering with an unhandled exception complaining about an unregistered operator signature. Specifically, custom fused layers containing non-standard activation and normalization routines cause the lowering subsystem to throw an error indicating that the symbol cannot be resolved in the operator registry. Furthermore, after manually bypassing this registration roadblock by stubbing out operator definitions, subsequent graph optimization passes—particularly the convolution-batch normalization fusion pass—exhibit unexpected behavior where the operator count delta fails to reflect the expected reduction, leaving redundant scaling nodes in the exported graph. Engineers investigating downstream performance regressions are currently unable to reliably audit which specific intermediate compiler pass altered the execution profile and node quantities, complicating hardware target profiling. We need a robust mechanism to properly register missing torch operators via the API, correctly compute op count deltas resulting from structural fusion passes, and reliably audit the graph pass execution history to identify which exact transformation pass modified the operator topology.
