We recently pushed a large language model quantization update targeting INT4 weights using a per-channel maximum scaling approach to reduce memory consumption on our edge cluster. Immediately after deploying the updated weights, we observed a catastrophic spike in evaluation perplexity, with generation outputs completely degenerating into repetition loops or outright garbage tokens.

Upon debugging the intermediate activation and weight tensors, we found that certain outlier channels containing exceptionally large weight magnitudes are skewing the per-channel absolute maximum calculation. Because the scale factor is strictly driven by the single largest absolute weight value in each channel, the remaining 99 percent of the weights are compressed into a tiny fraction of the available quantization bins, resulting in massive quantization noise and rounding them effectively to zero.

We need to implement a robust per-channel scale selection procedure that moves away from naive absolute maximum scaling. Specifically, we need functions to compute the baseline maximum scale, simulate the quantization and dequantization process under any given scale, and perform a grid search over a range of candidate scaling factors to choose the one that directly minimizes the mean squared error (MSE) relative to the original unquantized weights. This code must be written in pure numpy so it can run cleanly inside our scale selection preprocessing script.
