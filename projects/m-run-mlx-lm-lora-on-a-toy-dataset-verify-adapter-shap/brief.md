An edge machine-learning pipeline running MLX for Apple Silicon is experiencing deployment and memory profiling issues while fine-tuning small models with parameter-efficient techniques. Engineers are attempting to run `mlx_lm.lora` on a compact toy dataset to establish a baseline workflow, but they hit multiple roadblocks regarding adapter topology, memory footprint, and parameter auditing.

First, when inspecting the saved adapter weights, the loaded tensor shapes do not align with the expected rank configuration or target module dimensions, causing downstream projection errors during model merging. Second, during peak load under standard full-precision training versus quantized training (QLoRA), memory monitoring utilities report unpredictable peak RSS allocations that prevent scaling up to slightly larger edge devices. Finally, estimating the exact parameter count for a given rank, alpha, and target module layout fails to match the actual weight tensor count, leading to configuration mismatches and invalid hyperparameter tuning runs.

Your task is to build a verifiable MLX-LM LoRA utility module that successfully executes training on a toy dataset, verifies adapter shape correctness relative to the rank, measures peak RSS differences, and computes exact LoRA parameter counts. You must also supply a regression test that catches broken shape or parameter counting logic.
