The ONNX Runtime inference server deployment is experiencing a severe performance regression upon container restarts, even when persistent caching directories are fully enabled and populated. When the service boots cold and processes its initial batch of inference requests, execution times spike dramatically—often exceeding baseline warm performance by 5 to 10 times—before eventually settling down after several dozen requests.

Investigation into the underlying TensorRT Execution Provider logs reveals that while engine cache files are successfully located and loaded from disk during initialization, they are frequently invalidated at runtime due to subtle hardware context mismatches, dynamic profile shape boundary violations, or plugin registry version divergences. Consequently, TensorRT is forced to fall back to expensive on-the-fly CUDA engine rebuilds or partial sub-graph fallbacks, destroying throughput consistency and raising peak latency tails. Furthermore, incomplete sub-graph partitioning leaves critical operations outside the TensorRT execution scope, reducing overall node coverage and forcing unnecessary host-device memory roundtrips.

Your task is to implement a robust engine caching and validation module that guarantees warm-init behavior from the very first request, correctly detects and prevents cache invalidation triggers by standardizing execution contexts, and maximizes TensorRT sub-graph node coverage without compromising numerical accuracy. You will build a deterministic engine cache verification layer, a shape profile matching guard, and a comprehensive regression test suite to catch cache bypass bugs.
