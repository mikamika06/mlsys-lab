When building llama.cpp from source on Apple Silicon Macs, engineers frequently rely on the build system's default auto-detection to configure compiler optimizations, hardware instruction sets, and backend flags. Recently, during routine containerized evaluations and local builds for ARM64 inference runners, a curious disparity emerged between the auto-detected instruction set configuration and the explicit manual architecture reports.

Specifically, when utilizing standard environment builds versus targeted cross-compilation configurations or containerized toolchains, the build system's automatic native detection (`GGML_NATIVE=ON`) behaves inconsistently compared to explicitly provided target features. In certain environments, the auto-detector incorrectly assumes or drops specific vector acceleration extensions or NEON feature flags, leading to suboptimal kernel compilation paths or unexpected runtime fallbacks during large language model token generation.

Your task is to investigate, parse, and contrast these ISA (Instruction Set Architecture) reports, reconcile the discrepancies between auto-detected (`GGML_NATIVE`) configurations and manual flag configurations, and build a robust parser and validator in Python that analyzes build logs and configuration reports to ensure optimal hardware utilization on Mac CPU-only inference backends. You must implement the configuration parser, the contrast metric generator, and a comprehensive regression test suite that catches any regressions in ISA tier selection.
