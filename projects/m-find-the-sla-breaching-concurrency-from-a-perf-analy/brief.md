We are observing severe operational instability in our Triton Inference Server production deployment when scaling up user traffic under high concurrency loads. During recent benchmark sweeps using perf_analyzer and genai-perf, the system exhibits unpredictable tail latency spikes that routinely violate our strict service level agreements (SLAs), particularly when dynamic batching is enabled to maximize GPU utilization.

Engineering teams are currently unable to reliably determine the exact concurrency threshold where user-facing p99 latency breaches our operational ceiling, making capacity planning purely speculative. Furthermore, when comparing benchmarking runs with dynamic batching turned on versus turned off, we lack visibility into whether the observed latency inflation is stemming from queue wait times or actual kernel execution compute time. Finally, reporting tools fail to accurately segregate system-level token throughput per GPU from user-experienced token throughput, masking bottlenecks in request scheduling and concurrency handling.

We need a programmatic analysis module to ingest raw profiling fixtures, correctly identify maximum safe concurrency levels under custom SLA constraints, decompose latency deltas accurately into queue and compute components, and compute exact token-level performance indicators to stabilize our serving infrastructure.
