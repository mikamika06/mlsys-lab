Engineers working on low-level tensor expression compilation using Apache TVM have noticed that default schedules generated for small matrix multiplications often leave significant performance on the table compared to fully tuned tensor expressions. When optimizing small workloads, relying solely on standard compilation templates results in sub-optimal latency because memory layouts, tile sizes, and thread-block configurations are not optimized for the target hardware architecture.

To address this, we need to leverage TVM's MetaSchedule framework (`ms.tune_tir`) to automatically search for better schedule options on a small matrix multiplication kernel. However, integrating tuning into our build pipeline requires more than just calling the search API: we must be able to programmatically extract the best measured latency, compare it directly against the untuned baseline schedule to ensure our tuning pass actually improved performance, and parse the resulting MetaSchedule tuning database to rank the top-5 candidate schedules by their measured execution time.

Your task is to implement a robust utility module that executes a tiny MetaSchedule tuning trial on a small matrix multiplication, extracts and compares the best latency against the default schedule, and parses the tuning database to rank the top candidates. You will also write a regression test suite that catches improperly parsed database rankings or incorrect metric extractions, ensuring our optimization pipeline remains robust against structural regressions.
