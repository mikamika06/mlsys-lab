An applied machine learning team is integrating PyTorch's native quantization workflow using torchao into a high-throughput transformer serving pipeline to optimize memory footprints and alleviate bandwidth bottlenecks on lower-tier hardware. The target model uses dense linear layers that currently run in full precision, blowing past memory caps during high-concurrency inference spikes.

To address this, the team is attempting to adopt per-row symmetric integer quantization, leveraging PyTorch's `quantize_` infrastructure to compress weight matrices down to 8-bit integers alongside structural validation of size ratios and quality deltas. Furthermore, the pipeline requires an understanding of how advanced 4-bit group-quantized storage formats are packed and computed under the hood.

However, the current implementation fails during integration. When applying per-row symmetric quantization via the standard workflow, the scale factors computed across rows lead to catastrophic precision drift and output divergence when compared against high-precision reference outputs. The resulting tensors either violate expected memory footprint reductions or trigger unexpected out-of-bounds scale scaling errors. The task is to properly reproduce the exact math for per-row symmetric scaling factors, implement the size and quality delta verification helpers, compute the correct underlying byte footprint and storage mathematics for 4-bit group-quantized weights, and write a robust regression safeguard test that catches any improper quantization scale allocation.
