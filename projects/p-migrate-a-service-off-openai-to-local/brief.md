# Перевести сервіс з OpenAI на локальний рушій

У нас є корпоративний сервіс штучного інтелекту, який наразі повністю завя'заний на хмарне API OpenAI. Через зміни в політиці безпеки, вимоги до конфіденційності даних та бюджети, поставлено задачу перенести цей сервіс на власний локальний рушій висновків, який позиціонується як OpenAI-сумісний.

Наш клієнтський код написаний на стандартному офіційному Python SDK від OpenAI. Він активно використовує складні патерни: стрімінг токенів (streaming responses), виклик зовнішніх інструментів (tool calls / function calling) та вбудовані політики повторних спроб (retries) на випадок помилок мережі або обмеження частоти запитів (rate limits).

Проблема полягає в тому, що «OpenAI-сумісність» локального рушія є не повною. Деякі поля у відповідях відрізняються, заголовки або формат стрімінгу можуть мати незначні розбіжності, а поведінка при паралельних тул-колах веде себе інакше. Нам потрібно здійснити міграцію плавно, без переписування всієї бізнес-логіки в додатку, але адаптувавши клієнтський шар або прокладочний адаптер під реалії локального середовища.

Необхідно скласти чітку матрицю сумісності, виявити всі проблемні місця, полагодити стрімінг, токенізацію, механізми виклику інструментів і покрити все надійними регресійними тестами, зафіксувавши всі неминучі поведінкові відмінності.
