We are running an LLM-quantization pipeline using llm-compressor on our server fleet, aiming to calibrate a model using a general chat dataset and then serve it for code generation tasks. Recently, our engineering team noticed an alarming discrepancy in code-generation quality and token perplexity when deploying these chat-calibrated models for programming workloads. The error metrics show that activations from structured programming syntaxes, dense logic blocks, and deep nested scopes diverge significantly from the calibration distribution seen during the chat phase.

Specifically, the relative error of activation scales and outlier channels spikes when code-completion prompts are evaluated against the calibration statistics gathered solely from conversational dialogs. This distribution shift leads to severe degradation in quantization accuracy, incorrect weight scaling factors, and poor token prediction metrics on code tasks. We need to implement a dedicated calibration adjustment workflow, verify relative error bounds across disparate token distributions, and ensure our quantization pipeline correctly handles domain shifts between chat calibration runs and code serving workloads without breaking under test invariants.
