An incident ticket opened this morning from the serving cluster shows a subtle regression in our mixture-of-experts model outputs on long context workloads. While perplexity remains stable in the early layers, later transformer blocks in certain requests produce degenerate token distributions. Inspection of intermediate activation logs reveals that one of the expert router rows has become entirely zeroed out. This means incoming token representations routed to this particular expert layer receive no valid routing weights, effectively dropping token contributions or defaulting to an uninitialized routing path, causing silent corruption downstream. We need to diagnose how this zeroed row alters the routing probability distributions, analyze the active versus total parameter footprint under this MoE configuration, and ensure our diagnostic tooling robustly flags this failure mode before deployment. Engineers are requested to inspect the router weight matrices, verify parameter calculations across all active and inactive experts, and implement a robust diagnostic module to catch such corrupted router rows early in the pipeline.
