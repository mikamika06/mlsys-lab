When running large Mixture of Experts (MoE) models under llama.cpp with partial tensor offloading via override flags like `-ot` (tensor regex overrides) and `--n-cpu-moe`, users notice unexpected out-of-memory errors on the GPU or incorrect layer placement where expert weights are mistakenly loaded into VRAM instead of system RAM, or vice versa. Despite specifying target buffer assignments or adjusting CPU-bound MoE layers, the runtime either ignores custom regex patterns or fails to compute the correct VRAM savings, leading to suboptimal memory utilization, unpredictable offloading behavior, crashing during initialization, or failing to converge on the minimum viable CPU MoE count required to fit within constrained hardware VRAM budgets. Operators find themselves unable to reliably restrict expert weights to CPU memory while keeping attention layers on the GPU, and automated memory planning tools report mismatched buffer allocations without pointing to the underlying parsing or computation flaw.
