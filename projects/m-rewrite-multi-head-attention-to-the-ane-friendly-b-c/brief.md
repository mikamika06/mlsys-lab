When deploying transformer models onto Apple's Neural Engine (ANE) via Core ML, the memory layout and tensor shape order dictate whether operations execute efficiently on the specialized hardware or fall back to the CPU. Multi-head attention layers implemented naively using standard PyTorch or generic tensor layouts often generate a high volume of internal reshape and transpose operations when converted.

On the ANE, tensor dimensions are heavily optimized for specific layout patterns—specifically, the four-dimensional layout where batch and channel axes align with the hardware's expected vector widths, commonly represented in certain transformer optimizations as the `(B, C, 1, S)` layout. When multi-head attention is structured without regard for this layout, Core ML struggles to fuse operations, resulting in inflated latency metrics and excessive conversion overhead characterized by an abundance of layout-conversion nodes in the compiled `.mlpackage`.

Your task is to refactor a multi-head attention module to natively use the ANE-friendly `(B, C, 1, S)` layout, convert both the naive and optimized implementations to Core ML, measure the resulting hardware performance delta (specifically focusing on execution metrics and CPU/NE balance), and quantify the reduction in transpose and reshape operations in the final compiled package. Ensure that your regression suite correctly catches deviations from the required layout invariants.
