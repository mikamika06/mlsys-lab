We recently merged a new sliding-window attention kernel into our inference server stack. Since then, the testing team has reported an alarming symptom: about 15% of the nightly integration test prompts are generating entirely different text compared to the baseline from last week. The exact same model weights and sampling parameters are being used (temperature 0, greedy decoding).

A developer looked at the logs and noticed that the token generation matches exactly for the first few hundred tokens, but then suddenly diverges. They suspect this might not be a bug in the kernel logic itself, but rather a floating-point accumulation order difference causing a near-tie in the logits to flip the argmax. However, if the divergence happens extremely early in the prompt, it points to a serious memory corruption or KV cache misalignment.

We need an automated way to measure this. Please build a tool to compute the first-divergence index between two sets of generation outputs. Then, implement a regression gate that fails the CI build if too many prompts diverge before a specific token length. Finally, add an analysis function to determine what fraction of these divergences are caused by near-ties in the top-2 logits (e.g., difference < 1e-5), which would confirm the non-determinism hypothesis. Prove it works with a regression test.
