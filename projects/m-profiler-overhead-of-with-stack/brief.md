Our production training cluster is investigating intermittent latency spikes and massive trace file inflations during routine performance profiling runs. Engineers attempting to capture operational bottlenecks in our core transformer training loop report that enabling detailed stack traces via the profiler causes training throughput to drop precipitously—sometimes doubling step times—while simultaneously generating multi-gigabyte JSON trace artifacts that choke our log ingestion pipelines and storage quotas.

When developers try to trim the traces by guessing configuration flags or reducing iteration windows, the resulting profiling data either misses the critical backward pass entirely or omits python stack frames, making root-cause analysis impossible. Furthermore, engineers lack a systematic way to measure the exact performance penalty imposed by `with_stack=True` versus standard `record_function` annotations, leading to ad-hoc profiling sessions that waste cluster compute cycles and yield unusable diagnostics. We need a structured toolkit in `proftune` to correctly annotate training steps, quantify profiler overhead ratios, and automatically tune profiling parameters to respect strict trace byte budgets.
