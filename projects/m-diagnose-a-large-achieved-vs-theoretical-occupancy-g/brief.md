# Ticket: Severe Discrepancy Between Theoretical and Achieved Occupancy in Production GEMM Kernels

## Symptom Report
During our latest performance regression sweep on the primary tensor-core GEMM kernels deployed in our LLM inference serving pipeline, we observed an alarming anomaly. While our static resource analysis and compiler-reported parameters project a robust theoretical occupancy exceeding 85% across multiple streaming multiprocessors, our live profiling telemetry shows the actual achieved active warp occupancy dropping to a dismal 18% during heavy decode workloads.

This massive gap between theoretical potential and runtime reality is severely throttling our throughput and driving up token latency metrics under peak user concurrency. Engineers have noted that the issue becomes particularly pronounced when batch sizes scale down and token generation loops run concurrently with prefill steps. Despite optimizing thread block dimensions and tuning register allocations, the gap persists unabated. We need a rigorous, automated diagnostic harness and ranking engine within our low-level profiling tools to programmatically ingest kernel hardware counter logs, compute precise theoretical occupancy bounds from resource configurations, parse warp state execution statistics to identify the exact stall reasons, and enforce a strict regression safeguard to catch any future regressions in occupancy diagnosis accuracy.
