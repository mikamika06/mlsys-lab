When profiling a suite of deep learning workloads on our accelerator, several seemingly straightforward kernels like standard multi-head attention and custom normalization layers exhibit wildly suboptimal execution profiles. Specifically, performance counters show that achieved throughput in GFLOP/s falls drastically short of the theoretical hardware peaks, yet traditional memory bandwidth counters indicate we are not saturating the available device memory bandwidth either. Engineers are currently flying blind when trying to determine whether these discrepancies stem from arithmetic intensity bottlenecks, hidden synchronization overheads, non-coalesced memory access patterns, or algorithmic structure mismatch such as the quadratic scaling inherent in standard attention versus tiled implementations like FlashAttention. Without a rigorous, quantitative roofline analysis framework that correctly maps operational arithmetic intensity against achieved performance for diverse real-world kernels, optimization efforts are wasted on the wrong layers. The system lacks a systematic way to compute exact roofline coordinates, classify kernels into precise operational regimes, compare attention variants, and diagnose the true physical limiters when execution points fall far below expected bounds.
