# Ticket: GGUF quantization command-line resolution and size prediction mismatches

During recent pipeline runs involving low-level GGUF model quantization, engineers have noticed inconsistencies between the requested command-line arguments (such as default type specifications, selective quantization levels, and tensor-specific type overrides like raising `attn_v` precision) and the actual per-tensor quantization plan generated by the tooling. When attempting to quantize small test model architectures using various configurations, the estimated output file size predicted by our tooling frequently diverges from the actual physical size of the resulting quantized GGUF artifacts.

Furthermore, applying explicit command-line flags to override specific tensor types—particularly targeting attention components such as `attn_v` for higher precision retention—does not consistently propagate through the resolution pipeline, resulting in unexpected quantization profiles where critical tensors are incorrectly downcast. This discrepancy causes verification suites to fail when checking model fidelity and expected storage footprints. We need a robust, deterministic module that accurately parses quantization command lines, constructs precise per-tensor quantization plans incorporating all default and overridden type rules, correctly predicts exact output byte sizes, and validates these behaviors via comprehensive regression testing.
