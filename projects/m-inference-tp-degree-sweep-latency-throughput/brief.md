We are running distributed inference server evaluations on a multi-GPU cluster, scaling tensor parallelism (TP) degrees across different model geometries. Recently, during our automated throughput and latency benchmarking scripts, we noticed unexpected scaling anomalies and allocation faults when pushing the tensor parallel degree to higher values.

Specifically, when running models with non-standard key-value head counts (such as GQA architectures with fewer KV heads than total layers or specific odd divisors), the execution engine throws partition mismatch errors during tensor initialization, or fails to properly align the attention head slices across ranks. Furthermore, even when execution succeeds, the recorded throughput curves flatline prematurely or drop drastically due to communication overheads that violate expected parallel scaling laws.

We need to systematically build an analysis and verification pipeline that computes valid TP-degree sweeps based on model geometry, validates the maximum valid tensor parallel degree for a given KV-head count constraint, and parses real server execution logs to verify partition shapes against expected tensor slicing dimensions. Your task is to implement this module in `inference/tp_sweep.py`, ensuring correct partition mathematics, valid degree verification, log parsing, and writing a robust regression test suite in `tests/test_regression.py` that catches any invalid partition alignments or incorrect sweep bounds.
