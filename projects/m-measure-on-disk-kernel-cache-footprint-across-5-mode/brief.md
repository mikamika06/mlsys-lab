When working with low-level machine learning compilers and caching mechanisms like FXGraphCache, Mega-cache, or AOTAutogradCache, developers frequently encounter unexpected re-compilations and cache misses. Recently, engineers running inference and training workflows noticed severe performance degradation and bloated disk usage under certain caching configurations. Specifically, as model sizes scale across five different tiers, the on-disk kernel-cache footprint grows unpredictably, sometimes ballooning far beyond what the actual compiled artifacts justify.

Even more puzzling, when deployment directories are migrated or mounted on different paths, the compiled artifacts previously stored on disk suddenly fail to load or trigger massive cache invalidation sweeps, forcing the system to re-compile identical kernels from scratch. Furthermore, profiling the cache directory reveals a substantial discrepancy between the raw byte size consumed on disk by the cache directory structure and the actual cumulative size of the core Mega-cache artifact bytes. This opaque overhead causes storage exhaustion on edge nodes and complicates multi-tenant cache sharing. Your task is to build a diagnostic and measurement module that accurately tracks on-disk footprint across model scales, detects path-keyed cache invalidation behaviors, and compares raw directory bytes against core artifact bytes.
