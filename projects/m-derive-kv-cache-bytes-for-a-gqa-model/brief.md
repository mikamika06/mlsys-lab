When provisioning high-throughput inference nodes for multi-tenant serving, operators frequently encounter catastrophic out-of-memory (OOM) crashes during peak concurrency windows. Specifically, container instances allocated with static memory budgets based on nominal parameter counts routinely exceed their limits once long-context requests are processed using Grouped-Query Attention (GQA) architectures combined with low-bit KV cache quantization formats (such as Q4_0 or Q8_0).

Engineers report that monitoring tools show sudden, unpredicted memory spikes that do not correlate with standard weight footprints or batch size scaling laws. Profiling indicates that manual byte calculations fail to account for block-level padding, quantization block sizing overheads, and layer-wise variations in key-value head counts. Without a rigorous, mathematically sound derivation of KV cache allocations across diverse quantization schemas and context lengths, clusters remain vulnerable to unpredictable runtime terminations and degraded scheduling reliability.

Your task is to implement a robust calculation module in `kvderive/calc.py` that accurately derives baseline and quantized KV cache memory requirements, and to author a comprehensive regression test suite in `tests/test_regression.py` that ensures these byte allocation invariants hold under arbitrary model configurations and quantization types.
