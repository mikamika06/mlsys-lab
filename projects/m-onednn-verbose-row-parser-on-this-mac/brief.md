When debugging low-level CPU inference performance in local ML environments, developers frequently rely on verbose runtime tracing to understand JIT kernel selection and execution characteristics. Specifically, enabling verbose logging generates an extensive stream of comma-separated records detailing each primitive invocation, engine type, implementation string, and duration. However, engineers analyzing these logs on macOS or standard workstation builds regularly encounter brittle parsing scripts that fail when encountering malformed lines, unexpected comma delimiters, or varying implementation prefixes. Furthermore, a persistent discrepancy arises when attempting to reconcile the sum of individual JIT kernel execution durations against total end-to-end wall-clock time. Cumulative primitive times often deviate from wall-clock measurements due to framework scheduling overheads, thread pool synchronization delays, or unclassified fallback reference routines. Without a robust parser and systematic time reconciliation pipeline, identifying performance bottlenecks and verifying optimal kernel dispatching remains manual, error-prone, and difficult to automate across successive build iterations.
