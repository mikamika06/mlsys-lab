Our local model serving infrastructure is suffering from unpredictable latency spikes when handling dynamic multi-model workloads. During peak traffic windows, models are frequently evicted from memory due to tight resident memory caps, forcing subsequent requests to incur heavy reload penalties. However, not all reloads are created equal: some models are evicted from the active process table but remain resident in the operating system page cache, while others must be read entirely from cold storage or disk.

Operators currently lack a systematic way to quantify these distinct load duration regimes—cold, warm, and page-cached—leading to naive keep-alive heuristics that either exhaust system RAM or thrash the disk subsystem. Furthermore, without a precise predictive model of load durations and an optimal keep-alive controller that selects which models to retain under a strict memory budget, aggregate request latency degrades significantly.

Your task is to implement a robust load duration estimator, build a state-aware keep-alive controller that tracks model residency and memory usage under a hard cap, and design an optimization policy that minimizes total load time across a workload trace while respecting memory limits. You must also write comprehensive regression tests to ensure your optimization invariants hold under edge conditions.
