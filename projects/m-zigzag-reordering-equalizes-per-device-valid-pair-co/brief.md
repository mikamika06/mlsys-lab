We are attempting to scale our long-context transformer to a 1M token sequence length across a cluster of 128 GPUs using a Ring Attention architecture. We chunk the long sequence into blocks and distribute them across the devices. However, we are encountering a massive bottleneck during the forward pass. Monitoring tools show that GPU 0 finishes its portion of the sequence almost instantly and then sits completely idle, while GPU 127 grinds away for an eternity and frequently triggers Out Of Memory (OOM) exceptions.

To fix this, we implemented a cyclic, round-robin assignment—sending block 0 to GPU 0, block 1 to GPU 1, and wrapping around. While this improved our overall cluster utilization and stopped the immediate OOMs, the later GPUs in the ring are still lagging behind and bottlenecking the step time. Our profiler shows they are still doing significantly more computations. Because causal attention requires later tokens to attend to all preceding tokens, any strategy that assigns monotonically increasing block indices cyclically still leaves the later ranks with the heaviest workload. We need an assignment strategy that perfectly balances the number of valid attention block-pairs per device, completely flattening the workload distribution.
