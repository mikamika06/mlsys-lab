We are experiencing critical memory estimation failures and allocation crashes when running low-level fine-tuning pipelines under strict VRAM constraints, specifically with paged 8-bit Adam and QLoRA setups. During heavy training passes on our cluster nodes, engineers noticed that memory footprint computations are severely misaligned with actual device allocations. Specifically, the derived optimizer-state bytes per parameter for FP32 versus 8-bit implementations do not reconcile, leading to unexpected out-of-memory errors during large model training. Furthermore, calculating the total training memory budget that accounts for base model weights, LoRA adapters, activations, gradients, and optimizer states across different quantization configurations yields drifting and invalid totals. Compounding this, the dynamic CPU spillover mechanism fails to correctly identify or trigger at the precise step index required by paged-Adam's memory paging strategy, causing host-device memory thrashing and premature execution halts. We need an exact accounting package and calculation utilities that correctly derive optimizer-state parameters, project comprehensive QLoRA memory budgets, and accurately compute the exact step index where paged optimizer CPU spillover must be invoked to guarantee safe GPU memory ceilings.
