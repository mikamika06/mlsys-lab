Prefix caching cluster experiences unexpected memory bloat and cold-start miss penalties. Even though hit rates eventually stabilize, early request bursts suffer from high cache eviction rates and unpredictable memory consumption. Service owners cannot reliably size the KV cache for a target 90% hit rate during traffic ramps, leading to either severe out-of-memory errors or over-provisioned GPU memory wasting gigabytes per node. Furthermore, analyzing the warmup curve (hits versus request index) shows chaotic hit patterns rather than the smooth asymptotic convergence expected from standard Zipfian request distributions, indicating a disconnect between our working-set calculations and real-world prefix reuse. We need an automated module to precisely model the working set required for a 90% hit rate and track the exact warmup trajectory across request indexes. This unit implements the core working-set model and cache warmup simulation required to stabilize prefix cache allocations and prevent memory over-subscription in low-level ML serving infrastructure.
