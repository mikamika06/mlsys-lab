We are fine-tuning medium-to-large language models under tight memory budgets, and the activation memory footprint is frequently the primary bottleneck limiting our batch size and maximum sequence length. During the forward pass of a transformer block, intermediate tensors like attention matrices, layer norm states, MLP activations, and residual connections must be stored to compute backward gradients, unless activation recomputation or checkpointing is employed.

When analyzing activation memory consumption across diverse configurations—varying hidden sizes, intermediate dimensions, attention head counts, and sequence lengths—engineers often find it difficult to predict a priori which specific component dominates the total storage overhead. Sometimes attention matrix storage dominates at long sequence lengths due to quadratic scaling, while other times large intermediate feed-forward projection layers dominate due to high expansion factors.

Without a clear analytical understanding and empirical profiling of these memory components, we risk misallocating accelerator resources or encountering unexpected Out-Of-Memory (OOM) errors during large-scale fine-tuning jobs. Your task is to investigate and build a systematic accounting tool. You need to classify which term dominates memory across given transformer configurations, measure the real peak activation memory of a tiny transformer forward pass using standard profiling hooks, and quantify how activation memory scales as the sequence length doubles. Implementing this infrastructure will give us precise visibility into memory bottlenecks and ensure robust training stability.
