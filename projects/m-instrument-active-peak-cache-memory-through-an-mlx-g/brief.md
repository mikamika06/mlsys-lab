When deploying large language models on edge hardware using Apple Silicon via MLX, our production nodes have started experiencing unpredictable performance degradation and sudden process terminations under sustained text generation workloads. Operators report that during long-context generation loops, memory consumption climbs rapidly, occasionally triggering aggressive operating system intervention or silent kernel-level throttling without explicit Python out-of-memory exceptions being caught by the application layer.

Furthermore, when administrators attempt to apply strict memory constraints using custom limits, the system exhibits severe, unexpected throughput drops that vastly exceed theoretical overhead estimates. At the same time, incident review logs from recent cluster events show sudden failure cascades where generation tasks abruptly halt mid-sequence, yet post-mortem telemetry fails to pinpoint the exact token generation step where memory ceilings were breached.

Engineers need a robust instrumentation harness to accurately track active, peak, and cache memory allocations per generation step, quantify the exact performance penalty induced by restricted memory limits compared to default allocations, and reliably identify the precise step where memory usage crosses critical hardware ceilings from historical server logs.
