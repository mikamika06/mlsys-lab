# INCIDENT REPORT: Cluster Node Degradation and OOM Anomalies During Large-Scale LLM Workloads

## Symptom Description
During recent scaling runs across local multi-GPU and single-node runner environments in the inference cluster, operators have reported a cascade of abrupt job terminations, silent pipeline stalls, and mysterious CUDA driver exceptions. Specifically, container instances executing large language model serving tasks are failing unpredictably under peak workloads. When jobs are submitted with varying context lengths and tensor-parallel/pipeline-parallel degrees, system logs show sudden process exits without stack traces, sporadic `CUDA error: out of memory` messages even when free system memory counters suggest headroom, and corrupted NCCL communication loops that hang indefinitely during tensor aggregation phases.

Additionally, system resource monitors (`ps` and memory counters) display erratic behavior where resident set size (RSS) climbs rapidly right before termination, while GPU VRAM allocation tables show fragmentation that does not match expected static tensor footprints. Operators are currently unable to distinguish between genuine hardware memory exhaustion, misconfigured parallel process ranks, driver-level context leaks, and incorrect tensor alignment bounds. We need a robust diagnostic pipeline and classification utility integrated into our local runner framework to systematically categorize incoming error transcripts, extract precise root causes and remediation fixes from multi-source diagnostic logs, and provide reliable preflight memory/context admission checks before any job is dispatched to local accelerators.
