When fine-tuning large language models on limited accelerator hardware, practitioners often choose between full parameter fine-tuning, standard LoRA in bfloat16, and quantized LoRA (QLoRA) in 4-bit precision. While memory footprints differ substantially between these paradigms, the actual wall-clock execution time per training step and the exact ranking of peak memory consumption can often surprise engineers due to the interplay of kernel launch overheads, dequantization delays, activation checkpointing, and memory fragmentation.

In this exercise unit, you will implement an instrumentation and benchmarking module to measure the real per-step wall-clock execution difference between full fine-tuning and LoRA configurations, and you will construct a memory ranking module that evaluates and ranks the real measured memory consumption of full fine-tuning, LoRA in bfloat16, and QLoRA against a derived theoretical ordering. You will analyze how runtime latency varies under different sequence lengths and batch configurations, ensuring your measurements correctly capture performance characteristics without relying on external hardware counters that might be unstable in virtualized environments.

Your tasks include: implementing a per-step wall-clock latency measurement harness that computes robust ratios between full fine-tuning and LoRA iterations; building a memory profiling function that records accurate peak memory footprints for each training configuration; and creating a regression test suite that validates these performance and memory invariants against expected architectural bounds.
