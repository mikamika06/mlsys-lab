An inference service running high-throughput LLM workloads is experiencing unexpected Out-Of-Memory (OOM) crashes and high memory fragmentation when serving long-context requests. When configuring large-scale deployments, engineers frequently struggle to balance host memory caching, OS-level swap space, and LMCache CPU size allocations.

During peak concurrency, KV cache blocks assigned to swap space or offloaded to the host CPU via LMCache begin competing directly with system page cache and kernel allocations. Because the interaction between host_cache_size, --swap-space, and lmcache_cpu_size is poorly understood, memory eviction policies frequently thrash. This causes sudden latency spikes, degraded token generation throughput, and premature request evictions even when physical RAM appears available on paper.

Your task is to implement a unified memory sizing and configuration planning module that models the precise memory footprint, eviction overhead, and allocation bounds for host_cache_size, --swap-space, and lmcache_cpu_size. You must provide a programmatic way to compute required buffer sizes, validate configuration parameters against hardware constraints, and write a robust regression test suite that catches misconfigured buffer overlaps and incorrect memory budget allocations.
