# Issue: FP16 conversion precision regression and graph node mismatch in transformer export pipelines

We have observed significant numerical instabilities and unexpected output discrepancies when exporting custom transformer checkpoints to optimized runtime formats using the standard pipeline. Specifically, when executing mixed-precision optimization routines, certain sensitive attention and normalization layers undergo unintended precision reduction, resulting in a dramatic spike in `max_abs_err` metrics compared to the reference PyTorch implementation. Furthermore, baseline evaluations reveal that applying a generic optimization pass over-applies node fusions, whereas the specialized transformer graph optimizer fails to protect designated sub-graphs, particularly around the key-value cache update blocks in the decoder loop.

Engineers investigating customer reports note that inference jobs running on target accelerators exhibit irregular divergence during autoregressive generation steps, pointing to potential omissions or misconfigurations in the op block listing and downstream node matching rules. The pipeline currently lacks a systematic audit mechanism to inspect the decoder graph structure for missing KV-cache formatting nodes and verify that block-listed operations retain their required precision bounds. We need a robust, modular implementation that correctly defines minimal FP16 operation blocklists, distinguishes between generic ALL and transformer-specific optimizers, and provides rigorous auditing capabilities for decoder graphs to ensure full fidelity and error compliance.
