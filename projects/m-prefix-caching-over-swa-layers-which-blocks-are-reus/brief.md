When serving long-context requests using hybrid models that combine sliding window attention (SWA) layers, full attention layers, and state-space models like Mamba, our serving engine is experiencing unexpected memory bloat and lower cache hit rates than theoretically possible during prefix caching operations. Specifically, long prompts spanning up to 128k tokens show identical prefix blocks failing to be reused across requests when passing through sliding window attention boundaries, leading to redundant prefills and excessive GPU memory allocation.

Furthermore, our cost estimators for 128k-context workloads are projecting memory footprints that do not account for the differing memory scaling profiles between Mamba recurrent state sizes and attention key-value cache sizes across hybrid layer stacks. When comparing dense transformer configurations against hybrid configurations under identical context lengths, the allocated memory pools are either under-provisioned, causing out-of-memory errors during generation phases, or severely over-provisioned, wasting precious high-bandwidth memory. We need to implement a robust evaluation and planning module that correctly identifies reusable prefix blocks under SWA constraints, accurately computes state versus KV memory requirements for hybrid layers, and models 128k-context costs accurately.
