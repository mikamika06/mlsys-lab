We are experiencing a severe performance modeling bottleneck in our serving infrastructure simulation loop. During capacity planning for high-throughput LLM deployments on heterogeneous clusters, our prefill and decode throughput estimates are diverging wildly from actual hardware counters. Specifically, when we ingest long context requests or sweep across varying batch sizes, the predicted tokens-per-second ceilings calculated from our model configuration files do not match the expected arithmetic intensity curves.

The core issue stems from an oversimplified roofline analysis script that fails to account for the exact operational breakdown of transformer blocks. When calculating prefill phase computational requirements, the engine currently lumps attention projection FLOPs and MLP activations into a vague aggregate estimate, ignoring the exact dimensions of hidden states, intermediate MLP hidden sizes (such as SwiGLU expansion factors), and key-value head counts. Furthermore, during the decode phase, our memory bandwidth calculations are omitting critical hardware access patterns, specifically failing to precisely quantify the exact bytes of model weights streamed alongside the dynamic KV cache read overhead for a given active batch and context length.

Without an accurate, mathematically rigorous roofline predictor that computes prefill FLOPs per token and decode memory traffic per step directly from the model architecture configuration and hardware specifications, our hardware provisioning toolchain cannot reliably determine whether a deployment will be compute-bound or memory-bandwidth-bound. We need to implement a robust calculation pipeline that accurately derives these metrics from config data and constructs a trustworthy performance envelope.
