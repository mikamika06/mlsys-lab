# Ticket: Tokenizer output mismatch after GGUF conversion

We have recently integrated a new model checkpoint converted to GGUF format for inference using our low-level engine. While the model successfully loads and produces coherent text generation under normal prompts, downstream evaluations reveal subtle yet critical discrepancies in tokenization outputs compared to the original HuggingFace tokenizer. Specifically, when processing inputs containing punctuation, leading whitespaces, multi-byte UTF-8 characters, and special control tokens, the token IDs generated by the GGUF runtime diverge from the reference tokenizer. This mismatch leads to corrupted generation boundaries, improperly formatted chat templates, and occasional token shifting where punctuation or newline characters are split incorrectly or merged into neighboring words.

Your task is to investigate these tokenization anomalies, prove the divergence across different input classes, fix the vocabulary and merge rules conversion pipeline, enforce correct special token handling, and ensure a robust byte-by-byte round-trip guarantee across diverse text corpora. Finally, you must implement comprehensive regression tests to guard against future conversion regressions in CI.
