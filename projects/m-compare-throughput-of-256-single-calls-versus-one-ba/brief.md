An embedding serving pipeline processing high-volume traffic is exhibiting severe degradation in request efficiency and downstream retrieval quality. When evaluating the deployed embedding endpoint under load, operators noticed that dispatching 256 independent single-item requests sequentially or concurrently via individual HTTP calls results in a severe bottleneck, whereas a single batched payload containing all 256 texts processes significantly faster. The performance discrepancy is captured by a throughput ratio metric that drops far below expected operational thresholds.

Compounding this performance bottleneck, downstream vector search engines are returning erratic similarity scores and degraded retrieval relevance. Investigation reveals that the active embedding model does not guarantee L2-normalized vectors, causing Euclidean distance approximations and inner product calculations to diverge wildly from standard cosine similarity semantics. Furthermore, when system administrators attempted to swap out the underlying model or mix embeddings generated by two distinct model checkpoints within the same vector space, downstream cosine similarity metrics completely broke down due to incompatible latent spaces and differing vector norms or dimensional representations.

Your task is to implement a robust low-level embedding metrics and client batching runner that correctly computes and benchmarks batch throughput ratios, detects whether a model returns pre-normalized vectors, and constructs protective validation checks against mixing incompatible embedding spaces.
