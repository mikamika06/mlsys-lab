Engineers transitioning large language model training pipelines to Fully Sharded Data Parallel (FSDP2) frequently encounter unexpected out-of-memory (OOM) anomalies and synchronization stalls during multi-process cluster scaling, even when theoretical parameter footprints appear well within device capacity limits. In local multi-process simulation environments, tracking the exact memory high-water mark per rank, differentiating parameter residency behaviors between `SHARD_GRAD_OP` and `FULL_SHARD` configurations across forward execution boundaries, and isolating communication overhead introduced by backends like Gloo remain challenging without precise diagnostic instrumentation.

This exercise unit requires you to implement a diagnostic toolkit within `fsdpmeasure/` to profile, analyze, and simulate multi-process FSDP2 memory profiles and communication overheads. You will implement memory tracking functions to evaluate peak memory consumption per rank across a 4-process local cluster compared to single-process baselines, examine parameter residency states between forward passes under different sharding strategies, and quantify wall-clock communication latencies induced by distributed coordination. Completing these milestones ensures deep mastery of low-level FSDP2 memory layout dynamics and runtime performance bottlenecks.
