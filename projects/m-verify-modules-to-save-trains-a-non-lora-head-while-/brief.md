Our fine-tuning pipeline for task-specific classification wraps base transformer models with low-rank adapters. When training target-specific projection heads alongside LoRA adapters, developers observed that the head parameters remain completely static across training epochs, leading to zero performance gain on domain metrics. At the same time, recent deployment deployments show unexpected storage overheads where adapter checkpoints consume as much disk space as full base model weights.

To fix these issues, our library needs an explicit parameter verification utility. We must inspect parameter trainable flags and gradient status across all model submodules during a forward-backward pass to confirm that configured non-LoRA modules (via `modules_to_save`) actually receive gradients while all standard base backbone parameters remain strictly frozen. Additionally, we need a precise diagnostic function to measure the disk footprint ratio between saved adapter checkpoints and full base model checkpoints.
