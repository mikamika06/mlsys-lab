We are running a Triton-based GEMM and kernel autotuning benchmark suite where different tile size and block configuration parameters are exhaustively swept during the compilation and tuning pass. However, when inspecting the execution logs and the resulting compiled artifacts, we notice discrepancies in how the launched grid shape changes across autotuned configs. Specifically, when the block size (BLOCK_M, BLOCK_N, BLOCK_K) changes between evaluated configs, the total number of thread blocks launched along each dimension does not scale inversely as expected from the problem dimensions, leading to out-of-bounds memory accesses or invalid thread block allocations in certain edge-case configurations. We need a robust analyzer module that takes the problem dimensions and an autotuned configuration dictionary, correctly derives the resulting 1D/2D launched grid shape, validates the grid dimensions against boundary conditions, and provides regression tests to ensure that any future grid calculation changes correctly handle block rounding and grid truncation.
