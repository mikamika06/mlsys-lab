We are debugging a multi-node distributed training run using PyTorch's `torchrun` and NCCL backends across a cluster of nodes where membership dynamics and timeout thresholds are under heavy stress. During a prolonged training session, node 2 experienced a transient network partition, causing a cascade of heartbeats to drop. Instead of cleanly handling the node failure or triggering an elastic rendezvous re-initiation, the training job hung indefinitely before crashing with a cryptic NCCL watchdog timeout error (`[rank 0] Watchdog caught collective execution timeout`).

The standard cluster output shows that ranks desynchronized because the barrier synchronization in the collective communication primitives blocked indefinitely while waiting for the missing rank. Furthermore, the wrapper scripts failed to correctly parse the exit codes and environment variables injected by the elastic rendezvous framework (`etcd` or C10D backend), leading to corrupted rank mappings and failed state resumption from the last saved checkpoint.

Your task is to implement the core modules that parse NCCL watchdog diagnostic logs, handle elastic rendezvous membership change states, and implement state-restoration logic for `torchrun` elastic restarts. You must implement the necessary inspection functions to diagnose why the watchdog triggered, simulate membership re-mapping during a node drop, and write comprehensive regression tests that catch incorrect fallback handling during elastic state recovery.
