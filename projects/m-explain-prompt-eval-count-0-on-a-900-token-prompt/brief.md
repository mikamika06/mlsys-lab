An incident ticket came in from the inference cluster serving our LLM endpoints. During peak hours, an anomaly surfaced with one of our serving engines: a request containing a 900-token prompt recorded a prompt_eval_count of 0 in its metrics log, even though the engine processed the entire input and generated a valid completion. This counter discrepancy completely breaks our autoscaling triggers and renders our token-rate throughput calculations unreliable.

At the same time, we need to evaluate two competing local inference runners side-by-side using only their raw performance counters and token counts to see which one delivers better operational efficiency. To make matters more complicated, our capacity planning team requires us to compute Time to First Token (TTFT) analytically and demonstrate precisely which hardware or software component dominates this latency metric when scaling up to a 4k context window. Your task is to diagnose the root cause of the missing evaluation count, build a rigorous comparison harness for the runners, and model the TTFT breakdown accurately under heavy context loads.
