# Експорт у Core ML зсуває числа

Ми зіткнулися з проблемою чисельної нестабільності після експорту нашої моделі у формат Core ML для запуску на пристрої. Під час тестування на стандартних тестових наборах даних з'ясувалося, що хоча загальна структура виходу та форма тензорів повністю збігаються з оригінальною моделлю на PyTorch, кінцеві значення на виході дещо відрізняються.

Ця розбіжність є дуже малою в абсолютних значеннях для більшості проміжних шарів, проте її накопичення призводить до того, що на фінальному етапі класифікації інколи міняються місцями найвищі ймовірності для сусідніх або схожих класів. Через це точність моделі на пристрої падає порівняно з оригінальним пайплайном у PyTorch, що є неприйнятним для нашого продакшн-середовища.

Необхідно провести повний аналіз поведінки моделі після конвертації, побудувати пошарове порівняння чисельних значень між PyTorch та Core ML, локалізувати конкретні операції або шари, що вносять найбільшу похибку, перевірити коректність контрактів входу (layout, тип даних та препроцесування), а також полагодити конвертацію проблемних операцій. Наприкінці потрібно гарантувати, що фінальний argmax збігається на 1000 випадкових прикладах та налаштувати надійний регресійний тест паритету.
