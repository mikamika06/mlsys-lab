When running vLLM-style low-level KV cache allocation under strict hardware memory budgets, our inference serving engine reports intermittent out-of-memory crashes or severe block reservation discrepancies during peak request load. Specifically, the number of physical KV blocks successfully allocated by the block manager diverges significantly from the static block allocation planner's budget calculations for multi-tenant requests.

Engineers investigating the telemetry notice that while the theoretical memory calculator pre-allocates block counts based on maximum sequence length assumptions, the actual runtime block manager tracks fragmented block allocations and page tables dynamically. During high-concurrency request streaming, this leads to a mismatch where the real physical allocated KV blocks either exceed the expected budget—causing unexpected memory pressure and allocator thrashing—or fall short due to conservative padding rules.

Your task is to implement a robust measurement utility within the low-level serving module that accurately calculates theoretical block allocations, tracks real physical allocated KV blocks under simulated block-table states, and compares your real-time allocations against predicted budgets using relative error metrics. You will build a complete workflow that parses block tables, computes exact physical block footprints, compares allocations against oracle predictions, and writes regression tests to ensure allocation tracking remains invariant under simulated memory fragmentation faults.
