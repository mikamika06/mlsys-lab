# Incident Report: Unpredictable Latency Spikes and KV Cache Preemption Inefficiencies in vLLM Serving

During recent peak traffic tests on our large language model serving cluster running vLLM, operators observed severe and unpredictable latency spikes that severely degraded throughput. Analysis of system logs reveals that these latency regressions coincide with frequent request preemptions triggered by sudden KV cache memory exhaustion. Under high concurrency, the serving engine frequently invokes preemption routines to free up memory blocks, but the runtime behavior shows critical inefficiencies in deciding how to handle these evicted requests.

Specifically, the preemption manager often makes suboptimal trade-offs between swapping KV cache blocks out to host CPU memory and entirely discarding the blocks to rely on recomputation upon request resumption. This lack of an accurate cost model means requests with moderate context lengths are frequently swapped when recomputation would be faster and cheaper, or conversely, long contexts are recomputed from scratch when swapping would consume fewer resources. Furthermore, cluster monitoring infrastructure currently lacks a reliable way to track and aggregate the true wasted-compute overhead incurred by preemption events, leading to distorted cluster metrics and ineffective scaling policies.

To resolve this, we need a precise cost modeling module that computes the theoretical recompute-swap crossover point based on actual hardware bandwidth and compute capabilities, accurately extracts wasted-compute overhead from recorded preemption execution logs, and dynamically drives the optimal preemption policy to stabilize tail latencies.
