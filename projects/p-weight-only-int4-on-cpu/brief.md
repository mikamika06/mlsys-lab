# Тікет: Модель не влазить у пам'ять сервера без прискорювача

Наш основний сервер для інференсу на базі центрального процесора зіткнувся з критичною проблемою під час розгортання нової великої мовної моделі. Об'єм оперативної пам'яті виявився недостатнім для завантаження повноцінних ваг у форматі FP16 або навіть INT8 без використання додаткових графічних прискорювачів, яких на поточному вузлі немає в наявності.

Команда архітекторів запропонувала використати квантування ваг до 4 біт (weight-only INT4), щоб радикально скоротити споживання пам'яті та дозволити моделі успішно стартувати на чистих CPU-нодах. Проте виникли серйозні побоювання щодо стабільності роботи такої схеми. По-перше, просте округлення та зниження розрядності можуть призвести до катастрофічної деградації якості генерації тексту, що зробить відповіді моделі непридатними для продакшн-середовища. По-друге, розпаковка та декодування 4-бітних ваг «на льоту» під час виконання кожного матричного множення можуть спричинити суттєві накладні витрати й значно уповільнити час генерації токена, нівелюючи переваги економії пам'яті.

Необхідно реалізувати надійний пайплайн квантування та швидкого декодування ваг у 4 біти для CPU, який забезпечить коректне стиснення матриць, збереження прийнятного рівня якості відповідно до еталонних базлайнів, мінімальні витрати на декодування та можливість гнучкого налаштування групи масштабів. Усі зміни повинні покриватися автоматичними регресійними тестами для гарантування стабільності.
