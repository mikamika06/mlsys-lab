# Symptom Report: Runner Configuration Desynchronization and Unplanned Recycles

During heavy multi-tenant inference workloads involving dynamic client requests, local runner instances exhibit unpredictable latency spikes and intermittent state mismatches between the configured model parameters and actual generation behavior. Operators report that modifying environmental variables or request-level options occasionally fails to apply, while certain parameter updates trigger expensive full-process restarts and model re-allocations in memory despite no changes occurring to the base weight files or static context configurations.

Furthermore, monitoring pipelines attempting to track runner lifecycle events via aggregate counter metrics are currently blind to subtle mid-stream reloads, resulting in skewed utilization telemetry and undetected configuration fallbacks. The local runner management layer requires a precise, deterministic system to resolve option precedence across Modelfiles, request payloads, and host environments, accurately partition parameters into load-time versus sample-time categories based on runtime performance signatures, and robustly identify every individual runner recycle event purely from structural metric counters without relying on external process orchestration logs.
