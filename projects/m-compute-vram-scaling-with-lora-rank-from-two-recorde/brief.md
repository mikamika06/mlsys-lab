Our fine-tuning pipeline memory estimator fails to predict GPU memory overhead and compute budget when sweeping LoRA rank parameters in Unsloth training jobs. Infrastructure teams currently launch trial runs at rank $r=8$ and $r=32$, but when engineers request runs at $r=64$ or $r=128$, jobs frequently crash with Out-Of-Memory (OOM) errors or exceed timed job queues.

Log metrics from two Unsloth runs at different ranks are collected in telemetry files, recording peak allocated VRAM bytes and step FLOPs. However, our job planner treats memory scaling as a simple linear multiplier on total baseline memory rather than properly decoupling static base parameters (base model weights, KV activations, optimizer states) from rank-dependent LoRA adapter state and activation memory.

We need a module that parses two recorded Unsloth run logs at distinct ranks $r_1$ and $r_2$, extracts the static intercept and per-rank scaling slopes for both VRAM and compute, and projects peak VRAM and step compute requirements for arbitrary target ranks $r_{\text{target}}$. In addition, a regression test suite must be implemented in `tests/test_regression.py` to ensure rank scaling predictions maintain non-zero static intercept isolation and catch invalid slope formulations.
