Production vLLM clusters serving large language models are experiencing suboptimal time-per-output-token (TPOT) under peak interactive chat workloads, leading to high latency spikes and increased user-perceived delays. Although speculative decoding using secondary draft heads has been proposed to alleviate this bottleneck, naive implementations of tree-based speculative decoding like EAGLE3 fail to properly configure draft model execution trees and synchronization barriers on our serving infrastructure. When attempting to enable EAGLE3, administrators observe that the inference engine either falls back to standard autoregressive generation or produces incorrect speculative token verification logs, rendering the expected speedups inaccessible. Furthermore, monitoring tools fail to correctly compute key serving metrics such as token acceptance rates and end-to-end latency ratios, leaving operators blind to whether the feature is actually contributing to performance gains or degrading throughput. We need a robust configuration, server execution runner, and metrics reporting pipeline that correctly sets up EAGLE3 speculative decoding, processes token generation requests under real server conditions, accurately measures the draft acceptance rate, and computes the exact TPOT gain and latency ratio against baseline serving configurations without regressions.
