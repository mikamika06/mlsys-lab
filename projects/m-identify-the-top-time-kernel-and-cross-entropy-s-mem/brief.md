When profiling unsloth fine-tuning runs with custom Triton kernels and fused cross-entropy layers, engineers notice that performance bottlenecks shift unpredictably across training steps. Standard PyTorch profiler summaries dump thousands of overlapping events without distinguishing whether execution time is dominated by custom backward kernels or if memory overheads are being inflated by intermediate logits and activation tensors in the cross-entropy loss computation. Without an automated way to query trace events, engineers spend hours manually inspecting JSON timelines in Chrome Trace Viewer, making it impossible to systematically catch regressions in kernel efficiency or memory allocation spikes. This exercise unit builds a lightweight trace analyzer to programmatically extract the top-time kernel and calculate cross-entropy's exact memory share from recorded profiler traces.
