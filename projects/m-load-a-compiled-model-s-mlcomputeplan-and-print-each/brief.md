Our edge model deployment pipeline on Apple Silicon devices is experiencing unexpected latency spikes and elevated power consumption during real-time inference. System telemetry indicates that key neural network layers are falling back to the host CPU and GPU instead of executing on the Apple Neural Engine (ANE). However, our internal profiling tools currently lack support for parsing compiled `MLComputePlan` artifacts. As a result, performance engineers cannot determine device dispatch distributions or identify why specific operators fail ANE execution checks.

We need a dedicated profiling library under `mlplan` to ingest compiled compute plan dictionaries, track operator dispatch placements, and extract fallback reasons. The tool must parse operator execution attributes, calculate exact routing fractions across ANE, GPU, and CPU hardware units, and extract detailed rejection records along with associated cost metadata for all operators that failed ANE placement. Finally, the suite must include regression unit tests in `tests/test_regression.py` to prevent silent suppression of ANE fallback warnings in future releases.
