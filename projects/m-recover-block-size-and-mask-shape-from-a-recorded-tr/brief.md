When debugging custom Triton kernels or building tools that analyze low-level GPU execution traces, understanding the exact grid layout, thread-block dimensions, and memory access patterns is critical. During a recent investigation into optimized attention kernels, a performance engineer noticed that memory traces captured via Triton's visualization and instrumentation tools contained detailed records of individual memory operations, coordinate offsets, and block-level indexing. However, raw traces only store linear access indices and thread configurations without explicitly documenting the derived `BLOCK_SIZE` or the precise multi-dimensional shape of active boolean masks used during masked loads and stores.

Your task is to build a robust analysis utility that reconstructs the underlying `BLOCK_SIZE` parameters and recovers exact mask shapes from a recorded sequence of Triton memory-access events. The tool must parse trace logs containing thread-block coordinates, pointer offsets, and predicate masks, inferring the tile dimensions and active mask boundaries without relying on high-level source code annotations. Ensure your implementation handles edge cases correctly, including ragged block boundaries at tensor margins and varying dimensions across different program instances.
