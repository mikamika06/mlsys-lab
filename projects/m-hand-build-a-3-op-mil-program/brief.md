An edge export validation run using core ML's intermediate language (MIL) has hit a snag during graph translation and optimization passes. When compiling a model featuring Scaled Dot-Product Attention (SDPA) blocks for deployment on resource-constrained hardware targets, engineers noticed unexpected memory spikes and suboptimal operator fusions during long-sequence inference benchmarks.

Specifically, inspecting the raw text dumps generated by the low-level compiler reveals that certain attention sub-graphs fail to lower into efficient fused kernels, leaving behind fragmented primitive operations that severely degrade throughput on long sequences. Furthermore, tracking down these regressions manually across hundreds of lines of text-based graph representations is error-prone, as there is currently no systematic way to parse the textual compiler dumps, verify the exact structure of a hand-built MIL program, or programmatically analyze op histograms to detect whether the SDPA graph passes successfully transformed the computational graph.

Your task is to build a comprehensive exercise unit for `mlsys-lab` that addresses this pipeline. You will construct a programmatic utility to hand-build a three-operation MIL program representation, implement a graph pass simulator to evaluate how SDPA transformations affect memory and operation density across long sequences, and write a robust text-dump op histogram parser that extracts metrics from compiler intermediate files. Finally, you will establish a regression test suite as a safety net to ensure that any future modifications to the parser or graph pass logic strictly maintain structural invariants.
