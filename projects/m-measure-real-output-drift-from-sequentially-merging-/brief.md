We are observing a critical performance regression in our low-latency model serving pipeline after deploying sequentially merged LoRA adapters. During offline training, multiple specialist adapters are trained independently on top of a shared frozen base model. To reduce memory overhead and eliminate dynamic runtime routing complexity during inference, our serving infrastructure sequentially folds these separate adapter weight updates into a single unified parameter set before loading the weights into memory.

However, validation runs on our benchmark evaluation suites indicate that the outputs generated by the sequentially merged model deviate significantly from the expected baseline behavior where adapters are applied additively or evaluated independently. Specifically, when computing inference responses over standard validation batches, the relative error metric (`rel_err`) between the sequential merge output and the true composite oracle output spikes well above acceptable production thresholds.

Engineers report that the drift becomes particularly pronounced when scaling factors are applied during successive merge steps or when matrix non-commutativity is ignored during sequential weight accumulation. This ticket tracks the implementation of a robust measurement and merging module within the low-level ML systems codebase to accurately quantify this output drift, validate correct weight accumulation invariants, and establish automated regression guards to prevent deploying corrupted adapter mergers.
