Our automated Hugging Face to GGUF model conversion service has been experiencing frequent runtime failures and worker node instability in production. Jobs scheduled on 16 GB worker instances routinely crash with out-of-memory (OOM) errors halfway through converting multi-shard model weights, forcing ops teams to manually restart failed conversions on expensive high-RAM instances. In addition, large model conversion jobs frequently fail after downloading hundreds of gigabytes because missing intermediate tensor shards (e.g. shard 2 of 3) are only detected when the conversion script reaches the missing file.

To make matters worse, custom Hugging Face model repositories with non-standard or unknown pre-tokenizer configurations are triggering tokenizer validation errors due to mismatched checksum hash (`chkhsh`) calculations, making it difficult to verify whether tokenization behavior will remain consistent after GGUF conversion.

We need a suite of pre-flight validation tools in `ggufconv` to inspect Hugging Face repository file listings before launching conversions, compute deterministic tokenizer checksum hashes (`chkhsh`) for arbitrary pre-tokenizer models, and accurately estimate peak RAM consumption for eager (`--no-lazy`) vs lazy conversion modes to ensure jobs are routed to the right worker node sizes.
