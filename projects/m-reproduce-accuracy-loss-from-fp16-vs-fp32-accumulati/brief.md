When scaling matrix multiplication kernels in Triton, engineers often observe unexpected numerical drift and performance degradation as the reduction dimension $K$ increases or when memory access patterns are suboptimal. In this investigation, you will diagnose and resolve two critical issues encountered in low-level Triton matrix multiplication kernels.

First, you will analyze the precision loss associated with FP16 versus FP32 accumulation. As the inner dimension $K$ grows larger, standard FP16 accumulation suffers from catastrophic precision loss and underflow due to its limited dynamic range and mantissa precision compared to FP32. You will implement a mechanism to track and bound the relative error (`rel_err`) against a high-precision reference baseline, ensuring that numerical stability is maintained even as problem dimensions scale.

Second, you will investigate how memory layout and thread block scheduling impact hardware performance. Specifically, you will compare the L2 cache hit-rate between standard row-major program ID ordering and grouped program ID ordering on a real matmul kernel. Suboptimal thread block traversal leads to cache thrashing and reduced throughput, which can be mitigated by grouping program IDs to maximize spatial and temporal locality in the L2 cache. Your task is to implement the correct accumulation strategy and block scheduling logic, validating your implementation against rigorous correctness and performance metrics.
