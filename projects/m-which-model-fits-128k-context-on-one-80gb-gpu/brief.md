We are running large language models with a 128k context window, and we need to fit them within the strict memory constraints of a single 80GB GPU. As context lengths grow to 128k tokens, the KV cache footprint expands dramatically, often consuming tens of gigabytes depending on the batch size, number of layers, hidden dimensions, and particularly the precision of the KV cache representation (such as fp16, fp8, or int4).

Recently, during high-load serving benchmarks, we noticed that certain configurations that easily fit standard 4k or 8k contexts are failing with out-of-memory errors as soon as the active sequence length pushes toward the 128k limit, even when running on high-capacity 80GB accelerators. The engineering team needs a rigorous sizing and feasibility tool to determine precisely which model configurations can host a full 128k context within an 80GB budget, and to accurately analyze how different quantization choices for the KV cache (fp16 vs fp8 vs int4) alter memory consumption. Your task is to build a modular Python utility that computes exact KV cache memory footprints, evaluates datatype trade-offs, and verifies model feasibility against hardware limits, backed by robust regression tests.
