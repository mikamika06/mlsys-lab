When compiling custom PyTorch modules with dynamic control flow or unsupported operations, torch.compile introduces unexpected graph breaks. Performance dashboards show that even though the total number of kernel launches increases slightly, memory bandwidth consumption spikes dramatically for intermediate activations, wiping out the speedups we expected from operator fusion. We need a diagnostic tool in our profiling suite to programmatically ingest a recorded sequence of operations and graph break points, identify which fusion opportunities are severed by these boundaries, and quantify the exact byte volume and kernel overhead incurred by these lost fusions. Currently, our engineering team cannot audit how much memory churn is directly attributable to individual graph breaks versus inherent model complexity. Your task is to implement the core analysis engine that detects fusion pairs, isolates those severed across graph break boundaries, and computes the cumulative memory cost of the lost fusions.
