Our LLM serving performance dashboard is reporting highly erratic benchmark results across multiple deployment clusters running vLLM. Benchmark runs executed against identical model configurations display massive variances in reported Time To First Token (TTFT) p99 latencies, ranging from under 5 milliseconds to several hundred milliseconds. Infrastructure engineers are unable to audit whether benchmark runs included proper warmup cycles, whether EOS tokens were honored, or if prompt/output length distributions were artificially fixed, introducing severe length bias into the evaluation.

Furthermore, automated regression pipelines cannot reproduce past benchmark runs because CLI parameters cannot be systematically reconstructed from benchmark output metadata JSON files. Finally, our capacity planning team lacks statistical rigor when determining request sample sizes: runs are either stopped prematurely, yielding unacceptably wide confidence intervals on tail latencies, or run far longer than necessary, wasting valuable GPU cluster hours.

We need a benchmarking methodology audit package (`benchaudit`) that systematically audits benchmark configurations for common flaws, reconstructs canonical `vllm bench serve` CLI commands from result metadata, and calculates required request sample sizes to achieve a 2% confidence interval on p99 TTFT.
