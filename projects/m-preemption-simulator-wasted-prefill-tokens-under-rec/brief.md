When serving large language models under heavy concurrent request pressure, GPU KV cache memory frequently saturates, leading to runtime preemption events where running request contexts must be evicted to accommodate new arrivals or memory spikes. In our serving cluster telemetry logs, operators observe a severe degradation in effective throughput and unpredictable tail latency spikes specifically during periods of high contention when requests are abruptly aborted and restarted.

When a request is preempted under recompute-based policies, all previously processed prefill tokens are discarded from the cache, requiring the inference engine to re-execute the entire initial prompt processing phase from scratch upon rescheduling. System metrics indicate that under certain workload mixes featuring long prompts and frequent memory pressure, the cumulative volume of wasted prefill tokens dwarfs the actual token generation compute. Furthermore, choosing which active request to victimize lacks systematic modeling: current heuristic victim-selection policies lead to thrashing, where requests repeatedly get preempted right before completion, compounding recompute overhead. Engineers need a robust analytical simulator to quantify wasted prefill tokens, model the exact break-even point between recomputing and CPU/GPU swapping strategies, and evaluate deterministic victim-selection policy replays under realistic trace scenarios.
