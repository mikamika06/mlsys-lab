When deploying transformer blocks on Apple Silicon and edge hardware using PyTorch, engineers frequently encounter unexpected performance degradation or silent fallback behaviors when applying `torch.compile`. Specifically, certain operations, tensor shapes, or dynamic control flows inadvertently trigger graph breaks, forcing execution back to eager mode and eliminating potential throughput gains on the Metal Performance Shaders (MPS) backend. Furthermore, verifying that compiled modules maintain strict numerical equivalence with their eager counterparts across different execution configurations is essential before production deployment.

You are tasked with building a lightweight diagnostic and benchmarking package named `compilebench` that measures execution throughput ratios, parses diagnostic logs to isolate offending lines causing graph breaks, and rigorously verifies numerical parity between compiled and uncompiled transformer blocks. Your implementation must correctly compute performance metrics, accurately extract graph break reasons from log streams, and provide robust regression tests to safeguard compilation stability.
