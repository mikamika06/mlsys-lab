We are building a low-level machine learning systems module using Apache TVM and MetaSchedule to optimize operator performance through automated search. When tuning deep learning workloads via MetaSchedule, engineers run numerous tuning trials to discover optimal schedule templates and tile sizes, mapping out the exploration space for hardware execution.

However, a recurring issue has surfaced in our TVM compilation pipeline: we observe unpredictable performance gains and diminishing returns when scaling up the number of trial iterations. Compiling an IRModule containing multiple PrimFuncs requires extracting the correct task signatures and counts prior to launching the database tuning loop. Recently, tuning runs either fail to identify the correct extracted task count for complex multi-operator graphs or misjudge the trial-versus-latency trade-off curve, leading to wasted compilation hours or under-optimized tensor kernels.

Your task is to implement a robust measurement utility that records the trials-versus-latency curve for MetaSchedule search spaces, verifies extracted task counts and names for multi-PrimFunc IRModules, and writes a regression test suite that catches incorrect task extraction metrics or faulty curve analyses.
