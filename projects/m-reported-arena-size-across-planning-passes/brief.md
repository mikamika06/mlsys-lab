During low-level model compilation and export for edge accelerators, memory planning often executes across multiple iterative passes to optimize tensor allocations and lifetime overlaps. However, inspecting the memory planner logs reveals inconsistencies in the reported arena size across these planning passes. In some compilation targets, subsequent passes report varying or non-converging peak memory footprints for the static activation arena, making it difficult to guarantee that the final binary will fit within the target device's constrained SRAM limit.

Furthermore, optimizing memory layout through program-data separation—where constant weights and activations are segregated or repacked—shows distinct savings profiles across different allocation strategies, but current tooling lacks a unified way to quantify these savings accurately or compare them against an unoptimized baseline. Compounding this, certain programs contain unexpected dynamic or unplanned tensors that bypass static shape inference, introducing hidden runtime allocations that disrupt the planned memory schedule and evade detection until device execution fails due to out-of-memory errors.

Your task is to build a robust analysis and planning module that tracks reported arena sizes across planning passes to verify convergence, computes program-data separation memory savings for multiple allocation methods, and inspects exported program graphs to detect any unplanned or dynamic tensors. You will implement the core logic, provide comprehensive test harnesses, and write a regression test suite that serves as a safeguard against invariant violations in memory tracking.
