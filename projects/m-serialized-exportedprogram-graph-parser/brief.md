An edge deployment pipeline is ingesting serialized PyTorch models produced via torch.export, but our runtime parser is failing to extract the underlying graph structure correctly. When we attempt to inspect the exported program's graph nodes, operators, and tensor metadata, the parsing layer throws validation errors or misinterprets node targets and input/output operands. This prevents us from optimizing and executing the serialized graphs on our custom low-level inference engine. We need a robust graph parser that correctly interprets ExportedProgram structures, extracts node sequences, resolves operator signatures, and maps tensor shapes and dtypes without relying on high-level PyTorch runtime dependencies. The parser must correctly handle graph inputs, outputs, module calls, and core operator nodes while maintaining deterministic behavior across all serialized test cases.
