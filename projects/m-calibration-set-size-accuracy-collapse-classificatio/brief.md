When performing post-training INT8 quantization using OpenVINO NNCF on our CPU inference pipeline, we have observed a catastrophic drop in model accuracy under specific runtime conditions. During our weekly regression runs, certain models deployed on edge hardware exhibit erratic output distributions—sometimes producing complete NaN or saturated zero outputs—even though the FP32 baseline performs impeccably. Engineers report that this degradation appears tightly coupled with how the calibration subset is chosen and how quantization parameters are initialized. Specifically, small or unrepresentative calibration sets seem to trigger severe numerical instability inside specific layers, yet standard diagnostic logs show normal activation ranges prior to quantization wrapping. We need a systematic mechanism integrated into our quantization workflow to automatically analyze FakeQuantize node distributions, reconstruct scale and zero-point parameters from activation histograms, and robustly classify whether a chosen calibration set size will precipitate an accuracy collapse before committing the model to production deployment. This module must reliably parse network descriptions, reconstruct scales, and classify collapse risks to protect downstream inference quality.
