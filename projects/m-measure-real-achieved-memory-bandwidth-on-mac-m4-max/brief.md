Our high-throughput inference team deploying quantized Llama models on Apple Silicon M4 Max hardware reported severe execution stalls during auto-regressive decode phases. While large prefill matmuls scale cleanly across matrix sizes, small-batch matrix-vector operations suffer from massive latency spikes far below expected hardware throughput limits. Profiling reports show low ALU utilization, but the team lacks granular data on whether the bottleneck stems from memory bus saturations, bad stride access, or arithmetic intensity drop-offs.

Without an empirical roofline model calibrated specifically for the M4 Max memory architecture (documented peak memory bandwidth of 546 GB/s), optimization efforts remain reactive guesswork. We need a dedicated profiling library (`macroofline`) that calculates exact byte transfers, measures achieved memory bandwidth, computes arithmetic intensity across varying GEMM shapes, and fits an empirical roofline curve to classify whether each operation runs in a memory-bound or compute-bound regime.
