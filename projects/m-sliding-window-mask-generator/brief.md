We are running into severe performance and memory regressions when deploying our new hybrid LLM. The model architecture interleaves standard global attention layers with sliding-window attention layers (similar to Mistral).

According to the design, the sliding-window layers should maintain a bounded KV cache, meaning memory usage and generation latency per token should plateau once the sequence length exceeds the window size. Instead, we are seeing symptoms identical to a standard LLaMA-style model: latency degrades linearly with context length, and the model hits OOM exceptions during long-context generation just as early as the dense models do.

Furthermore, looking at a visualization of the raw attention score matrices, the lower-left triangles are completely dense. They should be strictly banded—tokens in a sliding-window layer must only attend to the previous `W` tokens, but they seem to be attending all the way back to the start of the sequence. We need you to fix the sliding-window mask generator to produce correct banded masks, implement a reference windowed attention forward pass to verify it, and write the memory accounting logic so the orchestrator allocates the correct KV cache sizes for hybrid layer configurations.
