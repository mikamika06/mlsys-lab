When deploying a compiled model to an edge device with a hardware accelerator enabled via a TensorFlow Lite delegate, profiling reveals that execution is heavily bottlenecked. Instead of running end-to-end on the specialized hardware, the graph is severely fragmented, causing roughly half of the execution nodes to fall back to the CPU. This constant offloading and round-tripping of tensors between the host CPU and the accelerator memory introduces massive overhead, completely neutralizing any potential performance gains or latency improvements.

The root cause typically stems from unsupported operations, incompatible data types, dynamic shapes, or implicit custom ops that break the continuous subgraph delegation chain. When a single non-delegatable operation is encountered in the middle of a dense block of supported layers, the runtime is forced to split the entire execution graph into multiple isolated subgraphs.

Your task is to analyze the graph partitioning behavior, locate the specific nodes or operators that break the subgraphs, restructure or rewrite the graph to maximize delegate compatibility, measure the latency and accelerator utilization improvements, and ensure that numerical output parity is fully preserved against the reference implementation.
