We are observing severe performance plateaus when scaling custom Triton kernels across various GPU tiers in our low-level machine learning pipelines. During routine kernel profiling and performance optimization sessions, engineers notice that certain elementwise and reduction operations fail to scale with GPU compute capacity, whereas matrix multiplication kernels scale aggressively with core count. Currently, performance tuning is entirely trial-and-error because engineers lack a systematic way to determine whether a newly written kernel is bottlenecked by global memory bandwidth or arithmetic execution units. 

When analyzing execution logs, memory-bound operations consume excessive bus bandwidth while leaving streaming multiprocessors underutilized, yet tuning tile sizes or thread block configurations often yields zero speedup. We need a rigorous, automated diagnostic module that computes arithmetic intensity—defined as floating-point operations executed per byte of DRAM traffic—and compares it against the hardware roofline crossover point. This tool must programmatically classify any Triton kernel as either compute-bound or memory-bound given specific hardware parameters, enabling our automated optimization harness to prescribe the correct tuning strategy without manual guesswork.
