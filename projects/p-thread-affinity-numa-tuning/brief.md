On a dual-socket server, doubling the number of threads yields only a 15% performance increase instead of the expected 80% near-linear scaling. When running high-throughput CPU inference workloads, latency degrades significantly and throughput plateaus well below the hardware capacity.

This symptom typically manifests when CPU cores across different NUMA nodes contend for shared memory bandwidth, or when threads frequently migrate between cores and sockets, incurring massive cache invalidation overhead and remote memory access penalties via the Inter-Socket interconnect (such as UPI or QPI). Furthermore, default operating system schedulers are often oblivious to cache topology, NUMA domains, and the distinction between physical cores and hyperthreads, scheduling distinct inference worker threads across separate sockets or competing for the same physical core.

Your task is to diagnose the root causes of this sub-optimal scaling, implement precise thread pinning and NUMA-aware memory allocation strategies, configure optimal instance-to-thread ratios, and package these optimizations into a robust, automated workflow that maintains its verification guarantees across multi-socket systems.
