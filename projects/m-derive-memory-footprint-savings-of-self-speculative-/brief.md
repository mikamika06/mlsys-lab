When scaling LLM serving infrastructure to handle high-concurrency workloads, optimizing GPU VRAM consumption is critical to maximize batch capacity and prevent out-of-memory failures. Standard speculative decoding couples a large target model with a completely separate, smaller draft model loaded alongside it in memory, resulting in significant static weight overhead and partitioned KV-cache allocations.

To mitigate this memory overhead, our engineering team is adopting a self-speculative decoding architecture (such as LayerSkip) where the target model itself acts as its own draft generator by exiting early at intermediate layers and utilizing shared backbone weights. However, production telemetry indicates that our memory estimator service is miscalculating peak memory utilization during deployment transitions. Specifically, operators notice that when switching between separate-draft configurations and self-speculative configurations under heavy context lengths and batch sizes, the reported memory-footprint savings deviate from empirical measurements, leading to under-provisioned serving instances and unexpected memory fragmentation.

Your task is to build a rigorous memory derivation and analysis module that computes weight and KV-cache footprints for both architectures, accurately derives the memory footprint savings of self-speculative decoding versus separate-draft pipelines, and incorporates robust regression checks to safeguard calculations against structural errors.
