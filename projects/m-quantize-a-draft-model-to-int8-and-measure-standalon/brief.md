When running speculative decoding to accelerate autoregressive language model inference, engineers frequently observe that the draft model execution time forms a significant portion of total generation latency. Because draft models run sequentially step-by-step for several draft tokens before target validation, their performance is heavily memory-bandwidth bound. To alleviate this bottleneck, the team attempted to quantize the draft model's weight tensors to int8 precision.

While the int8 quantized draft model executes faster in standalone execution benchmarks, downstream integration testing revealed unpredictable end-to-end throughput. In some serving configurations, total token generation speed improved noticeably, whereas in other configurations with identical batch sizes, generation speed actually regressed compared to using the unquantized float16 draft model.

The issue stems from the trade-off between draft execution speed and draft accuracy. Quantizing draft weights reduces model size and memory bandwidth demands, cutting draft step latency. However, quantization noise degrades draft logit accuracy, which in turn reduces the target model's token acceptance rate during speculative verification steps. When acceptance rate drops significantly, the target model rejects more proposed tokens and falls back to serial generation, erasing the benefits of faster draft execution.

We need to build a modular evaluation suite in our low-level serving stack to evaluate draft model quantization. We must implement int8 weight quantization for draft layers, measure the standalone latency reduction against float16 execution, simulate token acceptance rates across validation sequences for both models, and derive an analytical model to determine whether int8 draft quantization results in a net end-to-end speedup. Finally, we need regression tests to enforce that the trade-off calculation invariant holds.
