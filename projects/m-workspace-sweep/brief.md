The inference team has been migrating our text generation models to a specialized low-level tensor engine, but we are running into bizarre out-of-memory crashes in production. We are trying to find the best `workspace_size` parameter during engine compilation. We built an automated script that sweeps across different possible workspace limits, attempting to select the configuration that yields the fastest overall engine latency while still fitting within our 24GB device memory limit.

The problem is that the sweep script routinely selects an "optimal" configuration and reports that it perfectly fits in our VRAM budget. We deploy the model, and it easily handles short and typical inputs. But as soon as users send requests that reach the maximum sequence length in our optimization profile, the execution context violently crashes with an OOM.

The script is telling us the engine requires 20GB, but runtime monitoring right before the crash shows it attempting to allocate far more. It feels like the builder is somehow severely underestimating the required device memory for the engine, passing unsafe workspace limits to the compiler. We need to rewrite the engine planning and workspace sweep routines to strictly guarantee that the selected configuration will not OOM at the maximum profile shape, while still finding the minimum latency.
