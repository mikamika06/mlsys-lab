Production Ray Serve deployments handling high-concurrency large language model workloads are experiencing severe tail-latency spikes and request processing degradation under steady traffic loads. Operators report that individual replica queue depths become extremely imbalanced over time, leading to cascading head-of-line blocking where incoming queries are frequently routed to already saturated workers while other replicas sit idle. This performance cliff occurs even when aggregate cluster capacity is sufficient to handle the overall request volume, indicating a systemic flaw in how tasks are distributed across available worker instances.

Specifically, the default round-robin routing policy blindly cycles through replicas without accounting for variable generation lengths, prompt sizes, or ongoing batch execution times. Under bursty conditions, this cyclical assignment guarantees that workers processing longer sequences accumulate massive backlogs. To resolve this degradation, we need to implement a decentralized request distribution simulator and metric analyzer that contrasts traditional round-robin behavior against the power-of-two-choices load-balancing algorithm. You will build simulation primitives to measure real per-replica request distribution counts, evaluate queue length dynamics, and quantify tail-latency reduction factors under realistic synthetic workloads to ensure predictable serving performance.
