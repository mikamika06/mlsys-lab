# Ticket: Discrepancies in TensorRT engine layer introspection and profile aggregation

We are experiencing persistent operational discrepancies when validating optimized TensorRT inference engines across our distributed serving nodes. Specifically, post-deployment logs show that layer-wise execution timing and precision breakdown statistics derived from engine inspector JSON outputs fail to reconcile with our compilation targets. When inspecting layers compiled under mixed precision regimes (such as FP32, FP16, and INT8), the reported counts per precision group fluctuate unpredictably, leading to incorrect hardware resource allocations and suboptimal kernel scheduling decisions.

Furthermore, when parsing the aggregated output files generated via the `--dumpProfile` execution flag, cumulative runtime metrics and per-kernel execution counts do not sum correctly or match expected baseline profiles. This lack of visibility obscures performance regressions and prevents us from accurately isolating costly hotspots. Compounding these issues, our profiling pipeline fails to reliably flag hidden precision-boundary reformat nodes—such as implicit type-casting and data layout conversion layers inserted at transitions between disparate precision blocks. These unmonitored reformat transitions introduce unexpected latency bubbles and memory overhead. We require a reliable, automated toolkit to correctly parse inspector JSON structures, aggregate profile metrics, and detect precision-boundary reformat locations to ensure consistent model performance.
