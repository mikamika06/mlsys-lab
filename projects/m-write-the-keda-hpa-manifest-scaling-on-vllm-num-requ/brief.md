We are experiencing deployment scaling issues in our Kubernetes cluster hosting vLLM inference endpoints. During traffic spikes, the default Horizontal Pod Autoscaler (HPA) using CPU or memory utilization metrics fails to scale up quickly enough. Because Large Language Model inference workloads exhibit highly non-linear queuing dynamics where latency explodes as requests queue up before GPU utilization metrics register the load, standard resource-based autoscaling is inadequate.

We need to implement a custom KEDA (Kubernetes Event-driven Autoscaling) ScaledObject manifest that queries vLLM's internal Prometheus metrics endpoint, specifically targeting the `vllm:num_requests_waiting` metric. This metric represents the exact number of requests waiting in the prefill queue and provides an immediate, responsive signal for scaling out pods before request latency degrades.

Your task is to build out the KEDA configuration and supporting scripts that parse, validate, and construct the correct ScaledObject custom resource manifest alongside validation utilities. You will complete the modules required to inspect vLLM metric payloads, translate them into proper Prometheus scalar queries, and generate the complete KEDA ScaledObject manifest configured with the correct trigger metadata, polling intervals, and min/max replica boundaries.
