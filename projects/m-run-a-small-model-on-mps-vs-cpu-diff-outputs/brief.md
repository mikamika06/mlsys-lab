Engineers deploying small transformer or convolutional neural network models onto Apple Silicon via PyTorch's Metal Performance Shaders (MPS) backend are experiencing mysterious discrepancies and performance anomalies during execution. Specifically, when running inference on identical inputs between CPU and MPS, certain forward passes yield non-zero maximum absolute errors that exceed standard floating-point tolerances, breaking downstream accuracy validation tests. Furthermore, when analyzing staging overhead, moving tensors of varying sizes via the `.to('mps')` method exhibits non-linear latency spikes and unpredictable memory allocation patterns that do not align with expected hardware bandwidth limits, causing severe bottlenecks during rapid batch ingestion cycles. Finally, certain custom operations or less common mathematical primitives trigger abrupt application crashes with cryptic MPS-related runtime exceptions or NotImplementedError messages, but the raw exception text fails to cleanly isolate or expose the exact name of the unsupported operator, preventing automated fallback routing to CPU execution paths. We need a robust diagnostic toolkit within the runtime to systematically compare CPU versus MPS outputs using precise absolute error thresholds, profile tensor staging costs accurately across multiple tensor dimensions, and safely catch and extract unsupported MPS operation names to enforce resilient hardware execution boundaries.
