During mixed-precision training runs using PyTorch's Automatic Mixed Precision (AMP), engineers frequently wrap specific submodules, serialization steps, or precision-sensitive operations inside nested `torch.autocast` blocks. Recently, performance profiling revealed unexpected dtype promotions and memory regressions in custom transformer blocks where parts of the forward pass reverted back to full float32 or mistakenly inherited aggressive float16 casting despite explicit `enabled=False` escape hatches.

Specifically, when an outer `autocast` context enables half-precision execution and an inner nested `autocast` context attempts to explicitly disable autocast using `enabled=False`, the resulting effective execution state at deep nesting levels sometimes fails to respect the inner override. The state propagation logic either drops the inner disable flag or incorrectly merges parent and child context arguments, causing operators inside the disabled region to run under unintended precision rules.

Your task is to implement a robust utility module in `nested_cast/core.py` and `nested_cast/context.py` that accurately parses, simulates, and resolves nested autocast context hierarchies and their effective runtime flags, ensuring that disabled regions correctly override outer scopes and that all nesting invariants are fully preserved across complex block structures.
