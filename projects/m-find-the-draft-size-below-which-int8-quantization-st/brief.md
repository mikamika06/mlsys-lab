Our speculative decoding pipeline automatically quantizes candidate draft models to INT8 under the assumption that lower memory bandwidth overhead during draft generation always improves serving throughput. However, recent profiling reports on smaller draft architectures revealed an anomaly: after enabling INT8 quantization for compact draft models, overall token generation throughput regressed compared to running the exact same draft models in FP16.

When benchmarking end-to-end throughput across a sweep of draft model sizes, serving engineers observed that INT8 quantization provides clear speedups for large draft models, but actually degrades system throughput once draft model size falls below a certain parameter scale. The deployment manager currently lacks a automated utility to estimate draft step latencies under kernel launch and dequantization overheads, calculate expected acceptance yields, and pinpoint the crossover draft model size below which INT8 quantization stops paying off.

We need a structured evaluation module that models draft step latencies, computes speculative throughput metrics across precisions, locates the exact draft model size boundary where FP16 outperforms INT8, and includes regression tests to guard against invalid crossover selections.
