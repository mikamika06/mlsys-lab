We're serving an LLM with a highly varying set of prompts, many of which share common system prompts or prefixes. The team recently implemented prefix caching by chunking tokens into fixed-size blocks and hashing them to look up KV states (similar to vLLM's RadixAttention).

However, users are reporting hallucinated, nonsensical generations when they submit prompts that have different instructions but share identical middle sections. For example, if Prompt A is "Translate to French: [Article]" and Prompt B is "Summarize: [Article]", the tokens for "[Article]" are overwriting each other in the cache. The model tries to generate a French translation, but inadvertently loads KV cache states computed during the summarization request, leading to gibberish.

The attention mechanism is causal; the KV states for a block depend on all tokens that came before it. We need a hashing mechanism that strictly guarantees two blocks only share a hash if their entire causal history is identical. Your task is to implement chained block hashing, where the hash of block N incorporates the hash of block N-1. Additionally, write diagnostic functions to count how many blocks are safely reusable between two prompts, and how many blocks are "lost" (they contain identical tokens but are unshareable because their prefixes diverge).
