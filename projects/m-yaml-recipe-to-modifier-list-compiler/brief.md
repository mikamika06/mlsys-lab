We are building the foundational infrastructure for our low-level compression library, specifically targeting the llm-compressor recipes integration layer. Currently, when users supply a YAML quantization recipe, the system fails to correctly parse, validate, and compile it down into the internal modifier list representation that drives our oneshot calibration and quantization entrypoint.

Without this translation layer, the compression engine cannot ingest standard YAML configurations, rendering all downstream recipes useless. Even worse, edge cases such as empty or no-op recipes that specify zero quantization targets currently crash the builder rather than compiling cleanly into a zero-modifier list that preserves the unquantized baseline model. We need a robust YAML recipe to modifier-list compiler that handles standard block quantization, weight clipping parameters, GPTQ/AWQ block configurations, and gracefully processes null or empty recipes without throwing unexpected errors.

Your task is to implement the compiler module that ingests parsed YAML recipes, maps them to the six stated operational goals (including zero-quantization fallback, weight quantization, activation quantization, sparsity insertion, block-wise mixed precision, and calibration hooks), and ensures that all modifier parameters adhere strictly to the expected schema. A regression test suite must also be implemented to catch any schema validation regressions or incorrect fallbacks.
