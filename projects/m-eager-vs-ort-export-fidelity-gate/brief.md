# Ticket: Production ONNX Export Pipelines Failing Silent Fidelity Checks and Failing to Diagnose Tracing Errors

We are currently experiencing severe reliability issues across our automated model export pipeline from PyTorch eager execution to ONNX Runtime (ORT). During nightly builds and continuous integration runs, multiple production models fail deployment without clear diagnostic indicators. Specifically, exported ONNX graphs frequently exhibit silent numerical divergence when executed under ORT compared to native PyTorch eager mode, leading to subtle downstream prediction errors that bypass our current surface-level validation checks. Furthermore, when export or tracing operations fail catastrophically due to unsupported constructs or dynamic control flow, the resulting exception tracebacks are logged raw without categorization, flooding our telemetry and forcing engineers to manually parse dense stack traces to determine whether the failure stems from a graph break, an unsupported dynamic type, or a shape mismatch. Finally, recent post-mortem analyses revealed that several exported models contain hardcoded, baked-in Python integer constants instead of dynamic symbolic dimensions or parameterizable inputs, causing catastrophic runtime failures when batch sizes or sequence lengths vary in production inference containers. We urgently need a robust, modular validation and classification framework integrated into our export harness to systematically check eager-vs-ORT fidelity, accurately classify export and tracing tracebacks, and programmatically detect baked-in Python constants before any model artifact is cleared for staging and production deployment.
