An inference server running an INT8-quantized ONNX model on a modern GPU is exhibiting worse throughput and higher latency than its FP16 counterpart. When profiling the execution, engineers notice that instead of benefiting from native low-precision tensor core operations, the model suffers from excessive runtime fallback behavior, unexpected format conversions, and inefficient memory access patterns.

The problem stems from how the quantized graph is structured. Specifically, the network contains uncanonicalized Q/DQ (Quantize/Dequantize) node placements that force the runtime to constantly dequantize tensors back to floating-point representation before executing standard operations, or to insert expensive re-quantization steps across layers. Furthermore, when inspecting the extracted weights, the per-channel scaling factors required for accurate INT8 GEMM operations are either incorrectly parsed, flattened to per-tensor scales, or misaligned with the tensor dimensions expected by the backend engine compiler.

Your task is to investigate and resolve these low-level quantization bottlenecks. You must implement a module that correctly parses and recovers per-channel scales from a quantized ONNX model, canonicalizes the Q/DQ node placements to ensure proper kernel fusion, and diagnoses the performance anomalies to explain why the poorly structured INT8 engine runs slower than FP16. You will also write a regression test suite to safeguard against incorrect graph transformations.
