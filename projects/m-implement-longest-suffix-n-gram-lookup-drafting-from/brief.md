Users running copy-heavy generation workloads—like structured JSON extraction, RAG summarization, and repetitive log parsing—are complaining about slow token generation on our edge deployments. Speculative decoding with a secondary draft model would solve the speed issue, but we cannot afford the memory overhead of a second model on these devices.

We want to experiment with Prompt Lookup Decoding. The observation is that in highly repetitive tasks, the tokens we are about to generate often already exist earlier in the prompt or the previously generated context. If we can find the longest suffix of the current context that appears earlier in the sequence, we can just copy the tokens that followed it and use those as a "free" draft for speculative decoding.

Your task is to implement this n-gram lookup drafter from scratch. Then, to prove it actually works, build a simulator that measures the acceptance rate and step reduction on a few mock sequences compared to standard autoregressive generation. We need to be absolutely sure our decoding loop is lossless, so write a regression test that proves the simulated speculative decoding always produces the exact same sequence as the target.
