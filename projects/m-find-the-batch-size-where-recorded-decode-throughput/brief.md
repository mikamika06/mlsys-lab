We are profiling our LLM decode-phase kernel execution across varying batch sizes on a target GPU accelerator. Our performance telemetry shows that as the batch size increases from small values like 1, 2, and 4 up to moderate and large batch sizes such as 32, 64, and 128, the observed token generation throughput does not scale as expected or exhibits unexpected inflection points. Furthermore, when computing the effective memory bandwidth utilization from our measured throughput and model weight or KV cache sizes, we observe that the sustained bandwidth is dramatically lower than the hardware peak memory bandwidth even in regimes where token generation should be strictly memory-bound. Operators and profiling engineers report that standard roofline analysis suggests we should be memory-bound up to a certain critical batch size, but empirical token throughput curves exhibit premature saturation or severe degradation that standard models fail to capture. We need a robust diagnostic pipeline and analysis module to accurately pinpoint the exact batch size where the decode phase crosses over from memory-bound to compute-bound behavior, and to quantify how GEMV kernel occupancy limitations depress effective bandwidth far below theoretical hardware limits at intermediate batch sizes.
