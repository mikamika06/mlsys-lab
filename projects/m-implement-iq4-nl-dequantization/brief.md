Ticket #8841: Low-level quantization accuracy degradation and bit-per-weight computation discrepancies in GGUF loader

During recent model integration tests involving quantized GGUF weights, we observed unexpected output drift and severe numerical divergence when loading specific experimental quantization formats, notably the non-linear 4-bit and compressed superblock variants. Specifically, downstream evaluation pipelines running local inference complain that tensors using the non-linear 4-bit lookup codebook fail to reconstruct original floating-point weights within acceptable tolerances. When inspecting intermediate tensor buffers, the dequantized values exhibit a systematic skew, indicating that the index-to-value mapping or the underlying scale factors might be incorrectly applied during tensor block unpacking.

Additionally, memory footprint estimations reported by our telemetry subsystem are misaligned with physical memory allocations for models utilizing advanced low-bit formats such as the extremely compressed 2-bit, 1-bit, and ternary layouts. System administrators note that theoretical bits-per-weight (bpw) calculations returned by the introspection tools do not match the expected mathematical bounds derived from block header structures and padding bits, triggering false-positive alerts regarding out-of-bounds memory buffers and incorrect hardware memory reservations. Engineers attempting to trace superblock decoding routines for the 4-bit extended variants report invalid block strides or corrupted sub-block scaling factors when processing multi-block structures. We need a rigorous verification and implementation pass over the entire low-bit dequantization and bitrate calculation pipeline to ensure absolute bit-exact compliance with standard GGUF specifications before pushing the next runtime release.
