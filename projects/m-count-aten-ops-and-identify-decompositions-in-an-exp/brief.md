We are building a diagnostics pipeline for PyTorch's `torch.export` subsystem to audit low-level graph representations in an experimental compiler target. Recently, during model tracing and transformation passes, engineers noticed two distinct issues that disrupt lowering correctness.

First, when a model containing custom or composite operators is lowered, the exported graph retains varying levels of decomposition. Certain ATen operations remain un-decomposed depending on the active lowering flags, while others are fully flattened into core primitives. We need a reliable way to programmatically inspect an `ExportedProgram`, count the occurrences of specific ATen operator signatures, and identify which decompositions occurred during the export process. Without this visibility, downstream code generation passes fail to target the correct hardware instruction sets.

Second, during module capture, some legacy modules perform in-place mutations on global state or global configuration objects outside of pure tensor operations. When passed to `torch.export.export`, these state mutations trigger unexpected trace-time or export-time failures. Currently, these failures are caught late or manifest as opaque python tracebacks rather than structured diagnostic errors. We need a dedicated inspection harness that captures the exact export-time error thrown when an unsupported global-state mutation is encountered within the captured function boundary, extracting the precise exception type and message structure for analysis.

Your task is to implement the components in the package to satisfy these requirements across the milestones, ensuring complete visibility into ATen operator composition, decomposition tracking, and export-time error capture for global-state side effects.
