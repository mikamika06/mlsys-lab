Our large language model training cluster is experiencing severe communication bottlenecks and out-of-memory errors when scaling up distributed training with DeepSpeed ZeRO. Specifically, the engineering team has noticed that transitioning from ZeRO-1 to ZeRO-3 drastically alters memory consumption profiles per GPU rank, but the exact communication overhead and memory reduction factors under different world sizes and parameter counts are poorly understood and frequently miscalculated during resource planning.

When running large-scale training jobs, engineers struggle to automatically parse and extract partition sizes and real per-rank memory reductions from raw DeepSpeed initialization and runtime logs. Without a robust, programmatic way to analyze these logs and derive theoretical per-step communication volumes, we cannot reliably predict whether a given model configuration will saturate the interconnect or trigger memory fragmentation. We need a dedicated internal analysis utility (`zeroutil`) that computes per-step communication volume for both ZeRO-1 and ZeRO-3, parses complex log outputs to extract accurate partition sizes and memory reductions, and includes a rigorous testing framework to safeguard against communication and log-parsing regressions.
