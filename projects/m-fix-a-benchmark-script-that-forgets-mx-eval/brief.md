Because MLX uses a deferred execution model where operations build a directed acyclic graph of computations that is only executed when values are explicitly requested or evaluated via evaluation primitives, our benchmark loop is merely queuing operations rather than executing them. Consequently, the measured timings reflect only the overhead of graph construction rather than actual hardware compute execution.

To fix this, we need to carefully audit our benchmark suite and underlying execution modules. First, we must identify and properly instrument points where evaluation is required using explicit evaluation primitives. Second, we must correctly isolate and analyze where implicit evaluation occurs during tensor conversions or shape queries.
