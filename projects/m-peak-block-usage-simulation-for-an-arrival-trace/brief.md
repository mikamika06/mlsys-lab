# Peak KV Cache Block Usage Simulation and Fragmentation Analysis

Production serving systems for Large Language Models (LLMs) often experience out-of-memory (OOM) crashes or low overall device utilization when allocating KV cache memory. During high-concurrency peak load, the total memory required to retain context states for active inference requests frequently spikes. Operations engineers report that while raw token counts across active requests remain well below total GPU memory capacity, allocations fail, leading to dropped requests or severe throughput degradation.

The underlying cause typically lies in how memory is allocated for growing sequence lengths—specifically, contiguous allocation strategies versus paged block allocation strategies. Contiguous memory allocation suffers from severe internal and external fragmentation as sequences grow dynamically during generation, requiring large upfront over-allocation or frequent reallocations. Paged KV cache allocation breaks memory into small fixed-size block units, eliminating external fragmentation, though introducing minor tail-block internal fragmentation. Without accurate trace-driven simulation, it is difficult to determine the exact peak block demand for an arrival trace or measure the precise waste ratio between contiguous and paged allocation strategies under realistic sequence length distributions.

In this project, you will build a discrete arrival-trace simulator to model active sequence lifetimes and track peak memory demands. You will implement block tracking algorithms to compute total block usage over time and analyze internal waste ratios using empirical length histograms under both contiguous and paged schemes. Finally, you will write a robust regression test suite that verifies system invariants, such as ensuring paged block allocations never exceed total sequence lengths rounded up to block boundaries.
