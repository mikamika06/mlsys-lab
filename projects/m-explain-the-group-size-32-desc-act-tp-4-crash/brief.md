Our engineering team has encountered consistent and severe worker process crashes when initializing and running inference on quantized large language models under tensor parallelism. Specifically, when deploying a 70B model checkpoint quantized with a 4-bit representation, a group size of 32, and activation ordering enabled (`desc_act=True`) across a 4-GPU cluster (`tp_size=4`), the CUDA worker processes fail immediately during startup or upon receiving the first inference request.

The cluster orchestration logs report critical errors from the underlying GPU kernels, typically displaying stack traces indicating an illegal memory access or segmentation fault inside fused low-level matrix multiplication routines such as `exllama_v2_fused_gemm` or custom Triton kernel dispatchers. Interestingly, the identical checkpoint initializes and executes without any errors when running on a single GPU (`tp_size=1`). Furthermore, running with tensor parallelism set to 4 (`tp_size=4`) succeeds completely if the model is quantized using per-channel scaling (where `group_size` is disabled or set very large) or if activation ordering is turned off (`desc_act=False`).

We urgently require a robust diagnostic and validation library named `tpquant` to inspect input weight layouts, verify group index tensor mappings across tensor parallel rank slices, detect out-of-bounds scale lookups caused by permuted activations, and evaluate backend dispatch safety before initializing GPU kernels.
