Symptom: When deploying models using our multi-backend engine container, operators migrating existing configurations from vLLM deployment scripts to TensorRT-LLM are encountering mismatched memory allocations and silent failures under high concurrency. Specifically, standard deployment pipelines that specify arguments such as `--gpu-memory-utilization` and `--max-model-len` fail to map correctly to TensorRT-LLM's `KvCacheConfig` parameters, leading to out-of-memory errors or severe under-allocation of the key-value cache. Furthermore, operators are reporting that when memory limits are calculated based on total GPU capacity rather than available/free memory after overhead, the engine occasionally crashes during initialization on nodes running monitoring daemons. Additionally, configuration bundles that combine sliding window attention with unsupported block sizes or specific quantization formats pass initial validation but trigger internal assertion failures deep inside the runtime layers during sequence execution. We need a robust translation, memory calculation, and linting module that bridges vLLM command flags with TensorRT-LLM cache parameters, handles memory-fraction semantics correctly across total and free capacities, and flags invalid feature combinations before engine instantiation.
