An inference node hosting a custom local runner workload has been experiencing intermittent startup failures and performance anomalies during model deployment. When new model runners are initialized, the orchestration system sometimes halts abruptly mid-sequence, leaving behind a truncated log file that cuts off right after the initialization handshake. Operators are unable to tell whether the failure stems from a missing weight manifest file or an absent model weights directory, as both trigger similar generic termination signatures in the container output. Furthermore, when the runner successfully bypasses initial loading errors on resource-constrained host machines, system metrics indicate a silent fallback to CPU execution without any explicit error codes or exceptions being raised in the application session logs, degrading inference throughput by an order of magnitude. We need to systematically reconstruct the precise load sequence and failure point from the truncated logs, robustly distinguish between model not found and manifest not found conditions with specific error remedies, and implement a diagnostic safeguard to detect and raise an exception upon silent CPU execution fallback.
