When running multiple concurrent models through our local Ollama serving instance under high-throughput testing, we observe that once the active loaded model count reaches the threshold configured by the OLLAMA_MAX_LOADED_MODELS environment variable or server settings, subsequent requests for alternative model tags experience severe latency spikes, memory warnings, or intermittent failures where models fail to swap or load into VRAM cleanly. Instead of evicting the least recently used inactive model to free up slots for the incoming request, the local runner occasionally attempts to allocate beyond the configured capacity or evicts the wrong model instance currently handling active concurrent streams, leading to dropped connections and downstream inference errors. This symptom manifests particularly when switching rapidly between three or more distinct model tags while OLLAMA_MAX_LOADED_MODELS is constrained to a small integer like 2. We need a robust model management and eviction subsystem that accurately tracks model access timelines, enforces OLLAMA_MAX_LOADED_MODELS strict limits, and correctly executes least-recently-used evictions without disrupting active streams or violating concurrency constraints.
