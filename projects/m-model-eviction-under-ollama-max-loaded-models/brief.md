Ollama is a popular local runner for large language models, but when deploying multiple models concurrently, memory limits can quickly become saturated. Specifically, the environment variable `OLLAMA_MAX_LOADED_MODELS` governs how many models can simultaneously reside in memory (or GPU VRAM). When a new model is requested and the maximum number of loaded models is reached, Ollama must select an existing model to evict.

Recently, production operators noticed unexpected behavior during high-throughput multi-tenant request bursts. Instead of predictable Least Recently Used (LRU) behavior or clear priority-based retention, certain heavily queried smaller models are being prematurely swapped out while idle larger models remain resident, or vice versa, leading to excessive model-swapping latency spikes, cache thrashing, and dropped client connections.

Your task is to implement the core model tracking, usage telemetry updating, and eviction decision engine that simulates how Ollama evaluates model weights, memory footprints, and access timestamps to determine which model to unload when `OLLAMA_MAX_LOADED_MODELS` is exceeded. You will write the tracker, the eviction policy function, and a robust regression test suite to ensure that your eviction logic maintains state integrity under concurrent request loads without violating memory bounds.
