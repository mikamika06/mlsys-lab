An integration test suite running ONNX Runtime outputs against a reference TensorRT export is intermittently flagging discrepancies during validation checks in the deployment pipeline. When transitioning models across different runtimes, engineers frequently encounter divergence between native framework layers and optimized backend graphs.

The current triage workflow fails to distinguish between benign numerical drift—such as minor floating-point accumulation differences across hardware backends—and catastrophic structural or operator-level errors, such as transposed dimensions, unmapped custom plugins, or silent slicing bugs. Consequently, deployment operators are experiencing high rates of false-rejections where valid models are blocked, alongside hazardous false-acceptances where corrupted tensors pass downstream silently.

Your task is to build a robust diagnostic validation module named `errorclass` that ingests tensor discrepancy artifacts and runtime metadata to systematically classify error signatures, evaluate strict vs. relaxed tolerance policies without falling into false-accept or false-reject traps, and isolate whether a failure stems from localized tensor magnitude errors or global Top-1 sequence agreement degradation.

You will implement three core modules in `errorclass/`: `signature.py` for categorizing numerical error vectors and structural signatures, `tolerance.py` for evaluating adaptive threshold policies and preventing false classifications, and `metrics.py` for computing Top-1 token agreement versus per-tensor relative error norms. Finally, you will construct a rigorous regression test suite in `tests/test_regression.py` that verifies your validation boundary checks and prevents regression on faulty signature classifications.
