When scaling fully sharded data parallel training to larger or smaller world sizes, our distributed checkpointing layer fails to load or save weights correctly when transitioning between different node topologies. While the per-rank tensor metadata file is generated cleanly during a save, attempting to resume training or reshard the state dict across a different world size results in silent truncation, tensor dimension mismatches, or invalid byte offsets during the distributed IO phase.

In our multi-node cluster, we observed that saving a model checkpoint under a world size of 8 and then attempting to load it under a world size of 4 throws fatal indexing errors or produces corrupted weight tensors that cause immediate divergence in loss during the first step of post-checkpoint training. Our distributed training runs expect that sharded checkpointing should be fully portable across arbitrary world sizes via byte-exact verification of the underlying state shards, ensuring that tensor fragments map seamlessly regardless of how the communication groups are subdivided or expanded.

We need to implement a robust save and resharding mechanism that correctly calculates per-rank checkpoint file sizes, handles non-uniform tensor chunking across arbitrary world sizes, and guarantees byte-exact reconstruction of the global state dictionary. The solution must properly align tensor metadata, manage distributed byte offsets, and provide comprehensive regression tests to catch any shape or indexing drift when moving between different world topologies.
