Our serving nodes are currently suffering from unpredictable out-of-memory crashes and silent request drops during peak traffic hours. Operators report that instances configured with a seemingly generous token budget suddenly abort multiple active sessions when user prompt lengths, generation lengths, and concurrency spike simultaneously. The monitoring dashboards show memory usage creeping up non-linearly, yet our static capacity planning formulas consistently overestimate how many concurrent sessions a single GPU can support. When traffic doubles, latency degrades catastrophically instead of scaling gracefully, and we lack a reliable, deterministic way to size the KV cache budget under strict Service Level Objectives (SLOs). We need a rigorous analytical model and calculator that accurately predicts concurrent session capacity based on model architecture parameters, block size fragmentation, peak session headroom buffers, and quantization trade-offs, backed by automated regression tests to prevent future capacity planning failures before deployment.
