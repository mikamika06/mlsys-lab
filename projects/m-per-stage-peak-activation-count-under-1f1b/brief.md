# Ticket: Pipeline Parallelism Activation Memory Overflow under 1F1B Schedule

## Symptom
During large-scale training runs of large language models using pipeline parallelism with the 1F1B (One-Forward-One-Backward) schedule, distributed training jobs fail intermittently with out-of-memory (OOM) errors on intermediate pipeline stages. Interestingly, the OOM crashes do not occur uniformly across all devices or at the very beginning of the training step, but rather peak mid-way through the steady-state execution phase when the pipeline is fully saturated.

Engineers have observed that increasing the global batch size or scaling up the number of microbatches leads to sudden memory spikes on specific ranks, even when total parameter and optimizer states remain well within device capacity. Furthermore, manual profiling traces show that peak activation memory does not scale linearly with pipeline depth or total microbatch count in an intuitive way, making it difficult to statically provision GPU memory budgets or determine safe microbatch sizing configurations before launching expensive multi-node training clusters. We need a robust analytical model and trace generator to accurately compute per-stage peak activations, map full time-step memory traces across the 1F1B schedule, and automatically solve for the maximum allowable microbatch size under strict device memory constraints without trial-and-error cluster runs.
