When debugging performance regressions or analyzing fusion patterns inside PyTorch's TorchInductor compiler backend, engineers frequently inspect the generated low-level Triton kernel source code. However, reading through pointer offsets, block loads, masked operations, and manual index arithmetic makes it extremely difficult to determine the exact high-level sequence of PyTorch operators that generated the kernel. Without an automated way to trace back from the generated Triton body to the original logical operator chain, developers waste hours manually cross-referencing Inductor debug dumps with model definitions. This makes it impossible to systematically verify kernel fusion correctness or build automated optimization guardrails for custom hardware backends. You need a robust parser and reconstruction pipeline that takes synthetic or actual generated Triton kernel code snippets, identifies dataflow patterns, block operations, and mathematical transformations, and reconstructs the precise ordered chain of underlying PyTorch operations. This project builds a modular parsing and chain reconstruction utility that translates Triton kernel source text into structured operator lists and validates correctness through comprehensive regression tests.
