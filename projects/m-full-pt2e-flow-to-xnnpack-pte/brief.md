Edge devices running quantized models via the new PT2E (PyTorch 2 Export) quantization flow down to XNNPACK .pte format are experiencing severe accuracy degradation and unexpected numeric blowups during inference. Specifically, models calibrated with standard observer modules produce outputs where the maximum absolute error (`max_abs_err`) spikes dramatically compared to float baselines, especially on layers with outlier activations. Furthermore, switching between per-tensor and per-channel weight quantization configurations yields erratic error profiles that fail to satisfy tight embedded memory and precision budgets. Engineers report that while the export pipeline successfully generates `.pte` binaries, the internal tensor metadata, scale-zero-point mappings, and observer range calculations diverge from true activation distributions observed during runtime execution. This ticket addresses the need to implement a robust, end-to-end PT2E quantization, calibration, and XNNPACK export pipeline in pure NumPy that accurately mirrors PyTorch 2 Export quantization semantics, respects true activation bounds versus observer ranges, correctly handles per-channel versus per-tensor quantization parameters, and produces valid serialized `.pte` structures without numeric anomalies.
