# Ticket: Запакувати модель для рантайму без Python

Наш продакшн-сервіс інференсу мігрує на lightweight C++ / C-runtime середовище без Python інтерпретатора. Модель розпізнавання/обробки послідовностей на базі PyTorch використовує динамічні довжини контексту, змінний розмір батчу, а також кастомний C++ / CUDA оператор `custom_fused_op`, який реалізує спекулятивне згортання тензорів.

Наразі інженерна команда не може розгорнути модель за межами Python-середовища:
1. Стандартний `torch.jit.script` або `torch.onnx.export` падають або генерують некоректний граф через відсутність схем для кастомної операції та складну графіку контролю потоку з динамічними формами.
2. При використанні `torch.export` спостерігаються помилки верифікації формату тензорів (guard failures) під час запусків на реальних вхідних даних із варіативними формами.
3. Потрібно згенерувати автономний артефакт AOTInductor (компільовану бібліотеку `.so`), який містить запечену логіку обчислювального графа та підтримку кастомного оператора.
4. Необхідно надати механізм валідації (доказ еквівалентності) між оригінальною Python-моделлю та AOTInductor-артефактом на репрезентативній вибірці з 200 випадкових динамічних входів.
5. Автономний C-рантайм обгортка (або його емуляція через C-types / pure C ABI) повинен успішно завантажувати згенеровану `.so` бібліотеку і виконувати інференс без залучення `import torch` або будь-яких Python API під час самого обчислення.

Ваше завдання — реалізувати пайплайн експорту, реєстрацію кастомної операції в `torch.library`, збірку AOTInductor артефакту, перевірку числової еквівалентності та процедуру автономного запуску без Python runtime.
