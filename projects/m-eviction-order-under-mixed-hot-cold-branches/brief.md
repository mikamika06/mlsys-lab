We are experiencing critical eviction thrashing and memory fragmentation within our radix tree prefix caching layer during concurrent serving of mixed hot and cold branches. Under high-throughput multi-tenant workloads, requests frequently branch off shared prompt prefixes into distinct generation trajectories. Some of these branched subtrees represent high-frequency, highly active context chains ("hot branches"), while others represent long-tail, infrequent, or abandoned generation paths ("cold branches").

Currently, our eviction policy treats nodes within the radix tree uniformly or relies solely on simple global LRU/LFU heuristics across the entire prefix tree structure. As a result, long-lived or active cold branch roots often prematurely evict crucial blocks belonging to hot branches, or conversely, stale cold branches hold onto allocated block memory far longer than necessary without contributing to hit rates. When multiple branches compete for physical cache blocks, the system exhibits severe cache thrashing, leading to elevated time-to-first-token (TTFT) latency spikes, frequent recomputation of shared prefixes, and unpredictable memory footprint expansion.

We need to implement a dedicated eviction order management module for mixed hot and cold radix tree branches. This module must properly track branch temperatures, calculate fine-grained priority scores combining access frequency and recency, and determine the exact safe eviction sequence that protects hot prefixes while aggressively reclaiming resources from stale cold branches without breaking tree integrity.
