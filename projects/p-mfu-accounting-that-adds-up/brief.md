We have encountered a persistent and frustrating discrepancy in our training and inference performance metrics across different reporting pipelines. When running our large language models under the FlashAttention framework, three separate reporting tools provide wildly divergent MFU (Model Flops Utilization) numbers: 31%, 44%, and 58% for the exact same training run or inference workload.

This happens because each reporting script implements a different, ad-hoc formula for counting FLOPs, handling causal attention masks, accounting for Grouped-Query Attention (GQA), and separating the prefill phase from the decode phase without standardization. Because the hardware execution times and measured tokens per second are completely consistent, the root cause lies entirely in the accounting definitions and mathematical models used to estimate theoretical peak FLOPs versus actual FLOPs achieved.

We need a single, unified MFU accounting module that precisely models every architectural detail of the transformer layers, properly accounts for causal masking overhead, correctly scales for GQA key-value projection dimensions, cleanly separates prefill and decode phases, and produces numbers that strictly align with empirical benchmark measurements within a tight tolerance. All components must be consolidated into a robust library that can accept a model configuration dictionary and output an indisputable, verified MFU percentage.
