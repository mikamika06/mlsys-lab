Operators managing our low-level ML serving cluster have escalated a critical operational issue regarding severe resource contention and unpredictable tail latencies during high-concurrency prompt evaluation phases. Specifically, telemetry dashboards show that the hierarchical L2 KV-cache subsystem experiences massive memory bandwidth saturation and high eviction rates, while Time-To-First-Token (TTFT) metrics exhibit erratic spikes and occasional severe regressions instead of scaling smoothly with larger L2 capacities. Engineers report that speculative prefetching logic appears to populate the cache with token blocks that are subsequently evicted before any incoming requests can access them, while crucial hot context is pushed out prematurely. Furthermore, there is currently no systematic method to ingest production-like access logs, construct accurate reuse-distance profiles, precisely identify wasted prefetch operations, or quantitatively project the exact TTFT performance gains across different L2 memory footprints. We require a comprehensive analytical and testing pipeline to diagnose and prevent these inefficiencies.
