When working with large language models in GGUF format, particularly very large models that exceed a single file's size or file system limits, model weights are often serialized and distributed across multiple split files, known commonly as shards. Each individual shard file carries its own embedded metadata manifest describing the tensors, shapes, types, and offsets contained within that specific file, or referencing parts of the global weight distribution.

Currently, our runtime loader attempts to ingest these shards independently, treating each file as a standalone model artifact. This approach fails because downstream tensor lookups require a unified, cohesive view of the entire model topology and tensor map across all participating files. Without a consolidated logical manifest, tensor offsets overlap, global tensor index lookups fail with missing keys, and multi-file weight loading crashes during initialization.

Furthermore, users frequently encounter corrupted or incomplete downloads where one or more shard files are missing from a split sequence, or where files have been incorrectly renamed or adulterated, violating the strict naming conventions mandated by the GGUF split specification. When an invalid shard set or a malformed filename is encountered, the loader currently throws cryptic out-of-bounds errors or silent truncation faults deep inside the tensor memory mapping routines, making debugging extremely difficult.

Your task is to implement a robust manifest consolidation module that merges multiple individual shard manifests into a single logical manifest, detects incomplete or invalid shard sets, and rigorously validates all shard filenames against the expected naming conventions. You will provide the implementation code and a comprehensive test suite to safeguard against incorrect logical merging.
