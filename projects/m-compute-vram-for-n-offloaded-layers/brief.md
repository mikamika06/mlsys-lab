# Ticket: Unpredictable OOM and Sub-optimal Performance in Partial GPU Offloading

When operating large language models via llama.cpp on heterogeneous hardware configurations, platform engineers frequently encounter severe memory management failures and throughput bottlenecks. Specifically, deploying models using partial layer offloading specified through the number of GPU layers parameter (-ngl) often leads to unexpected out-of-memory crashes during inference, especially as context windows expand. Operators observe that static allocation strategies fail to account for the interplay between model weight distribution, layer-wise memory footprints, and active context memory pools residing concurrently within the accelerator device memory.

Compounding these stability issues, manually selecting an arbitrary value for the offloaded layer count results in erratic generation speeds. In many cases, increasing offloaded layers yields negligible or even negative performance returns due to PCI-e transfer overheads or mismatched batch processing limits, failing to reach the optimal hardware inflection point where compute throughput peaks relative to memory bandwidth constraints. Because operators lack a programmatic method to compute precise VRAM consumption profiles, determine the maximum feasible layer count under strict hardware memory budgets, and systematically identify the performance knee across an offloading sweep, production deployments suffer from constant trial-and-error tuning, frequent runtime faults, and suboptimal resource utilization across cluster nodes.
