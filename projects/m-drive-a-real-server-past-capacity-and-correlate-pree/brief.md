We are running a high-concurrency vLLM serving cluster under aggressive request load, driving the inference engine deliberately past its physical KV cache capacity to study system degradation. The incident report from production shows that when request arrival rates spike beyond our concurrency limits, the scheduler is forced to heavily utilize block preemption and dynamic swapping to accommodate incoming tokens.

While our average latency remains relatively stable, engineers on-call have noticed alarming spikes in tail latency, specifically the p99 metrics, during peak burst windows. Looking at the cluster telemetry dashboards, we suspect a direct correlation between the frequency of block preemption events and the dramatic tail latency degradation, but we lack a rigorous, automated diagnostic script to quantify this relationship under controlled simulation.

Your task is to build a diagnostic utility within our serving telemetry package that loads server load logs and preemption event counters, simulates or extracts preemption frequencies under overloaded conditions, and computes the statistical correlation against p99 latency metrics. You will implement data structures to parse server metrics, compute rolling window correlations, and write regression tests to ensure that the correlation analysis correctly flags anomalous preemption behavior without false positives.
