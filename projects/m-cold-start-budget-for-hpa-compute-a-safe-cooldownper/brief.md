Production vLLM pods backing our inference cluster are flapping violently under dynamic loads. When an Horizontal Pod Autoscaler (HPA) scale-down event triggers, newly removed pods are terminated, but immediate traffic spikes subsequently trigger scale-up actions before remaining pods become fully operational. The autoscaler rapidly cycles through scaling loops because the scale-down cooldown (`cooldownPeriod`) was set to a default value lower than the actual pod warm-up latency.

Additionally, our Kubernetes readiness probes are intermittently passing during weight loading and initial engine initialization because the current probe endpoint only inspects HTTP listener socket bindings rather than full inference engine readiness. This sends live user traffic to unready pods, causing high request error rates and skewing the startup phase timing measurements required to parameterize the HPA.

You must design a reliable readiness probe classifier that distinguishes basic process life from complete engine readiness, compute a tight, mathematically safe HPA `cooldownPeriod` derived from startup phase metrics and warm `torch.compile` cache lookup predictions, and write a test suite that guards against unsafe cooldown underestimates and inaccurate readiness states.
