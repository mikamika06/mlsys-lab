The current offline serving benchmark pipeline fails to accurately mirror Triton's `perf_analyzer` concurrency and request load generation behaviors when executing performance evaluations against local models. Specifically, when simulating concurrent request streams with fixed or variable arrival distributions, the resulting latency percentiles (p50, p90, p99) and request throughput calculations deviate significantly from expected analytical models under heavy queue saturation. Additionally, the system lacks standardized concurrency schedule generators and robust metric aggregation functions that handle request timing jitter correctly. Furthermore, there are no automated regression tests to protect the integrity of the load test simulation engine, leading to undetected metric drift and calculation errors when modifications are introduced to the benchmarking runner code. This unit implements a complete `perf_analyzer`-equivalent load testing simulator and metric pipeline with strict verification gates to ensure precise concurrency control and accurate percentile computations.
