We have been running extensive distributed training and inference workloads on our newly trained Sparse Mixture-of-Experts (MoE) models, and we are seeing some deeply concerning symptoms. Specifically, during high-throughput inference batches and long-context processing, our perplexity randomly spikes, and downstream task accuracy degrades without any visible errors or Out-of-Memory (OOM) crashes in the logs.

After adding some temporary print statements deep in the router, we realized what is happening: due to the rigid `capacity_factor` used to allocate fixed-size buffers for each expert, any token that routes to an expert whose buffer is already full is simply dropped. It bypasses the expert computation entirely and is replaced by a zero vector or identity mapping. Because token routing distributions are highly non-uniform and depend on the text, this "silent dropping" happens dynamically.

Right now, nobody has measured exactly how many tokens we are throwing away. We have no mathematical model predicting how the drop rate scales with sequence length and capacity factor. We also don't know the padding overhead if we were to switch to a fully lossless routing mode (where we pad all experts to match the maximum load). We need a dedicated library to compute these drop metrics on the fly, model the expected drops using statistical distributions, measure the quality penalty, and automatically recommend a safe capacity factor for a given target drop budget.
