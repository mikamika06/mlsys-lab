When running speculative decoding pipelines in low-level ML systems, managing capture sizes and memory allocation for CUDA graphs is crucial for avoiding severe host-side overhead and memory fragmentation. In our serving engine integration layer, we observe sporadic mismatch errors, illegal memory access crashes, and sub-optimal throughput bottlenecks when batch sizes and speculative token counts fluctuate dynamically. Specifically, the dynamic tensor shapes passed into the CUDA graph capture hooks do not align with the pre-allocated execution grids or the padding buckets required by the runtime engine. Furthermore, evaluating different speculative execution configurations—such as SGLang EAGLE settings under a tight KV-cache budget—often results in out-of-memory errors or severe performance degradation because the memory footprint estimation does not correctly account for the draft model's overhead combined with the target model's sliding windows and KV cache allocation blocks. Additionally, parsing verbose build logs from TensorRT-LLM to extract critical draft-engine performance counters, layer allocation statistics, and memory usage profiles currently requires tedious manual inspection, leading to incorrect parameter tuning and sub-optimal hardware utilization during engine initialization phases. We need a robust implementation that correctly computes CUDA graph capture sizes for any given maximum batch size and number of speculative tokens, calculates optimal SGLang EAGLE configurations under strict memory budgets, and programmatically extracts draft-engine statistics from recorded TensorRT-LLM verbose build logs.
