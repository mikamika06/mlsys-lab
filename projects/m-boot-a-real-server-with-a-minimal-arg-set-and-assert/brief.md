Our automated deployment integration pipeline is continuously failing during the staging smoke tests for serving endpoints. When orchestration workers spawn new serving instances with custom model alias overrides passed via `--served-model-name` command-line flags, client routing validation checks consistently fail. Downstream API gateways querying the `/v1/models` endpoint expect to receive the configured alias name in the response payload. Instead, health checks receive unexpected responses or connection failures, causing traffic routers to flag the freshly booted server as unhealthy and immediately terminate the task. Inspecting worker execution logs reveals that while CLI arguments are being provided to the server launcher, either the argument parsing layer is discarding optional CLI flags or the server request handler is failing to return the mapped model identifier on the models API endpoint. We need a reliable CLI argument parser and server instance handler that correctly parses engine options, initializes server state, and returns the accurate served model identifier when `/v1/models` is hit.
