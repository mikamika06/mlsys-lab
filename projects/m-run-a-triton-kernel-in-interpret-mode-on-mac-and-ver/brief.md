We are observing an issue in our low-level Triton profiling and execution environment on macOS systems where developers need to run Triton kernels under interpret mode (`TRITON_INTERPRET=1`) to debug tensor indexing and shared memory behaviors. Currently, engineers lack a standardized workflow to execute these interpreted kernels locally while capturing per-block timing metrics, parsing real PyTorch/Triton Proton profiler trace trees to extract the precise percentage of execution time spent within specific instrumented regions, and selecting the optimal configuration from raw autotuner sweep results obtained via `do_bench`.

Without a clean, unified interface over these components, performance regressions slip through during kernel development, and misconfigured autotuning parameters lead to suboptimal execution blocks on target hardware. We need a robust set of utility modules that let us execute Triton kernels in interpret mode with per-block metrics, process structured profiler trees to compute regional execution time shares, and parse autotuning logs to pick the absolute fastest configuration. Developers should implement the core logic for running and verifying interpreted Triton execution, analyzing profiler tree breakdowns, and selecting autotuning configurations, backed by a comprehensive regression test suite to catch structural bugs.
