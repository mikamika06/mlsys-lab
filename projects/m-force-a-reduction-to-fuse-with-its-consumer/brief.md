We are investigating a PyTorch 2.x compile pipeline issue using TorchInductor, focusing on low-level code generation for transformer-like models. When profiling our generated Triton kernels and CPU C++ outputs, our performance telemetry highlights two distinct anomalies that degrade end-to-end throughput.

First, during certain sequence-parallel or fused attention and normalization workflows, TorchInductor generates separate kernels where a reduction operation writes out intermediate global memory buffers only to be immediately loaded and consumed by a subsequent pointwise or reduction kernel. We need to inspect the Inductor intermediate IR or generated Triton code dumps to identify and force these reductions to fuse directly with their consumers, eliminating the intermediate memory roundtrip.

Second, when inspecting the CPU C++ backend output (`.cpp` files generated by Inductor), we notice that some inner loops fail to vectorize properly or include excessive scalar overhead. We need to be able to accurately classify the generated kernels in a dump and systematically count the number of vectorized loops present in the generated CPU C++ output to establish a regression baseline before applying manual or compiler-flag overrides.

Your task is to build a small utility module in `fusion/analyzer.py` that processes Inductor output code dumps, classifies kernels, counts vectorized loops in CPU C++ output, and helps formulate transformation rules to force reduction-to-consumer fusions. You will also write a regression test suite in `tests/test_regression.py` that asserts structural invariants on the loop and fusion patterns.
