Production PyTorch jobs running large transformer training pipelines are experiencing unexpected Out Of Memory (OOM) failures on 24 GB GPU instances, despite reported active tensor memory peaking at only 13.8 GB. Memory snapshot dumps captured prior to job failure indicate that the CUDA caching allocator reserved 23.9 GB before aborting. The diagnostic log shows large fragmentation gaps opening up during variable-length sequence execution, where block allocations of varying sizes leave unusable holes between active tensors.

Our offline memory planner and schedule analyzer relies on a caching allocator simulator to predict peak memory footprints and detect potential OOM conditions before submitting jobs to the GPU cluster. However, the current offline simulator predictions deviate significantly from runtime CUDA memory snapshots. The offline simulator fails to replicate best-fit allocation matching across expandable segments, leading to incorrect peak reserved memory calculations and unobserved fragmentation spikes. We need an accurate best-fit caching allocator simulator that models expandable segment allocation deltas and correctly tracks peak allocated memory, peak reserved memory, and the fragmentation gap across arbitrary allocation trace events.
