An internal service built on Ray Serve is experiencing erratic end-to-end tail latencies when requests flow across a two-stage deployment pipeline. Under peak workloads, downstream service calls via deployment handles exhibit unpredictable stalls, making it difficult to isolate whether the bottleneck resides in the ingress preprocessing stage, the cross-process communication boundary, or the downstream execution loop. Furthermore, engineering lacks a reliable way to measure per-stage latency accumulation and isolate overhead introduced specifically by the deployment handle interface. We need to implement a clean two-stage serving pipeline using Ray Serve deployment handles and instrument it to precisely track and accumulate stage-wise execution metrics without guessing or relying on wall-clock time thresholds.
