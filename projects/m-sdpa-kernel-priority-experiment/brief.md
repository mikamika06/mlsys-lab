During high-concurrency training runs on modern transformer workloads, our memory footprint abruptly spikes during attention evaluation, occasionally triggering out-of-memory (OOM) errors even when sequence lengths and batch sizes are well within historical safety margins. Engineers report that PyTorch's scaled dot-product attention (SDPA) backend dispatch is behaving inconsistently, sometimes bypassing the high-performance FlashAttention kernel in favor of the fallback Math kernel, while other times exhibiting unexpected memory inflation despite identical tensor shapes. Further investigation shows that manual control over kernel priorities via context managers or backend flags is either missing or failing to prevent fallback behaviors. We need a diagnostic harness and dedicated module to run targeted SDPA kernel priority experiments, compute exact memory blowup profiles comparing MATH and FLASH implementations, and implement a robust debug decoder function that diagnoses whether inputs are eligible for FlashAttention before dispatch occurs, complete with rigorous regression safeguards.
