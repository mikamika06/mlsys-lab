We are observing unusual CPU inference behavior on a multi-socket Intel Xeon system running a local LLaMA instance via `llama.cpp`. The deployment team noticed that token generation throughput varies wildly depending on how the underlying ggml binary was configured, compiled, and invoked. Specifically, when inspecting the build and startup logs from the Xeon server, various `GGML_*` feature flags and ISA detection indicators show up differently between builds, leading to performance divergences that fluctuate between legacy AVX-512 code paths and modern Advanced Matrix Extensions (AMX) tiles.

Furthermore, during profiling of different quantized tensor formats (such as Q4_0, Q4_K, and Q5_K), the accelerated kernel dispatcher sometimes falls back to generic vector routines instead of dispatching to tile-accelerated intrinsics or specialized dot-product loops. This causes significant drops in tokens per second under high concurrency loads.

Your task is to build a robust diagnostic and configuration module within `mlsys-lab` that parses real Xeon configure logs to extract GGML ISA flags, compares AMX-enabled vs AVX-512-only performance benchmarks, and classifies quantized tensor formats based on kernel acceleration suitability. You will implement the core extraction routines, performance comparison metrics, and format classification tools across the designated package files, while ensuring your code strictly adheres to the low-level constraints of the system. Finally, you will write a robust regression test suite to catch any incorrect ISA tier assignments or faulty kernel mappings.
