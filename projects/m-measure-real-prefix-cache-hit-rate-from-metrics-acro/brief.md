Our serving cluster running vLLM with Automatic Prefix Caching (APC) enabled is experiencing inconsistent cache efficiency across multi-turn user sessions. During peak hours, operators notice that repeat queries within the second turn of a dialogue are not consistently hitting the cached prefix blocks as expected, leading to higher time-to-first-token (TTFT) and unnecessary re-computation of common prompt prefixes and system instructions.

To diagnose and resolve this performance discrepancy, we need to inspect the live metrics exposed by the vLLM server endpoint. Specifically, we must programmatically parse the Prometheus-style `/metrics` endpoint data across a standardized two-turn workload simulation. By extracting exact counter values before and after the turns, we can compute the precise real prefix-cache hit rate rather than relying on aggregate estimates or logs.

Your task is to build a lightweight measurement tool that simulates or interfaces with the serving metrics collector, parses the relevant vLLM counters for cache requests and hits across a multi-turn conversation flow, and computes the correct hit rate ratio. You must implement the data extraction logic, build the workload runner, and write a robust regression test suite to safeguard your metrics calculation against counter drift and incorrect aggregation.
