# Реальна пам'ять моделі проти estimate-only

Панель локального раннера перед завантаженням показує, скільки моделі
знадобиться пам'яті. Ми повірили цій цифрі й розписали під неї парк машин:
на 32 ГБ — оця модель із контекстом 16k, на 16 ГБ — та сама з 4k.

На проді вийшло інакше. Машини, де за оцінкою лишалося ще пару гігабайтів,
починають вивантажувати шари на CPU, і швидкість падає втричі. Машини, де
оцінка обіцяла впритул, іноді працюють нормально. Тобто цифра з панелі не
бреше навмання — вона систематично зсунута, і треба зрозуміти на скільки й
чому, а не додавати «запас на око».

## Що ти пишеш

`lmsmem/estimate.py` — те, що рахує панель:

```python
param_count(config) -> int
kv_cache_bytes(config, context_length, kv_bytes_per_element=2) -> int
estimate_bytes(config, context_length, bytes_per_param) -> int
```

Конфігурація моделі — це `hidden_size`, `n_kv_heads`, `head_dim`,
`intermediate_size`, `vocab_size`, `n_layers`. Оцінка складається з ваг і
KV-кешу на заданий контекст, як її й рахує панель: рівно стільки байтів,
скільки просять числа.

`lmsmem/resident.py` — те, що насправді займає процес:

```python
resident_bytes(config, context_length, bytes_per_param, page_size=4096) -> int
relative_error(estimate, resident) -> float
```

Різниця береться не зі стелі. Пам'ять видається сторінками, і кожен окремий
регіон округлюється вгору до межі сторінки, а не сумарний розмір один раз.
Плюс рантайм тримає власні буфери. Твоє завдання — порахувати це так, щоб
розрив пояснювався арифметикою, а не «запасом».

`lmsmem/offload.py` — що станеться, коли не влізло:

```python
offload_split(total_bytes, gpu_ratio, page_size=4096) -> {"gpu_bytes", "cpu_bytes"}
```

Частка, що лишається на прискорювачі, теж кратна сторінці, і ніколи не
перевищує загального розміру. Сума двох частин зобов'язана дорівнювати
цілому — інваріант, який грейдер перевіряє окремо.

## Як перевіряється

Грейдер рахує еталон сам, на дванадцяти конфігураціях реальних моделей і
кількох довжинах контексту. Третій майлстоун твій: пишеш тест, а ми
підміняємо `resident_bytes` так, щоб він повертав рівно оцінку. Тобто розрив
зникає — саме той розрив, заради якого існує задача. Твій тест має це
побачити.

```
mlsys project start m-compare-lms-load-estimate-only-against-real-resident
mlsys project grade m-compare-lms-load-estimate-only-against-real-resident --milestone 1
```
