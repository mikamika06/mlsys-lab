# Ticket: Inference Mismatch After ONNX/TensorRT Export on Large Model

We recently completed the export pipeline for our core multimodal transformer model from PyTorch to ONNX and subsequently compiled it into a TensorRT engine for low-latency production serving. However, end-to-end integration tests on our staging cluster reveal a severe numerical discrepancy in the final output logits compared to the reference PyTorch implementation. The mismatch is not uniform; certain inputs pass with high cosine similarity, while others diverge catastrophically, producing garbage outputs or NaN values during generation.

The computation graph consists of approximately 900 individual nodes, including custom plugins, fused attention layers, normalization blocks, and dynamic slicing operations. Manual inspection of the entire graph is infeasible. We need a systematic debugging and reduction workflow using polygraphy-style tooling to compare intermediate tensor outputs layer by layer, isolate the exact subgraph or single faulty operation responsible for the numerical divergence, construct a minimal isolated test case reproducing the failure, apply a correct patch or operator substitution, verify full output parity across diverse validation workloads, and ensure that the reduced minimal reproduction script and regression test remain permanently committed in the repository to prevent future regressions during subsequent compiler updates. Please investigate and resolve this issue methodically without guessing.
