Our vision model export pipeline produces Core ML models whose predictions drift significantly from the original PyTorch model when evaluated on real image inputs. Downstream mobile engineers report that classification outputs shift completely or yield degraded accuracy scores after conversion.

When exporting vision models using Core ML conversion tools, the model expects raw image pixel inputs scaled into a specific range before applying internal linear transformations (scale and bias). However, our current export contract miscalculates the relationship between standard PyTorch `torchvision.transforms.Normalize(mean, std)` parameters and Core ML's `ImageType` preprocessing spec, leading to misaligned input channels and incorrect normalization offsets. Furthermore, team members are uncertain about the numerical impact on precision drift when exporting CNN architectures in standard single precision (fp32) vs half precision (fp16), and how that precision selection affects the final `.mlpackage` binary footprint on disk.

We need a deterministic utility that maps PyTorch normalization statistics (`mean` and `std`) directly into Core ML `ImageType` scale and bias parameters, evaluates output relative drift between original PyTorch forward passes and converted fp32/fp16 representations, and measures the storage footprint reduction ratio across precision tiers.
