# Custom Metal Kernel Optimization Ticket

Profiling reports a significant bottleneck during the execution of our primary inference workload on Apple Silicon. Specifically, a recurring element-wise activation and scaling operation is taking roughly 22 percent of total execution time. Investigation into the framework's default execution trace reveals that this performance degradation stems from memory bandwidth saturation. The current implementation decomposes what should be a single fused pass into four separate sequential memory passes, forcing the hardware to repeatedly read intermediate tensors from high-latency device memory back to registers and write them out again.

To eliminate this redundant memory traffic, we need to implement a custom fused Metal Performance Shading or raw Metal kernel that combines these operations into a single streamlined pass. The new kernel must read the inputs once, execute the fused arithmetic logic directly in threadgroup memory or registers, and write the final output back in a single operation.

Your task is to establish a rigorous baseline measurement of the unoptimized operation, design and implement the custom Metal kernel wrapper, verify its numerical correctness across various boundary shapes, measure the exact performance speedup relative to your own baseline, safely integrate the kernel into the model architecture without causing accuracy regressions, and ensure that behavior under non-canonical shapes remains robust and well-defined. Follow the milestones sequentially to build, validate, and integrate the solution.
