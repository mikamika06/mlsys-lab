An incident in production has exposed our OpenAI-compatible API gateway serving vLLM endpoints to intermittent client disconnections and corrupted response streams. Clients streaming chat completions report receiving mixed chunks from concurrent requests, overlapping SSE data payloads, and unparseable event blocks that lack the standard double-newline delimiters or contain malformed JSON payloads. Furthermore, requests hitting our completions endpoint versus our chat endpoint are experiencing subtle cache misses due to prefix token divergence, as the templating system prepends chat-specific control tokens that shift the prompt prefix and invalidate the vLLM prefix-caching blocks.

To resolve these stability and performance bottlenecks, we must implement a robust Server-Sent Events (SSE) framing validator that parses raw byte streams, detects interleaved or malformed frames, and raises explicit framing errors. In addition, we need a precise mapping layer that translates incoming OpenAI API request payloads into vLLM `SamplingParams` structures while properly routing extra body parameters. Finally, we need a diagnostic module and corresponding regression tests that locate and analyze the exact chat-versus-completions template tokens responsible for shifting the prefix blocks, ensuring our prefix caching mechanism remains fully operational across both API surfaces.
