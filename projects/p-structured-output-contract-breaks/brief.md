Your internal service relies on a large language model to extract entity information and return it strictly as JSON. Most of the time, the model behaves well and honors the prompt. However, in about 4% of production requests, the model breaks the implicit contract. It either wraps the JSON block in conversational padding (like "Here is the JSON you requested:"), hallucinates the wrong type for a field (returning a string instead of an integer for an age field), or simply gets truncated because the generation budget (`num_predict` or `max_tokens`) is exhausted before the JSON object is properly closed with a brace.

Because retries cost both compute and latency, you have been tasked with bringing the failure rate down to exactly zero. You will do this by replacing standard decoding with a schema-guided generation process. First, you will analyze a corpus of recent logs to categorize the failure modes. Then, you will implement grammar masking directly on the raw logits so the model is physically prevented from generating invalid tokens at each step. Finally, you will add a truncation safeguard: if the token budget is about to expire, your generation loop must force the model to correctly close the JSON structure rather than leaving it truncated. By the end, you'll have a robust system that never returns malformed data.
