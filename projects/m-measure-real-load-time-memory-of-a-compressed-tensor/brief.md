When working with compressed LLM checkpoints using the oneshot API, we often encounter situations where loading times or runtime memory footprints do not align with our theoretical estimates. During recent profiling sessions on our compressed-tensors workload pipeline, we noticed that loading serialized compressed model checkpoints leads to unexpected latency overheads and memory spikes that are not captured by simple parameter count calculations.

Specifically, when a compressed tensor checkpoint is loaded into memory, the dynamic unquantization, sparse mask decoding, or meta-tensor reconstruction phases introduce hidden memory allocations and synchronization bottlenecks. These overheads make it difficult to predict whether a given quantization or pruning recipe will actually fit within strict hardware memory budgets during initialization or if it will trigger out-of-memory errors on target devices.

Your task is to implement a robust measurement utility in `mlsys-lab` that accurately evaluates the real load-time and runtime memory consumption of compressed tensors. You will build a module to inspect compressed checkpoint files, simulate or execute the loading process while tracking exact peak memory allocations, and establish regression tests to ensure that memory measurement invariants hold true across different compression configurations.
