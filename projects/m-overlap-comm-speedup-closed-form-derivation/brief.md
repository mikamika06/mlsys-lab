Our distributed training cluster running heavy DeepSpeed jobs is encountering intermittent performance degradation, unexpected loss scaling behavior under FP16 mixed precision, and runtime configuration failures during multi-node initialization.

On 64-GPU nodes, performance monitoring shows zero communication speedup even when gradient communication and backward pass computation are scheduled to overlap, causing total iteration step times to exceed budgeted SLA bounds. Simultaneously, the dynamic loss scaling module is prematurely adjusting scale factors after unskipped gradient steps or failing to back off predictably when gradient overflow occurs, resulting in severe numerical underflow or floating-point instability. Furthermore, jobs configured with implicit or partial batch size definitions are launching with mismatched global batch sizes, causing worker ranks to hang or fail far into long-running training loops instead of failing fast at launch time.

We need a unified core engine package (`dsengine`) that models communication overlap speedup bounds using closed-form formulations, reproduces dynamic loss scaler trajectories across step windows with overflow tracking, and strictly validates DeepSpeed's `train_batch_size` consistency rules across data-parallel world sizes.
