We are expanding the profiling and performance analysis infrastructure in our low-level ML systems layer, specifically targeting automated metric extraction from Nvidia Nsight Compute (`ncu`) CLI exports. Currently, our continuous integration pipeline collects raw CSV exports from profiling runs, but our automated test harness lacks a robust parser to inspect kernel-level metrics, analyze section differentials, and catch profiling data integrity hazards.

Engineers have reported three distinct challenges when processing large `ncu` CSV exports across varying profiling configurations:
1. Extracting specific Speed-Of-Light (SOL) metrics (such as memory or compute throughput percentages) for a named list of target kernels across multiple profiling iterations can become tedious and error-prone when parsing large, unstructured columnar headers and varying metric naming conventions.
2. Comparing profiling reports generated under different collection settings—specifically contrasting `--set basic` versus `--set full` reports for the same kernel—requires systematically identifying which extra performance sections were introduced by the fuller profiling pass without relying on manual spreadsheet inspection.
3. Automated analysis pipelines frequently fail to flag untrustworthy profiling data when hardware performance counters are skewed by kernel replay mismatches or divergent execution paths during replay passes, leading to silent propagation of invalid performance metrics.

Your task is to build a modular Python package named `solparser` that automates these profiling analysis steps across three distinct milestones. You will implement robust CSV parsing for Nsight Compute exports, differential section analysis between basic and full report sets, and an automated regression test suite that guarantees correctness and flags data integrity warnings such as kernel replay mismatches.
