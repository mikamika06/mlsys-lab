Our high-throughput LLM serving infrastructure is hitting unpredictable tail latency spikes, specifically violating our strict p99 inter-token latency (ITL) SLO during mixed workloads containing both heavy prefill requests and long-running interactive decode streams. When a massive prompt arrives, its massive context window processing completely starves ongoing decode iterations if scheduled naively, or creates severe head-of-the-line blocking when chunking parameters are arbitrarily chosen without respecting system token budgets.

We need a principled chunked-prefill scheduler engine that explicitly operates under a configurable per-iteration token budget while cleanly mixing prefill chunks with decode steps without preemption overheads. Furthermore, the system must incorporate an analytical model to choose the optimal `max_num_batched_tokens` threshold directly derived from target p99 ITL constraints, workload sequence length distributions, and hardware execution bounds. Without this automated budget planning and simulation framework, our GPU utilization remains sub-optimal and tail latencies will continue to breach production SLAs under peak traffic conditions. Your task is to implement the core chunk planning algorithm, the step-wise scheduling simulator, and the SLO-driven parameter selector, complete with rigorous regression tests that catch incorrect scheduling invariants.
