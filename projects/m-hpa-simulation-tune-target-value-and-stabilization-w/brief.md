We are observing severe autoscaling thrashing and request timeout spikes in our vLLM serving tier (`rw2-vllm-serving`). When sudden request bursts arrive, the Horizontal Pod Autoscaler (HPA) immediately spins up new replicas, but due to cold-start delays and queue saturation, the traffic metrics overshoot, triggering a rapid scale-down cascade shortly after. This oscillation repeats continuously, wasting compute resources and driving tail latencies up.

Additionally, our multi-turn interactive chat sessions suffer from frequent context eviction and cache misses. Because incoming requests are load-balanced randomly across distributed stateless serving replicas without session affinity, consecutive turns of the same conversational session land on different pods. This forces each replica to re-compute the prefill stage or miss out on warmed prefix caches, significantly reducing our overall cache hit rate.

Your task is to investigate and resolve these issues across three milestones. First, you will implement an HPA simulation model that explores different target utilization values and stabilization windows to dampen scaling oscillations and avoid thrash. Second, you will diagnose a provided thrash timeline trace by identifying the exact parameter responsible for the instability. Third, you will model session affinity and quantify the exact hit-rate loss experienced when multi-turn sessions are subjected to random load balancing versus affinity-aware routing. Finally, you will write a robust regression test suite that catches any misconfigured autoscaling thresholds or broken session routing logic.
