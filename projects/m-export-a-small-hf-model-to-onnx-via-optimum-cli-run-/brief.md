When deploying transformer models from Hugging Face to Apple Silicon devices using ONNX Runtime with the CoreML Execution Provider (CoreMLExecutionProvider), developers frequently encounter unexpected performance regressions and runtime fallback behaviors. Specifically, while the model successfully exports to the ONNX intermediate representation via optimization tooling, inference execution times under the CoreML provider occasionally exhibit higher latency than the baseline CPU execution provider for identical input tensors. Furthermore, during session initialization, certain operators silently fall back to the CPU execution provider due to unsupported attribute types, dynamic shape restrictions, or missing CoreML translation kernels, resulting in a fragmented execution graph spanning multiple providers.

Engineers working on edge deployment pipelines report difficulty in programmatically auditing node placement across execution providers and verifying numerical parity between CPU and CoreML execution paths. Without automated inspection of the session execution graph and systematic latency profiling under constrained hardware simulation, performance bottlenecks and silent operator fallbacks remain undetected until production deployment. This exercise requires building a modular toolkit to parse model export configurations, simulate multi-provider ONNX Runtime sessions with CoreML and CPU execution providers, audit operator placement to isolate fallback nodes, and verify numerical precision bounds.
