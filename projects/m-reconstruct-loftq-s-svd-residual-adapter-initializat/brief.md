# Ticket: LoftQ Initialization and DoRA Parameter/Forward Inconsistencies

We are observing severe gradient divergence and incorrect parameter accounting when integrating advanced low-rank adaptation techniques into our lightweight finetuning pipeline. Specifically, when loading pre-quantized weights using LoftQ initialization strategies, the subsequent downstream fine-tuning runs produce degraded perplexity compared to baseline checkpoints. Operators report that the SVD residual approximation step does not properly align with the low-rank adapter matrices, leading to uncaptured high-frequency error components in the initial weight delta.

Furthermore, enabling directional adapter configurations (`use_dora=True`) appears to behave identically to standard LoRA during forward execution in several test modules, suggesting that magnitude-vector decomposition is either bypassed or treated as a superficial flag rather than an active directional scaling mechanism. Compounding this, our memory footprint profiling scripts report incorrect trainable parameter counts when DoRA is toggled on, failing to account for the magnitude scaling vectors and resulting in erroneous optimizer state allocations during distributed training. We need a rigorous verification and implementation of the LoftQ SVD residual initialization, accurate DoRA forward semantics, and precise parameter delta tracking.
