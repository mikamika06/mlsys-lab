We finally got our object detection model exported through the ExecuTorch conversion pipeline, and it successfully produces a `.pte` artifact file. However, every time we attempt to load and execute this model on the target ARM Cortex-M microcontroller, the system hard-faults immediately.

The device logs indicate a severe out-of-memory (OOM) exception originating in the SRAM bank during the very first forward pass, specifically somewhere around the third or fourth convolution layer. We verified the model parameters, and the static weights fit comfortably within the Flash memory constraints. The SRAM budget is strict (around 512KB for dynamic allocations).

We suspect the default ExecuTorch memory planner is not optimally sharing buffers across intermediate activations. The execution trace shows that it simply allocates a contiguous new memory block for every single intermediate tensor without ever reusing space when an earlier activation goes out of scope. We need a diagnostic toolset to parse this memory layout plan from the artifact, visualize the peak footprint, separate the static weights from the dynamic program execution, and implement a buffer re-planning strategy to pack the tensor lifetimes more efficiently into the available memory budget.
