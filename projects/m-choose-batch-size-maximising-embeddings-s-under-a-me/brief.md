# Embedding Endpoint Throughput and Truncation Optimizer

Our production embeddings service is currently underperforming during burst workloads and intermittently emitting silent silent state errors. When downstream clients submit batches of documents, the endpoint frequently hits Out-Of-Memory (OOM) failures or throttles severely due to sub-optimal batch size selection under strict memory ceilings. Furthermore, inputs that exceed the model's context window (`num_ctx`) are handling sequence boundaries inconsistently, causing unannounced payload truncation without reporting proper telemetry.

You need to implement the core execution engine for selecting optimal batch configurations and handling sequence truncation. First, implement a batch selector that evaluates candidate batch sizes to identify the exact batch size that maximizes aggregate throughput (embeddings/second) while respecting a hard peak memory budget. Second, implement an input preprocessor that applies configurable sequence truncation policies (such as `error`, `truncate_left`, or `truncate_right`) for sequences longer than `num_ctx`, returning processed token arrays alongside structured truncation metadata. Finally, write a safeguard regression test suite in `tests/test_regression.py` that validates the truncation policy behavior and ensures invalid policy configurations or unhandled sequence overflows are caught before deployment.
