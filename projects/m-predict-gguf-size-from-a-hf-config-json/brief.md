When deploying large language models locally using llama.cpp, users frequently need to estimate the memory footprint of a quantized GGUF file directly from a Hugging Face `config.json` before downloading gigabytes of weights. However, simple estimation scripts often fail or diverge significantly from actual file sizes.

Engineers report that standard memory calculators break down when confronted with modern architectural variations. Specifically, models utilizing Mixture of Experts (MoE) routing layers, tied embedding weights between input tokens and output logits, non-standard tensor naming conventions, or varying quantization bits-per-weight (bpw) distributions across distinct tensor types produce large discrepancies. A naive parameter-count multiplication assumes a uniform bit-width, ignoring padding, quantization block scales, and metadata overhead embedded within the GGUF container structure.

Your task is to build a robust size prediction engine for `mlsys-lab` that accurately parses Hugging Face configurations, accounts for weight tying and sparse MoE layers, and computes exact expected GGUF sizes across multiple quantization families. You will implement the core calculation modules, verify predictions against empirical data across diverse model families, and write a rigorous regression test suite that catches structural flaws in quantization accounting.
