We noticed unexpected drift in model output quality and memory footprint when deploying quantized weights on MLX edge runtimes. The production pipeline uses MLX quantization primitives, but the relationship between packing format, group size selection, and dequantization precision drift remains poorly verified across deployments.

Specifically, we lack automated validation for how group size impacts weight reconstruction accuracy and how packed 4-bit representation differs in memory and behavior from 8-bit quantized variants. Without an in-house baseline that checks dequantization mathematical correctness and tracks mean squared error across `group_size` settings, quantization bugs pass quietly into production.

Your task is to build a benchmark and dequantization verification utility. You will sweep group sizes across `{32, 64, 128}` to compute dequantization MSE against original unquantized float weights, implement a pure Python/NumPy hand-dequantization function for packed 4-bit weights to mirror MLX packing mechanics, evaluate 4-bit versus 8-bit weight footprint against output drift, and author a regression test suite that catches scale/bias alignment corruptions.
