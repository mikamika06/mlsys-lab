Engineers optimizing high-throughput machine learning inference workloads on Apple Silicon using Metal Performance Shaders (MPS) and MPSGraph frequently encounter unexpected CPU-GPU synchronization stalls and inflated submission overheads. During profiling sessions using Xcode Instruments with the Metal System Trace template, developers observe that certain execution pipelines generate an excessive number of individual command buffers, saturating the submission queue and degrading overall throughput. Specifically, comparing naive imperative sequences (loop-of-ops) against consolidated MPSGraph structures reveals puzzling discrepancies in command buffer counts and execution latency profiles. Furthermore, applications relying on dynamic dictionary feeds or argument binding exhibit micro-stutters and high CPU overhead due to repeated allocation and descriptor creation costs, even when the underlying tensor shapes remain static. Without a systematic method to parse trace exports, model graph submission boundaries, and quantify the performance benefits of cached buffer reuse versus runtime argument re-binding, developers struggle to diagnose why their custom edge runtimes fail to hit target frame rates or latency SLAs. Your task is to implement robust trace parsing utilities, graph structure analyzers, and buffer reuse overhead benchmarks to uncover these hidden dispatch inefficiencies and ensure correct execution invariants across target hardware execution tiers.
