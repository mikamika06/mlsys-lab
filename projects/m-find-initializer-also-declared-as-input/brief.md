An integration pipeline parsing large ONNX graphs exported from PyTorch is failing intermittently during heavy model ingestion. Engineers notice that models containing initializer tensors which are also explicitly declared in the graph's input list throw validation anomalies or produce corrupted tensor memory mappings when accessed via TensorRT parsers. Furthermore, large models containing tensors stored in external data files fail to accurately resolve byte offsets and data ranges when relative paths span multiple nested subdirectories. Finally, production tooling reports unexpected runtime segmentation faults and incorrect buffer allocations on specific Linux distributions when handling models whose raw weights exceed the 2GB memory ceiling enforced by legacy protobuf deserialization limits, despite the graph structure itself appearing fully intact and structurally valid according to standard ONNX schema specifications.
