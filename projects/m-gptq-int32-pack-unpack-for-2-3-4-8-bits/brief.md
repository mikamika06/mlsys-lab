When integrating custom low-bit weight formats into our low-level inference runtime, kernel execution fails or produces severe numerical divergence specifically on models quantized with non-standard bit widths such as 3-bit, or when attempting to ingest weight tensors originating from alternative quantization ecosystems like AWQ directly into our GPTQ-native execution pipelines. Engineers have reported that weight matrices for layers using 2, 3, 4, or 8 bits exhibit corrupted values, incorrect memory strides, and out-of-bounds memory accesses when processed by the int32 packing and unpacking routines. Furthermore, batch conversion scripts fail to align the packed column-major or row-major layouts required by target hardware kernels, leading to silent layout mismatches and catastrophic accuracy drops during prefill and decoding phases. A robust, mathematically precise implementation of bit-packing, unpacking, cross-format order conversion, and stride calculation is urgently required to stabilize low-bit model execution across all supported bit widths without relying on heavy external runtime dependencies.
