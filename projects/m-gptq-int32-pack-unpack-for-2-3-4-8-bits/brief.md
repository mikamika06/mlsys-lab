# Ticket: Weight Loading and Layout Corruptions in Low-Bit Quantization Kernels

When deploying quantized Large Language Models using custom low-bit inference engines, operators frequently encounter catastrophic numerical divergence, illegal memory access faults, and unrecoverable runtime crashes during weight loading. Specifically, model checkpoints quantized using 2-bit, 3-bit, 4-bit, and 8-bit integer configurations fail to initialize properly when packed into or unpacked from 32-bit storage registers. The resulting weight matrices exhibit severe bitwise corruption, leading to garbage activation values during prompt evaluation.

Furthermore, when attempting to ingest checkpoints trained or packed under AWQ conventions into downstream inference runtimes expecting GPTQ weight layouts, execution fails because the internal row-to-column indexing and packing orders do not match the expected hardware access patterns. This layout discrepancy triggers out-of-bounds memory accesses within custom CUDA kernels. Additionally, calculating the required tensor shapes, buffer sizes, and memory strides for arbitrary quantization configurations across non-standard channel dimensions often results in incorrect buffer allocations, truncating weight columns and corrupting tensor strides. Resolving these layout, packing, and conversion inconsistencies is critical for robust execution across diverse target models.
