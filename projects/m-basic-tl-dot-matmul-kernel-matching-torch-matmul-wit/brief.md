Our team is investigating a performance regression in our lower-level Triton matrix multiplication kernels compared to standard PyTorch and cuBLAS baselines. When running our custom Triton kernel implementation over various matrix dimensions, we notice incorrect numerical outputs on certain block configurations, unexpected compilation failures when tile sizes break alignment constraints, and a complete lack of systematic performance tracking against cuBLAS hardware limits.

Specifically, the kernel produces high maximum absolute errors when evaluated against torch.matmul on standard inputs, failing numerical validation gates. Additionally, when experimenting with different tile dimensions, we encounter silent failures or invalid configurations due to Triton's multiple-of-16 shape-alignment constraint, which must be programmatically checked and enforced before launching or evaluating candidates. Finally, we currently lack a programmatic pipeline to parse recorded real-GPU benchmark curves to compare our kernel's achieved TFLOPS against hardware limits and cuBLAS baselines across different matrix sizes.

Your task is to fix these issues across the triton dot-product matmul modules. You will implement a correct basic tl.dot matmul kernel matching torch.matmul within tolerance, validate tile sizes against Triton's strict multiple-of-16 shape-alignment constraint, and build a performance analysis helper to read and extract TFLOPS comparisons from recorded real-GPU benchmark curves.
