Under high GPU memory pressure, our vLLM-based serving cluster experiences unexpected latency spikes and elevated prefill queue lengths when preempting running inference requests. Telemetry indicates that the scheduler frequently selects inefficient preemption actions when dropping requests from memory, leading to excessive re-execution overhead during prompt recovery. Furthermore, token accounting metrics reported to the control plane show discrepancies in re-executed prefill token counts following preemption events, confusing autoscaling policies and memory budget calculations.

Investigation logs reveal that the engine lacks a unified cost model to evaluate the trade-offs between recompute-mode preemption and swap-mode preemption across varying PCIe bus bandwidths and cache memory footprints. Without accurate estimates of roundtrip PCIe host-device transfer times versus prefill throughput, requests are often assigned suboptimal preemption modes.

Your task is to implement recompute-mode preemption with accurate re-executed token tracking, construct a swap-mode PCIe cost model, and implement a selector that picks the optimal preemption mode across diverse workload profiles. Ensure your implementation passes all invariant checks and includes regression tests to prevent scheduling regressions.
