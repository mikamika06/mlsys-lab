Profiling logs from a recent deep learning inference run show unexpected stalls and hardware counter discrepancies when analyzing custom fused CUDA kernels. Engineers report that standard roofline estimates provided by basic Nsight Compute profiles do not align with manual byte-transfer and arithmetic intensity calculations, leading to confusion over whether specific layers are bottlenecked by memory bandwidth, execution pipelines, or launch latency. Furthermore, cross-checking raw DRAM throughput bytes against derived throughput percentages yields floating-point divergences, and ranking kernels by achieved throughput or GFLOP/s consistently fails when sorting under peak hardware specifications. The profiling pipeline needs a robust implementation to programmatically parse kernel execution metrics, correctly classify compute versus memory versus latency bounds from Speed-of-Light (SOL) figures, validate memory bandwidth through byte-sum time formulas, and accurately rank performance using arithmetic metrics without manual intervention or heuristic guesses.
