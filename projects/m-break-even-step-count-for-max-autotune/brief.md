# Ticket: PyTorch Inductor Compilation Mode Selection and Break-Even Analysis

Production workloads running PyTorch `torch.compile(mode="max-autotune")` are experiencing unpredictable tail latencies and multi-minute warm-up stalls on deployment clusters, while shorter-lived ephemeral jobs spend more time compiling kernels than executing actual model forward passes. Conversely, long-running serving instances pinned to `default` or `reduce-overhead` are leaving GPU performance on the table because high-throughput kernels generated by exhaustive autotuning are never leveraged.

Engineering has flagged that we lack a systematic way to predict whether `max-autotune` pays off for a given request volume or serving step budget, and we do not have a reliable mapping of what flags or knobs actually change between compile modes under the hood in PyTorch Inductor. We need a modular library (`autotune`) that exposes:
1. Extraction of the exact configuration flag delta between standard compile modes.
2. Calculation of the break-even step count where the upfront compilation overhead of exhaustive tuning is fully amortized by per-step execution gains.
3. A policy selector that picks the optimal compilation mode given a specific serving step budget and performance profile.

Your task is to implement the core components of this library under the `autotune` package, ensuring all calculations handle edge cases cleanly and all regression tests are robust against invalid fallback behavior.
