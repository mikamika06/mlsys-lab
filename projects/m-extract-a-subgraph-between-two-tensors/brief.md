Our ONNX model pipeline is processing large, complex vision and language models exported from PyTorch, but we are encountering severe memory bottlenecks and redundant operations during inference optimization with TensorRT and ONNX Runtime. When trying to isolate and optimize specific subgraphs, our tooling fails to properly excise the computational slice between two specified tensor boundaries (e.g., between an intermediate normalization output and a downstream attention projection), leading to bloated execution graphs.

Furthermore, standard ONNX graph exports retain verbose primitive sequences—specifically, consecutive Mul-Erf-Add-Mul patterns implementing activation layers—which fail to fuse into high-performance native Gelu operators supported by TensorRT execution providers. This lack of operator fusion causes unnecessary kernel launches, higher memory bandwidth pressure, and suboptimal execution latencies on target hardware accelerators. Compounding these issues, our current graph surgery passes fail to prune dead nodes and constant subgraphs effectively; static initializer-only constant folding passes leave orphaned parameters and unused weights inside the ONNX protobuf structures, inflating model footprint and complicating downstream serialization. We need a robust ONNX graph manipulation module that can extract precise subgraphs bounded by start and end tensor names, fold dead initializer-only constants safely, and pattern-match or rewrite primitive chains into single fused operators.
