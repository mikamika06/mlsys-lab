An operator working with mixed-precision GGUF models and LoRA adapters on llama.cpp noticed a subtle drift in generation outputs when comparing two workflows for deploying fine-tuned weights on quantized base models. Specifically, when an adapter is trained on a floating-point base model and then the merged model is quantized to GGUF format, the output distribution diverges noticeably from the workflow where the base model is quantized first and the adapter is applied or loaded via `--lora-scaled` at runtime.

To make matters worse, when estimating memory footprints or packaging deployment artifacts, teams often miscalculate the exact byte overhead introduced by specific rank configurations across various transformer module sets (such as attention projections versus MLP blocks), leading to out-of-memory errors or misconfigured scaling factors during inference execution.

Your task is to build a low-level Python diagnostic and tooling module under the package name `loratool` that analyzes these quantization versus adaptation divergences, computes exact tensor byte overheads for given LoRA ranks and module configurations, and validates runtime output shifts using simulated GGUF quantization noise and adapter scaling mathematics. You will implement the core logic, build the required harness and validation checks, and supply a robust test suite that catches regressions when underlying quantization-adaptation invariants are violated.
