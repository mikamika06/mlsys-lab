We are working with llama.cpp-style GGUF model files, specifically dealing with quantization recipes and tensor inventory size calculations. In our low-level ML runtime, handling mixed-precision quantization requires precise memory layout calculations before loading weights into memory.

Recently, when inspecting quantized model exports using the Q4_K_M (Mixed 4-bit quantization) scheme, engineers noticed that our runtime's loader fails to accurately compute the exact memory footprint from the layer tensor inventory alone. When attempting to pre-allocate memory buffers for model weights based on a given weight tensor inventory, the calculated output size diverges from the actual memory required by the deserialized model structure. This discrepancy causes buffer allocation failures, out-of-bounds pointer arithmetic during tensor weight mapping, and crashes when executing larger models.

Furthermore, different quantization variants such as Q4_K_S (Small) versus Q4_K_M (Medium) introduce distinct block sizes and padding behaviors for attention and feed-forward tensors, yet our current ftype recipe resolver lacks the ability to correctly select and apply these specific quantization blocks per tensor category.

Your task is to implement the ftype recipe resolver and output size prediction module for Q4_K_M inventories, explaining and handling the exact size delta between Q4_K_S and Q4_K_M formats. You must implement the inventory size predictor, build a robust recipe resolver for mixed precision, and include a regression test suite that catches any faulty size calculations or incorrect quantization block mappings.
