Our distributed inference cluster is experiencing suboptimal routing decisions when serving requests that require prefix caching across multiple nodes. Specifically, when a request is routed to a worker node that holds a stale or partially invalidated KV cache state, the system incurs a significant performance penalty due to redundant re-computation and cache miss overheads.

During high-concurrency periods, routers frequently make greedy scheduling choices based on outdated cache locality metrics, ignoring the synchronization lag between the central metadata registry and the actual worker memory state. As a result, requests that should have benefited from prefix reuse are instead dispatched to nodes where their context prefix must be re-computed from scratch, inflating Time-To-First-Token (TTFT) metrics and degrading overall cluster throughput.

We need to formalize and implement a robust mechanism to quantify the routing penalty associated with stale cache states. This involves computing the exact mismatch cost—expressed in terms of extra compute cycles and memory bandwidth wasted—when a request lands on a node with an outdated prefix cache. Furthermore, the routing policy must incorporate this quantified penalty into its cost function to avoid suboptimal node assignments, ensuring that cache locality metrics are accurately weighted against queue length and load balancing constraints in low-level ML serving infrastructure.
