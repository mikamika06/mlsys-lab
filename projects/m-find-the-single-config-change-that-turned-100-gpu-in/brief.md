We have been tracking inference performance regression reports across our local runner fleet after the recent scheduler upgrades. Specifically, on several multi-layer transformer configurations, workloads that previously achieved 100% offload execution entirely on the GPU accelerators have unexpectedly fallen back to a mixed CPU-GPU layer execution strategy. Engineers noticed that average generation throughput dropped significantly, but no clear error logs or out-of-memory exceptions were triggered during initialization.

Initial troubleshooting indicates that a subtle configuration change or variable assignment might be responsible for steering specific layers away from the device memory pool. However, manual inspection of the deployment configuration templates has proven inconclusive due to the sheer volume of parameters. Furthermore, we lack a robust mechanism to automatically extract and quantify the exact layer split ratio from raw execution log summaries containing textual PROCESSOR column mappings. Without a systematic way to parse these text outputs and predict theoretical decode throughput based on hardware memory bandwidth limitations under partial offload conditions, we cannot reliably isolate whether the drop is caused by hardware bottlenecks, misconfigured environment variables, or scheduler policy shifts. We need a diagnostic toolset integrated into our workspace to automate finding the single offending config divergence, parse processor assignments, and accurately model token generation speeds.
