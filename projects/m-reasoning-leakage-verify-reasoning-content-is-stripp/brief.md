An audit of our vLLM-based serving infrastructure has highlighted a critical data leakage vulnerability concerning requests processed against reasoning-capable open weights models. When untrusted API callers request completions or chat streams, the engine occasionally exposes internal chain-of-thought tokens, diagnostic steps, and pre-computation artifacts through the response payload. Specifically, the field designated for internal reasoning content—variously referenced as reasoning_content in delta objects or embedded within specialized output structures—is being serialized and transmitted directly to external clients rather than being completely stripped or scrubbed prior to dispatch.

This behavior violates strict enterprise security boundaries and tenant isolation policies, as private alignment steps, internal scratchpads, and sensitive prompt reflections become visible to unauthorized actors. Furthermore, downstream API consumers can exploit this exposed telemetry to infer structural states, bypass alignment guardrails, or extract confidential processing metadata.

Your task is to harden our low-level vLLM response handling code. You must implement robust sanitization logic that intercepts generation chunks and chat completion responses, inspects the response structures, and guarantees that any internal reasoning fields or hidden thinking tokens are thoroughly removed or neutralized when servicing untrusted client callers, while ensuring standard message content remains unaffected and fully performant.
