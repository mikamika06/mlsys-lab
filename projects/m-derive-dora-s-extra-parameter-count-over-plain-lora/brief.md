# Ticket #8841: Parameter count discrepancies and training instabilities in advanced adapter modules

Our low-level parameter-efficient fine-tuning pipeline is currently experiencing critical memory budget miscalculations and training instabilities during weight-decomposed adaptation and rank-stabilized scaling runs. Specifically, when deploying multi-layer transformer configurations using advanced adapter variants, the reported extra parameter counts deviate from theoretical expectations, triggering unexpected out-of-memory errors on accelerator nodes. Furthermore, downstream forward-pass validations against golden reference implementations exhibit numerical drift, leading to erratic gradient trajectories during initial fine-tuning phases.

Compounding these issues, our rank-scaling experiments indicate that unadjusted scaling increments fail to stabilize activation magnitudes properly as adaptation ranks grow larger, causing severe gradient explosions. The engineering team requires a robust, modular implementation within the adapter package that accurately computes parameter overheads for decomposed weights, executes precise forward passes matching reference NumPy states, and correctly implements stabilized scaling factors. A comprehensive test suite and regression safeguard must also be established to prevent regressions in weight decomposition and scaling invariants during optimization passes.
