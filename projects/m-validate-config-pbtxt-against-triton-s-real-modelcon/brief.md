We are experiencing a series of issues in our Triton model repository validation and serving pipeline when handling model configurations and versioning policies.

First, when onboarding new model repositories into our low-level serving infrastructure, engineers frequently draft `config.pbtxt` files manually or via scripts. These configuration files often contain structural errors, missing mandatory fields (such as maximum batch size, instance groups, or platform-specific backend definitions), or unrecognized schema fields that diverge from Triton's true `ModelConfig` protocol buffer specification. Consequently, Triton fails to load the models at runtime, leading to abrupt service crashes and difficult-to-debug startup failures in our cluster orchestration layer.

Second, our model repository directory structures are becoming disorganized due to automated CI/CD pipelines and manual hotfixes. We are encountering various broken repository layouts—such as missing version subdirectories, malformed version names, missing configuration files entirely, or orphaned weight files. Currently, our ingestion service throws generic exceptions without clearly distinguishing the exact structural failure reason, making it impossible to automatically route remediation or quarantine broken uploads.

Third, our version management layer is failing to accurately compute which specific model versions should be resident in memory under a given `version_policy` configuration (such as specific versions, latest versions, or all available versions). This miscalculation leads to premature unloading of active model versions or failing to load newly requested versions according to the policy rules, resulting in serving errors when clients request a specific or default model version.

We need a robust module that validates Triton `config.pbtxt` files against the real `ModelConfig` proto rules, precisely classifies broken repository layout states by their exact failure reason, and computes the exact set of resident model versions under a given version policy.
