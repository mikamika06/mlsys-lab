Ticket: INC-88204
Subject: Quantization deployment failures and unexpected memory OOM during model deployment rollout

Our serving team reported multiple critical failures during our quarterly model quantization rollout. First, several downstream deployment pipelines selected quantization recipes that failed during initial model loading because they assumed a calibration dataset was present when none had been collected, or conversely spent hours waiting for calibration on zero-shot low-latency workers. Second, memory budget estimates for our 70B and 13B models were wildly inaccurate. Deployed models consumed up to 12% more GPU VRAM than calculated by our deployment scripts, causing Out-Of-Memory (OOM) crashes across multiple inference nodes. Third, several pipelines were silently linked against deprecated quantization kernel variants across our four primary inference libraries (bitsandbytes, auto_gptq, auto_awq, and vllm_quant), triggering runtime warnings and subtle degradation in generation throughput.

We need a unified library selection and quantization planning module (`quantmap`). It must provide deterministic decision rules for selecting between calibration-free and calibration-based strategies, precise bits-per-parameter (BPP) calculations accounting for group-size quantization metadata overhead, and an automated dependency auditor that flags deprecated model formats and provides replacement recommendations before model quantization jobs are submitted.
