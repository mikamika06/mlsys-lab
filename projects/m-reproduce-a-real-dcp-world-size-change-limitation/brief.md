When attempting to migrate distributed checkpointing (DCP) artifacts generated under one world size to a different target world size, jobs crash or misalign shard mappings. For example, a checkpoint saved from an 8-GPU FSDP training run fails to reload directly when restarting on a 4-GPU setup, or produces silent tensor corruption due to unmatched sharding plans, metadata indexing discrepancies, and layout mismatches across ranks.

You need to diagnose why PyTorch Distributed Checkpoint (DCP) experiences world-size-change limitations when reloading checkpoints across different tensor parallelism or data parallelism world sizes. Your task is to implement a utility toolkit that can read raw sharded DCP metadata and checkpoint files, programmatically reconstruct and stitch together sharded tensor files manually across differing rank distributions, and finally export the fully reassembled tensors cleanly into a single standard Safetensors file format without relying on live distributed coordinator initialization or matching process groups.

The lab unit requires you to implement modules that parse sharded DCP metadata indices, correctly stitch split tensor fragments based on coordinate offsets, and convert the resulting unified state dict into standard single-file safetensors format. You must also write robust regression tests ensuring that your stitching logic handles edge cases such as uneven padding, partial replication, and broken coordinate metadata without corrupting underlying tensor weights.
