Our team is investigating performance degradation in several core Triton kernels deployed across production workloads. Specifically, a newly tuned flash-attention decoding kernel is exhibiting significantly lower throughput than expected on NVIDIA A100 GPUs, achieving only a fraction of its theoretical peak compute performance. Initial profiling inspections via Nsight Compute (NCU) show that the kernel is stalling, but engineers are currently unable to automatically extract and parse register pressure metrics to confirm whether register allocation limits are bottlenecking block occupancy per Streaming Multiprocessor (SM).

Compounding this diagnostic challenge, our local development fleet primarily consists of Apple Silicon Macs where CUDA hardware is unavailable. Engineers attempting to profile and debug kernel execution behavior locally are blocked because our tooling lacks support for constructing per-block execution timing tables using Triton's interpreter environment (TRITON_INTERPRET=1). Without a reliable way to emulate grid execution and measure per-block operation timelines locally, developers are forced to make blind code changes and wait for slow remote CI cycles on expensive GPU nodes.

We need a robust module that programmatically parses NCU profiling metrics to accurately isolate register-pressure-limited occupancy, alongside a local execution helper that leverages Triton's interpretation mode to synthesize per-block timing breakdowns on non-CUDA platforms.
