An edge deployment pipeline using llama.cpp with the Metal backend on an Apple Silicon device is exhibiting unexpected performance cliffs and runtime exceptions when running mixed-quantization GGUF models. During high-throughput generation tasks, tuning the GPU offload fraction parameter via the command-line flag `-ngl` results in sudden out-of-memory errors or erratic performance plateaus rather than a smooth progression of tokens per second.

Furthermore, when attempting to optimize model footprint by converting specific weight layers using `llama-quantize`, certain tensor configurations trigger an abrupt failure with the error message: `tensor dim not divisible by 256`. This halts model preparation workflows entirely for specific architectures where dimensional constraints conflict with block quantization requirements. Finally, engineers are attempting to establish a reliable evaluation matrix by comparing standard quantization profiles—specifically `Q4_K_M` versus `Q6_K`—measuring both raw file size reductions and a proxy perplexity quality metric to determine the optimal trade-off point for mobile deployment.

Your task is to build a diagnostic and simulation module for `mlsys-lab` that models the optimal `-ngl` offload fraction for token throughput without triggering memory overflow, diagnoses and simulates the tensor dimension constraint violations in quantization tools, and computes quantization metrics comparing file sizes and perplexity proxies across different quantization levels.
