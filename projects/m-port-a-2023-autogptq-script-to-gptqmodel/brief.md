We are experiencing deployment and compatibility friction when integrating older quantization workflows into modern inference stacks. Specifically, legacy scripts developed around AutoGPTQ in 2023 rely on outdated serialization formats, specific parameter layouts, and now-deprecated module wrapping conventions that fail when loaded directly by modern GPTQModel-based runtimes or high-throughput serving engines.

Engineering teams trying to upgrade their model repositories find that loading these legacy checkpoints results in shape mismatches, missing quantization configuration attributes, unexpected state dictionary key errors, or incorrect runtime kernel dispatches. Furthermore, auditing large storage buckets filled with unlabelled repository files becomes tedious when trying to automatically identify whether a given checkpoint was produced by AutoGPTQ, GPTQModel, or standard HuggingFace Transformers.

We need a dedicated utility module within our low-level ML systems suite that handles the systematic translation of 2023 AutoGPTQ configuration dictionaries and state dict structures into valid, modern GPTQModel-compatible formats. This unit must also implement a format-to-runtime compatibility oracle to verify whether specific quantization configurations can execute successfully on target runtime backends, alongside a robust directory-content classifier that accurately identifies the producing library from raw repository file listings.
