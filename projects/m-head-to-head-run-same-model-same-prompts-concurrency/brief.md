An ongoing engineering investigation into inference server throughput optimization has raised questions regarding concurrency scaling behavior between different serving engines. When running a head-to-head performance evaluation using the exact same target model weights, identical prompt distributions, and varying concurrency levels of 1, 8, and 32, the observed request throughput ratio fluctuates unexpectedly under heavy load.

Engineers report that while initial concurrency settings yield predictable performance parities, higher concurrency tiers expose subtle divergence in request scheduling efficiency, token batching behavior, and memory utilization patterns between the two compared runtime engines. Without a rigorous, automated verification pipeline to execute these controlled head-to-head runs, compute resources, and evaluate performance ratios systematically, regressions in execution efficiency go unnoticed.

Your task is to build a robust low-level harness and implementation that configures, executes, and evaluates comparative throughput ratios across specified concurrency levels, ensuring that performance characteristics are accurately quantified and protected against regression failures.
