# Ticket: GGUF Naming, Round-Trip Conversion, and Metadata Auditing

We are observing severe integration issues in our offline model-weight conversion pipelines. Downstream inference engines and model hubs fail to ingest custom quants due to malformed file naming conventions, data corruption during round-trip exchanges between GGUF binary formats and PyTorch state dicts, and silent divergence of metadata tensors between cloud-hosted and locally materialized quants.

Specifically, operators attempting to ingest various quantized distributions report that file naming validation routines are overly permissive or entirely absent, allowing malformed identifiers that break llama.cpp loader parsers downstream. Furthermore, when engineers attempt to round-trip weights by parsing a GGUF file into PyTorch tensors and serializing it back into a valid GGUF container, checksums and tensor layouts drift or fail to preserve crucial quantization parameters, quantization types, and tensor alignment invariants. Finally, infrastructure teams lack a reliable automated method to diff model metadata between an uploaded Hugging Face Hub GGUF quant and a locally generated candidate, leading to unaligned tensor shapes, missing key-value pairs, and silent runtime failures during prompt execution.

Your task is to implement a complete module that handles GGUF filename validation according to standard conventions, enables a robust round-trip transformation between GGUF binary structures and PyTorch representations, and provides a precise metadata diff utility to compare remote hub quants against local ones.
