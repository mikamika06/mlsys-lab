We are observing severe numerical instabilities in our nightly production builds of the transformer ranking model. Last week, the ML optimization team set up an ablation study to isolate the cause. They updated the builder configuration to strictly disable `cuDNN` and `cuBLASLt` tactic sources, forcing the engine to fall back to vanilla `cuBLAS` and custom kernels, which are slower but historically more numerically stable.

Despite merging these builder configuration changes, the instability has persisted. The metrics show no change in accuracy, and profiling the generated engines indicates they are still executing `cuDNN` tactics in the multi-head attention layers.

Looking at the build logs, we see the engine compilation step is completing in under 30 seconds and printing "Global timing cache loaded successfully." It appears the timing cache, generated weeks ago before the ablation study, is injecting previously timed `cuDNN` tactics into the build process, and the builder is blindly accepting them because the cache header's environment parameters (TRT version, compute capability) match our current hardware. We need to implement a parser for the timing cache header and a strict legality check that rejects any cache containing tactics from sources we are currently trying to ablate.
