# Ticket: High-Throughput KV Cache Allocation Failures Under Concurrency

During high-concurrency text generation workloads involving multiple long-context sequences sharing prefixes or branching via parallel sampling, our vLLM-inspired serving engine exhibits severe runtime anomalies. Operators have reported that GPU memory usage gradually creeps upward, failing to reclaim space even after requests finish and their associated sequence objects are entirely destroyed. This memory leak eventually manifests as sudden out-of-memory crashes during peak load windows, despite active garbage collection of request handles in the upper layers.

Compounding this stability concern, when executing multi-branch generation where a prompt forks into several candidate completions, subsequent tokens occasionally exhibit data corruption or cross-contamination, where characters or attention states from one branch bleed into another branch's output stream. Furthermore, the batch scheduler reports intermittent index out-of-range exceptions during kernel launches because the flat tensor mapping indices passed to custom attention kernels fail to align with the physical block tables assigned to active sequences.

We need a robust, low-level paged KV cache block allocator implemented from scratch. It must correctly manage physical block allocation and deallocation using an LRU-ordered free list, implement precise copy-on-write semantics with reference counting for forked sequences, and efficiently compute the flat slot mapping tensors required by flash-attention style kernels without leaking memory or corrupting shared prefix blocks.
