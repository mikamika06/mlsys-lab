Our current Python bindings for the FlashAttention kernel lack adequate input validation, leading to catastrophic failures during model training. When users pass tensors that violate the underlying C++ kernel's assumptions, they don't get a helpful Python exception. Instead, they get unhandled C++ exceptions, segmentation faults, or silent data corruption.

For example, if a user passes a tensor where the last dimension isn't contiguous in memory (often due to slicing operations), the kernel will read garbage data without complaining. If they pass a `float32` tensor, they get a cryptic CUDA kernel-not-found error instead of a clear typing explanation. If the head dimension exceeds 256 or is not divisible by 8, the GPU process aborts entirely.

We need an input-contract error classifier that inspects the properties of the Q, K, and V tensors before we ever invoke the FFI. It must evaluate shapes, strides, and dtypes, returning an array of string error codes (like `ALIGNMENT_ERROR`, `HEAD_DIM_ERROR`, `DTYPE_ERROR`, `SHAPE_ERROR`, or `NDIM_ERROR`). Your first task is to build the alignment guard checking inner-dimension contiguity. Next, build the classifier. Finally, write a regression test to ensure our guard is actually enforcing these rules and catches invalid strides.
