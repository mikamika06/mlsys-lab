In our custom low-precision training pipeline, training stability issues and gradient norm discrepancies have been logged during FP16 fine-tuning runs. Downstream gradient monitoring hooks and adaptive gradient clipping modules report wildly exaggerated gradient norms right before optimizer updates, causing premature step aborts and spurious gradient clipping.

Investigation of the logging infrastructure reveals that diagnostic tools intended to inspect gradient magnitudes after loss unscaling are receiving incorrect values. When calling gradient inspection and verification functions, the gradients attached to parameter groups either remain at their inflated FP16 loss-scaled magnitudes or return inconsistent array representations when unscaling is triggered.

We need to implement and verify a robust `GradScaler` and helper utility that correctly unscales gradients in-place across all parameter groups in an optimizer, returns the true unscaled gradients as explicit array structures for inspectability, and provides a verification routine to calculate max absolute errors against reference gradient baselines. Without a verified unscaling contract, gradient clipping scales down unscaled gradients a second time or acts on scaled gradients, destabilizing training momentum.
