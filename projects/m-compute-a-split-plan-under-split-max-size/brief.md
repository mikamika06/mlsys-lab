When working with large language models in the GGUF format, particularly across massive multi-gigabyte models or distributed environments, managing storage constraints and memory allocations often requires splitting model files into multiple shards. The llama.cpp ecosystem provides utilities to split GGUF files based on maximum file sizes or tensor count restrictions to fit into standard filesystem limits or memory blocks.

However, implementing a reliable split planner that correctly honors both size caps and tensor count caps while accurately predicting per-shard byte sizes poses significant challenges. If the splitting logic miscalculates tensor alignments, incorrectly batches sequential layers, or fails to respect threshold constraints, the resulting split files become corrupted or fail to load correctly during runtime initialization.

Your task is to implement a robust GGUF split planner module that computes accurate split plans based on maximum size constraints, predicts precise per-shard byte sizes, and cleanly enforces maximum tensor counts per shard. You will build out the core splitting algorithms, ensure accurate sizing calculations, and write regression tests to safeguard against split boundary violations and incorrect grouping logic.
