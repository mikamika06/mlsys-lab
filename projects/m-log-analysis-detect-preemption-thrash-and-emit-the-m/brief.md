The support queue is lighting up with users complaining about our vLLM serving endpoints. We are seeing cases where inference throughput completely collapses under load. We captured scheduler logs, and users note their low-priority batch requests seem to stall indefinitely, completing only when the system goes totally quiet at night. The high-priority user-facing requests zip right through, but the background tasks starve. We need a way to schedule requests where low-priority jobs gradually accumulate priority (aging) so they are bounded in how long they wait.

On a related note, the logs show what looks like severe preemption thrash. Some requests are being scheduled and immediately preempted over and over. You need to write an analyzer in `vllm_policy/logs.py` (`detect_thrash`) that spots this pattern. If the number of schedule events in the log is > 0, and the ratio of preemptions to schedule events strictly exceeds 0.25, it should emit a dictionary with a minimal configuration change: specifically, reduce the current `max_num_seqs` argument by 16 (minimum 1). If there is no thrash, return `None`.

Also in `logs.py`, implement `classify_traces`. It takes a list of traces (each with an `id` and a `series` of dicts containing `q` and `kv`). Compute the average queue depth (`q`) and average KV usage (`kv`) across the series. If the average `q` > 10.0 and `kv` > 0.85, classify the trace `id` as `"capacity-bound"`. If `q` > 10.0 but `kv` <= 0.85, classify it as `"arrival-bound"`. Otherwise (or if empty), label it `"idle"`.

Finally, in `vllm_policy/scheduler.py` implement `simulate(requests, age_factor)`. At each time step starting at 0, select the available request (where `arrival <= t`) with the highest effective priority: `prio + (t - arrival) * age_factor`. Tie-break by lowest request `id`. Decrement its `work`. When `work` reaches 0, record `t + 1` as its completion time. Return a dictionary mapping `id` to completion time. Test this heavily in `tests/test_regression.py` to ensure aging actually prevents starvation.
