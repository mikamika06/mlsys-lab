We noticed severe resident memory underestimation when running long inference sessions with GGUF model files mapped via `mmap`. While the file size on disk is known and constant, the actual physical memory occupied by page-cache resident pages varies dramatically based on access patterns, page size boundaries, prefetching, and tensor layout.

Our ops dashboards currently assume page-cache resident size directly equals the file size, or in some cases, linearly scales with simple byte reads. This causes our node-level memory budgeter to incorrectly schedule concurrent model instances, leading to unexpected OOM kills when page cache pressure triggers aggressive eviction or unexpected page faults pull unmapped tensor regions back into physical RAM.

Your task is to implement an accurate page-cache resident size estimator that models Linux page cache dynamics for mmap'd model files. You will write code to simulate page residency tracking based on tensor read accesses, account for page alignment and system page size boundaries, and build scheduling projections that estimate actual physical memory footprint over time. Finally, you will write a safeguard test suite to ensure our estimation logic correctly catches non-aligned boundary leaks.
