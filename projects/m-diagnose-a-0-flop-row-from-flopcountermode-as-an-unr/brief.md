When profiling our new custom transformer block using PyTorch's `FlopCounterMode`, the summary table contains mysterious rows showing zero FLOPs for custom attention and custom RMSNorm operations, throwing off our automated profiling pipeline. Furthermore, when auditing standard linear layer counts against our hand-derived architectural formulas, the numbers drift, and our automated model ranking script for Model Floating-point Utilization (MFU) across four different cluster configurations produces inverted or nonsensical rankings despite high token-per-second throughput numbers. We need a robust, programmatic diagnostic and auditing toolset that can correctly identify unregistered custom ops as the source of zero-FLOP rows, rigorously cross-check linear counts against theoretical bounds, and correctly compute and rank model configs by MFU without manual intervention.
