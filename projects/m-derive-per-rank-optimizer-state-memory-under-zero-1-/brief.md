When attempting to scale training for a large language model across a multi-node GPU cluster using standard distributed data parallel configurations, engineers frequently encounter sudden, frustrating Out-Of-Memory (OOM) errors during the optimizer step or gradient accumulation phases, long before the forward pass even completes its tensor allocations. System logs show GPU memory utilization spiking unpredictably during backward execution, particularly when transitioning from moderate model sizes to billions of parameters. Although reducing the global batch size temporarily mitigates the crash, it severely degrades training throughput and convergence stability. Traditional memory estimation formulas provided by naive frameworks fail to account for the nuanced memory footprint differences between unsharded optimizer states and partitioned optimizer states across varying ZeRO distributed training stages. Engineers need a precise analytical tool to calculate exact per-rank memory consumption under ZeRO-1, ZeRO-2, and ZeRO-3, and to automatically determine the minimum viable ZeRO stage required to fit specific model architectures within strict per-GPU hardware memory budgets without guesswork.
