We are currently investigating a performance anomaly on Apple Silicon hardware where certain transformer layers exhibit unexpected latency spikes during inference passes. Initial telemetry points toward inefficient operator dispatch loops within the PyTorch execution engine, but standard high-level profiling tools only show aggregated wall-clock durations without exposing individual kernel self-times or dispatch overheads.

Engineers attempting to diagnose the bottleneck are currently unable to reliably isolate the single most expensive operator by pure self-time from raw profiler export summaries, nor can they quantify the exact proportion of execution time consumed exclusively by matrix multiplication families versus memory-bound copy or elementwise operations. Furthermore, when analyzing execution traces across varying batch sizes, attempts to group profiling records by input shapes fail to accurately compute the structural row count variance, masking how dynamic shape dispatches fragment execution tables. We need a robust programmatic analysis module to parse these profiler tables, extract top-1 self-time operators, compute matmul self-time shares, and measure row count deltas across batch configurations.
