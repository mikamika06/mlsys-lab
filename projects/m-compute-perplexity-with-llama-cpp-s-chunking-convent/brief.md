Our quantization pipeline for GGML/GGUF models was updated recently, but quality evaluations across model variants are producing erratic scores. When running perplexity benchmarks against quantization candidates, the scores diverge wildly depending on the batch/chunk size passed to the evaluation harness. Furthermore, when attempting to measure KL divergence against baseline F16 logits, we are seeing unexpected spikes in divergence even on near-identical models.

When comparing quantized models (e.g., Q4_K_M vs FP16 baseline), our current scripts compute cross-entropy loss inconsistently across chunk boundaries, leading to incorrect perplexity figures. In addition, the current KL divergence metric implementation exhibits numerical instability on large vocabulary sizes and fails to track top-1 token prediction agreement accurately.

We need a standardized quality measurement module in `ppl/` that strictly follows llama.cpp's token chunking convention for perplexity calculation, correctly computes position-wise KL divergence and top-1 token agreement between FP16 baseline logits and quantized model logits, and supports dumping reference F16 logits to disk for offline scoring. Finally, we need a regression test suite in `tests/test_regression.py` that verifies our evaluation pipeline catches improper logit shifts, indexing offsets, or altered prediction distributions before deploying quantized weights.
