An inference optimization team has integrated `torch.compile` on an attention-heavy transformer model block running locally, aiming to reduce self-time and operator overhead. Initial benchmarks showed modest acceleration, but engineers noticed unexpected volatility in downstream profiling runs. Specifically, changing minor configuration flags or introducing dynamic batch dimensions causes the compilation pipeline to silently trigger full recompilations midway through execution, severely harming latency spikes. Furthermore, it remains unclear how many distinct kernels were actually generated, and whether fusion passes successfully combined elementwise operations or left them unfused, leading to unnecessary memory round-trips.

Your task is to build a profiling and verification suite inside `torchprof/` that measures real self-time and operator count reductions from `torch.compile`, intercepts and detects guard-failures using `torch._dynamo.utils.counters`, and inspects generated trace data to count fused versus unfused kernels. You must implement the profiling utilities, write a harness validation script, and author a strict regression test that catches guard-bypass regressions.
