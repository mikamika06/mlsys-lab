During prolonged inference and training loops on Apple Silicon using PyTorch MPS, processes frequently terminate unexpectedly with out-of-memory errors or suffer from severe memory bloat despite apparent availability in system monitor tools. Specifically, long generation runs consume un-reclaimed memory blocks, and setting memory caps fails to trigger the expected allocation limits early enough, causing unpredictable crashes downstream instead of graceful constraint enforcement. Furthermore, tracking allocation discrepancies between driver-level reports and current runtime allocations shows unaccounted fragmentation overhead that degrades iteration throughput over time. Engineers need a robust management module to enforce strict memory fraction ceilings, safely cadence cache purging during intensive generation steps, and continuously compute fragmentation ratios to prevent sudden process termination.
