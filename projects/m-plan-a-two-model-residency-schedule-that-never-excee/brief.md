When deploying multiple large language models concurrently on Apple Silicon unified memory, systems frequently encounter allocation bottlenecks and out-of-memory errors due to improper residency management and static memory limits. Apple Silicon architectures allow the operating system and GPU driver to share a single physical pool of unified memory, but the maximum amount of memory that can be wired (pinned) for GPU usage is governed by the system parameter `iogpu.wired_limit_mb`.

Engineers running concurrent workloads often observe that when a primary model and a secondary speculative or smaller model are resident simultaneously, their combined weight and KV cache allocations exceed the default wired limit. This causes the kernel to aggressively evict pages, thrash allocations, or fail requests outright, even though sufficient physical RAM exists on the system. Furthermore, traditional discrete GPU workflows assume a slow PCIe bus transfer where host-to-device copies dominate overhead, whereas unified memory architectures eliminate this explicit host-device copy entirely.

Your task is to implement a two-model residency schedule planner in low-level ML systems that calculates precise memory footprints, respects the wired memory limit configuration, measures the performance and residency trade-offs when `iogpu.wired_limit_mb` is dynamically adjusted, and confirms that host-device copy overhead is eliminated. You will build a module that schedules model residency blocks, computes wired memory compliance, and writes a robust regression test suite that catches schedule violations.
