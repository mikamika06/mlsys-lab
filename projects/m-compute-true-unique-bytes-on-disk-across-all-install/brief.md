# Скільки насправді байтів на диску займають встановлені моделі

Локальний реєстр моделей зберігає ваги в блобах, адресованих за вмістом:
кожен блоб має дайджест-ключ, і той самий блоб може використовуватись
кількома тегами одразу — спільний токенізатор, спільна ліцензія, а іноді й
спільні шари між квантами одної моделі. Утиліта, що показує "скільки місця
займають установлені моделі", зараз просто підсумовує розмір кожного тега
окремо — і видає число, яке помітно більше за те, що насправді лежить на
диску. Через це адмін видаляє теги, звільняючи менше місця, ніж очікував, а
місце під новий `pull` оцінює неправильно і впирається в диск на середині
довантаження.

Треба порахувати правду: скільки байтів насправді унікальні, скільки реально
довантажиться для ще одного кванту вже встановленої моделі, і які блоби вже
нікому не потрібні.

## Що ти пишеш

`blobstore/index.py` — `build_blob_index(config) -> list[blob]`. Конфігурація
— це `{"tags": {tag_name: [{"digest", "size"}, ...], ...}}`. Один і той самий
`digest` може повторюватись у кількох тегах — це один і той самий блоб на
диску, а не два різних. Блоб — це `{"digest", "size", "tags"}`, де `tags` —
відсортований список імен тегів, що на нього посилаються. Список блобів
упорядкований за `digest`.

`blobstore/cost.py`:

```python
unique_bytes_on_disk(config)
naive_total_bytes(config)
incremental_pull_bytes(config, candidate)
```

`unique_bytes_on_disk` — сума розмірів по кожному унікальному `digest` рівно
один раз. `naive_total_bytes` — сума розмірів по кожному тегу окремо, з
дублями (те, що зараз рахує наївний підсумовувач). `incremental_pull_bytes
(config, candidate)` — скільки байтів реально довантажиться, якщо поставити
ще один тег `candidate` (той самий формат, що список блобів у тезі): усе,
чийого `digest` ще немає серед уже встановлених тегів у `config`, і не по
двічі, якщо сам `candidate` згадує один і той самий блоб більше одного разу.

`blobstore/gc.py` — `find_orphaned_blobs(config, disk_blobs)` і
`orphaned_bytes(config, disk_blobs)`. `disk_blobs` — це `{digest: size}`,
те, що фізично лежить у сховищі блобів. Осиротілий блоб — той, що є на диску,
але на нього не посилається жоден тег у `config`. `find_orphaned_blobs`
повертає відсортований список таких `digest`, `orphaned_bytes` — суму їхніх
розмірів.

## Як перевіряється

Грейдер рахує еталон сам, із тих самих конфігурацій, на кількох установках і
сценаріях довантаження. Третій майлстоун — твій: пишеш тест, а ми підміняємо
побудову індексу на таку, що зливає два різні блоби в один запис, коли в них
випадково збігається розмір. Твій тест має це побачити.

```
mlsys project start m-compute-true-unique-bytes-on-disk-across-all-install
mlsys project grade m-compute-true-unique-bytes-on-disk-across-all-install --milestone 1
```
