Our speculative decoding serving engine has been running into severe unpredictability under dynamic production traffic. When we configure the serving layer to maximize overall system throughput during peak hours, tail latencies for individual user requests spike significantly, causing SLA violations. Conversely, when we tune the batch configuration exclusively for single-request latency, our hardware utilization plummets, leaving substantial GPU compute idle and driving up operational costs per generated token.

We need a systematic way to ingest the exact same profiling data—spanning variable batch sizes, draft acceptance probabilities, verification overheads, and token generation costs—and independently compute both the latency-optimal batch size and the throughput-optimal batch size. Currently, the recommendation pipeline lacks a principled mechanism to separate these two operating points, leading engineers to guess batch sizes manually through trial and error. This unit requires implementing the core profiling calculations, metric derivations, and recommendation logic to clearly isolate latency-optimal versus throughput-optimal batch sizes from shared trace profiles, backed by regression testing to ensure fundamental operational invariants hold under all conditions.
