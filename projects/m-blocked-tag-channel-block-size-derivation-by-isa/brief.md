An inference engine targeting Apple Silicon and x86 architectures is currently showing abnormal memory layout translation overheads during vision and convolutional model execution. When running standard models under CPU execution providers with oneDNN style blocked memory layouts, operators are frequently falling back to reference paths or incurring excessive reorder operations. 

Profiling traces indicate that the channel-block size derivation for blocked tags does not properly align with the underlying instruction set architecture vector register width or cache line boundaries, causing severe pipeline stalls when transitioning between plain and blocked formats. Specifically, on Apple Silicon architectures using channels-last layouts, the reorder-op count explodes, inflating the reorder overhead fraction to unacceptable levels before and after layout transformations. 

We need to implement a robust channel-block size derivation function that inspects the target ISA capabilities, calculate precise plain versus channels-last reorder counts, and quantify the exact reorder overhead fraction. You will implement the layout derivation logic, measure the reorder metrics, and provide a regression test suite that catches regressions where block sizes or reorder fractions are improperly computed.
