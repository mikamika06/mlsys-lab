We are in the process of migrating our custom LLM inference attention kernels to PyTorch's `FlexAttention`. I attempted to implement an ALiBi relative positional encoding coupled with a local sliding window. However, we're encountering two severe issues during generation.

First, the generated text rapidly degrades into repetitive gibberish past the 1,000 token mark, suggesting that our token-level ALiBi scores are improperly scaled or our attention span is drifting incorrectly. Second, despite the sliding window theoretically restricting the KV cache span, memory usage remains strictly quadratic. We hit Out-Of-Memory (OOM) exceptions much earlier than calculated, and our system profiling shows that `FlexAttention` is materializing full N x N blocks because our custom `BlockMask` is effectively disabled or computing bounds incorrectly.

We need a purely mathematical, dependency-free reference implementation of both the token-level modifiers (`score_mod` for ALiBi, `mask_mod` for the sliding window) and the block-level sparsity calculator (which calculates block ratios and returns `kv_num_blocks` and `kv_indices`). We want to test and debug our PyTorch logic against this clean Python/Numpy reference to ensure our index boundaries and causality constraints are mathematically perfectly sound before dispatching to the CUDA backend.
