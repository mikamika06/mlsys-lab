During performance profiling of our low-level ONNX Runtime inference server, we noticed severe latency jitter and inefficient execution resource utilization under varying workload conditions. Specifically, when we sweep through different intra-op thread counts to find the optimal execution configuration, the latency profile exhibits unpredictable peaks, and our current thread selection logic fails to reliably isolate the true minimum latency index. Furthermore, standard execution via session run incurs a massive memory allocation and host-to-device/device-to-host copying overhead on every inference step, which severely bottlenecks end-to-end throughput. Although we attempted to convert standard session execution to use optimized IOBinding buffers and to compute the exact copy-time share of end-to-end latency, our metrics drift and fail to track runtime performance reliably under load.

Your assignment is to build a robust performance optimization library under the `ortopt` package that fixes these runtime inefficiencies. First, implement a reliable thread sweep module that accurately identifies the optimal thread count using argmin over execution latencies across a parameter grid. Second, provide a high-performance execution adapter that correctly converts standard session run calls into `run_with_iobinding` routines with pre-allocated device buffers without altering output correctness. Third, implement precise latency analysis utilities that calculate the copy-time share of end-to-end latency. Finally, you must write a comprehensive test suite in `tests/test_regression.py` that guards against incorrect thread selection and broken IOBinding transformations to ensure system stability.
