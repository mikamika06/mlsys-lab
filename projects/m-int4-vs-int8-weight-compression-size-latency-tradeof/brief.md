We are experiencing unexpected memory allocation failures and accuracy drift when serving large language models locally using CPU inference pipelines with NNCF INT4 and INT8 weight compression. While transitioning our model weights to lower-bit representations aims to reduce memory footprint and improve bandwidth utilization, our profiling shows inconsistent latency gains across different hardware threads, accompanied by abrupt out-of-bounds access faults during quantization block execution. Specifically, when configuring group-based weight compression schemes, certain channel dimensions and layer configurations that do not align cleanly with expected block boundaries cause the packing routines to silently truncate weights or trigger silent indexing errors down the line. Furthermore, the tradeoff between the aggressive memory bandwidth reduction of INT4 and the numerical stability preservation of INT8 remains poorly balanced in our current deployment script, leading to severe throughput degradation when batch sizes fluctuate. We need a robust weight compression and execution harness that accurately evaluates the size versus latency tradeoff across INT4 and INT8 variants, while strictly validating quantization group alignments and capturing non-divisible group size misconfigurations before runtime execution.
