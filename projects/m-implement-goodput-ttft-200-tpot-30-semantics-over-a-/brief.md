An engineering team operating a high-throughput LLM serving cluster with vLLM has noticed discrepancies between raw token throughput and actual production service quality under strict Service Level Objectives (SLOs). Specifically, the cluster management dashboard displays an aggregate throughput metric that looks healthy, but user-facing applications report severe tail-latency violations, sudden performance degradation, and unhandled request failures during periods of heavy preemption.

When operators try to evaluate service performance using standard metrics like Time to First Token (TTFT) and Time Per Output Token (TPOT), they encounter multiple operational puzzles. First, writing a clean filtering script for goodput under `--goodput ttft:200,tpot:30` semantics over raw request output JSON results yields unexpected drop-offs where successful requests are incorrectly marked as failed or vice versa, especially when requests suffer mid-generation stalls or queueing delays. Second, analyzing token-by-token generation logs shows that the total end-to-end latency (E2EL) frequently deviates significantly from the simplified formula E2EL != TTFT + TPOT*(n-1), and the exact source of this gap during request preemption and memory swapping needs to be precisely quantified. Third, operators are confused by the divergence between Inter-Token Latency (ITL) and TPOT when calculated from fine-grained token arrival timestamps: while TPOT is often treated as a steady-state average, actual ITL sequences reveal bursty behavior, scheduling jitter, and tail spikes that regular TPOT metrics completely mask.

Your task is to implement the core analytics library that correctly parses serving traces, computes accurate goodput under strict SLO constraints, models and decomposes the E2EL preemption gap, and rigorously extracts and differentiates ITL from TPOT using token timestamp streams.
