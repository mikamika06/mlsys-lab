Ticket #8412: Unexpected Latency Regression and Branch Strategy Failures under PyTorch Compilation

Engineers across multiple model optimization squads have reported severe performance degradation when compiling models that incorporate data-dependent control flow. Specifically, when converting models containing conditional execution branches into optimized device graphs, utilizing graph-safe control flow primitives such as torch.cond frequently incurs massive overhead compared to vector-parallel masking operations like torch.where. This latency penalty occurs even when the computational body of the conditional branch is extremely lightweight and trivial in nature, leading to underutilized execution units and suboptimal kernel launch patterns on target accelerators.

Compounding this performance anomaly, our intermediate representation lowering pass currently fails to evaluate whether the overhead of tracing and dispatching through torch.cond is justified relative to torch.where. Across six distinct intermediate representation test scenarios characterized by varying branch instruction counts and tensor dimensionality, the compilation pipeline either emits inefficient structured control flow nodes or fails to establish a consistent decision boundary.

We require an automated measurement module capable of modeling the latency cost ratio between torch.cond and torch.where, alongside a robust decision component that reliably classifies intermediate representation cases into optimal execution pathways. Please implement these components under the condcheck/ package along with a comprehensive regression test suite to safeguard future lowering logic.
