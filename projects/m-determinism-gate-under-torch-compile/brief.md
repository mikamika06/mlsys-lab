Ticket: Production inference pipelines using PyTorch 2.x `torch.compile` are experiencing intermittent, hard-to-reproduce output discrepancies during high-throughput rollouts. Operators report that identical inputs passed through compiled modules occasionally produce subtle floating-point variations or outright divergence across separate execution passes or worker nodes, bypassing standard validation suites. Standard unit tests that check single-pass correctness fail to capture these runtime non-determinisms introduced by backend kernel autotuning, Triton compilation flags, or non-deterministic reduction operations in fused CUDA kernels. We need a robust, low-overhead determinism gating mechanism tailored for `torch.compile` modules that verifies output stability before promotion, ensures warmup runs handle autotuning artifacts properly, and exposes a testable interface to catch regressions in determinism policies.
