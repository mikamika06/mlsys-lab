When deploying large language models using high-throughput serving engines, operators frequently observe unexpected out-of-memory (OOM) crashes or underutilized hardware during startup. Specifically, adjusting configuration parameters such as the GPU memory utilization fraction, enabling FP8 precision for the key-value cache, or co-locating multiple model instances on a single physical accelerator often leads to a discrepancy between the expected block allocation and the actual runtime behavior.

In many production environments, the engine initializes by querying total device memory, subtracting reserved overhead for weights and activations, and scaling the remaining capacity by the specified utilization parameter. However, when operators switch the KV cache data type to FP8 to double the sequence length capacity or split the available memory pool proportionally between two separate models, the block calculation logic frequently produces invalid counts or causes illegal memory overlaps.

Your task is to implement the core engine functions that accurately compute realized GPU blocks from memory utilization sweeps, determine the precise impact of FP8 dtype on capacity limits, and correctly partition available memory fractions when running multiple models on a single GPU. Your code must correctly predict these allocations and pass rigorous safety regressions to ensure robust multi-tenant serving stability.
