Our Triton kernel autotuning sweep for a fused attention block on a modern GPU has finished running across several block size and num_stages combinations, saving a CSV-like recorded history of configurations along with their measured execution times and peak shared memory footprints. However, the logging infrastructure recorded many configurations that are dominated by others—meaning there exists another configuration that is both faster and uses no more shared memory, or uses strictly less shared memory while being at least as fast.

We need to process this raw recorded sweep to filter out the sub-optimal configurations and select the exact Pareto-optimal configurations, sorted reliably by performance or configuration identifier. Currently, our performance engineering scripts crash or return unpruned sets when trying to extract the optimal frontier from noisy autotune logs, leaving us unable to pick the optimal launch parameters automatically during runtime compilation. Your task is to implement the sweep analysis library that reads the recorded measurements, extracts the true Pareto frontier in terms of latency and resource usage, and provides robust regression tests to ensure future pruning updates never drop a valid optimum.
