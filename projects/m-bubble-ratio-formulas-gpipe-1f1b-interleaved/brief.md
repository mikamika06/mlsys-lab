We are observing latency bottlenecks and out-of-memory errors when evaluating different pipeline parallelism scheduling strategies for large transformer models across multi-GPU clusters. Engineering teams report that analytical estimates of pipeline bubble overheads do not consistently align with empirical execution traces, particularly when switching between standard GPipe schedules, steady-state 1F1B execution, and interleaved 1F1B pipeline variations.

Furthermore, dynamic memory allocation during forward activation caching is causing unexpected OOMs on early pipeline stages. The memory consumption profiles appear to deviate from standard theoretical bounds, especially as the number of microbatches and interleaved virtual stages per physical rank changes.

Your goal is to implement an accurate pipeline parallelism scheduling and analysis library in `pipelib/`. First, build exact analytical bubble-ratio estimators for GPipe, 1F1B, and Interleaved 1F1B schedules that compute theoretical idle time fractions given pipeline depth, number of microbatches, and virtual stage counts. Second, implement an event-driven schedule simulator that executes `ScheduleGPipe` and `Schedule1F1B` workflows, tracking exact stage execution steps, forward/backward timing, and bubble fractions under real schedule constraints. Third, extend the simulator to track peak in-flight microbatches and activation memory footprints across stages, accurately reflecting peak memory pressure under interleaved execution.
